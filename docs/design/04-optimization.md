# 性能优化

## 从完整负载定位成本

单次 RPC、RMM 处理、GPU 等待及 worker 调度会重叠。先用完整 33 场景确定是否有应用收益，再按相同统计总体拆分热点。使用硬件工作负载看场景结果、validation、内核健康与资源恢复。保留逐任务授权、依赖、错误、完成和回收语义。不同控制组的百分比不能累加。

| 位置 | 保留的手段 | 安全与正确性约束 |
| --- | --- | --- |
| 映射和执行域 | 用受保护代次和域租约避免重复准备，同一可信事务内收敛重复检查 | 对外发布前更新映射身份和所有权，保留真实根及设备检查 |
| 输入捕获 | 按实际映射页遍历命令，复用同一页的只读准备 | 每个任务独立捕获、校验并持有命令范围和依赖 |
| READY 与等待 | S3 使用已有 Proxy vCPU 作有界等待提示，允许 Client 同时准备后续请求 | 保留每任务状态与调度边界，提示后仍走可信检查 |
| 完成通知 | S8 用本地有界 IRQ-work 处理完成 fence 链，减少重新调度 | 可信完成在先，沿用依赖、错误传播及同步取消 |

同一完整负载下还观察到部分场景与总分不同方向变化。优化保留依据包含预设场景保护线，terrain、折射和模糊等敏感场景要逐项核对。[汇总与原始 run-id](../shared/GPU_PERFORMANCE_EXPERIMENT_SUMMARY_20261118.md)

## 撤回和诊断

| 候选 | 对照 → 实测 | 分差 | 判定 |
| --- | --- | --- | --- |
| C1 分散提示许可 | 1170 → 1121 | −49，−4.19% | 局部短暂停减少，RPC 变长，总分退化 |
| C2 提高接收 worker 优先级 | 1170 → 1133 | −37，−3.16% | 局部 RPC 略快，整机退化，撤回；对象残留使单项归因收窄 |
| C3 Mesa GLThread | 1170 → 1160 | −10，−0.85% | 环境参数送达，实际 worker 启用缺乏证据 |
| C4 每 Group 输入页预分配 | 同构建 1163 → 1166 | +3，+0.26% | 强制重编译后归因成立，低于 1182 保留线；首轮混合镜像单列 |
| P18 RMM 分段计时 | 同期 1164 → 1161 | −3，−0.26% | 诊断采样通过，保留计时证据 |

P18 同总体样本中，FINISH 的 ACK 等待及错误扫描均值 23.26 µs，后续队列证据均值 4.65 µs。控制页读取样本的整页失效和 DSB 均值约 0.236 µs。由局部样本不能预测一次改动的整机提分。1200 分探索在 P18 收尾，发布基线保持 1170。[候选记录、命令与退出码](../shared/GPU_1200_PROFILING_OPTIMIZATION_20261117.md)
