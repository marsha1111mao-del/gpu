## 假设平台拥有的能力

| 平台能力 | 本设计采用的前提 |
| --- | --- |
| 可信内存保护 | RMM管理的真实IOMMU页表、授权元数据，以及可信Proxy的页表/控制内存，不能被未授权Host、普通VM或其他设备直接篡改。 |
| 关键设备配置保护 | IOMMU root、控制寄存器和工作态GPU任务MMIO只能由获授权的可信主体修改；Host不能通过物理别名、配置替换或普通VM映射绕过。 |
| 未授权DMA阻断 | 平台阻止其他设备对受保护内存的未授权物理访问；包括未接入本服务或不经过IOMMU的DMA。PL330等设备的物理封堵由平台承担。 |
| 保护状态持续有效 | 上述保护在设备交接、复位和电源切换期间按可信协议维持或恢复；Host的板级供电、时钟及合法OPP权限不授予任务寄存器修改权。 |

这些是模型前提，不是已在当前板卡证明的硬件能力，也不表示任意CCA平台天然提供全部能力。
RMM仍须实施owner/generation、授权范围和映射互斥；软件owner记录表达策略，平台负责阻止策略外的原始物理访问。
不引入EL2接管普通VM页表，不增加GPU数据路径外置SMMU S2，也不把GPT/GPC当作单个Realm的owner检查。
Client之间仍由可信Proxy建立的GPUVM及软件授权约束；平台假设不替代软件的越权检查、撤销和回收。
