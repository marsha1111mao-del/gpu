## 保留的核心研究结论

项目可分为两部分：Arm GPU直通与共享的实现/性能优化，以及GPU任务隔离的安全设计。第二部分重点是内存/映射生命周期和中断通信；执行形状与统计泄漏是进一步可选择的隐私目标，应独立定义和评估。

PORTAL、CAGE、ACAI与项目可信ProxyRealm、Client身份及设备授权主线最直接相关；PhantomMap、DMGuard等帮助检查实际物理页、多别名和生命周期。按照既定平台保护假设，GPU建图时软件完成IPA到HPA授权与合成Stage-1映射，执行时由硬件Stage-1限制访问；这一模型不因实验硬件只能模拟而失去研究意义。

内存隔离仍需把授权贯穿建图、使用、撤销与复用。页表、根配置、关键MMIO和固件受保护只是前提；对象归属、实际HPA权限、别名、旧引用、generation和安全回收仍需闭合，不能由一次映射检查推出全生命周期安全。

可信中断通信应绑定RMM认证的Client、device/context、job cookie与epoch，并由受保护状态和真实原生fence确认成功/错误。通知到达、任务终态、输出可见、应用正确、结果发布、DMA静默和安全复用分别判定。过期/重复/跨Client事件，以及取消/reset与完成竞争，是关键验证目标。

CounterSEVeillance、TEEcorrelate等表明，认证事件来源不自动解决中断干扰和统计观察泄漏。精确可信内部状态与受限外部统计应分开；计数器、overflow、profiling、队列与逐job时间戳需纳入出口策略。它们是CPU机密计算的支撑证据，不能宣称已经验证本项目GPU存在或消除了同一种攻击。
