## 2. 研究问题：保护模型功能而非设备隔离

作者目标是阻止拥有设备REE root权限的攻击者利用外露权重、公开预训练模型和模型查询复制私有任务功能。GPU在REE中不可信，TEE内小网络和最终分类可信；用户输入隐私与物理侧信道排除。攻击结果以替代模型分类准确率衡量，不以逐字节权重恢复衡量。

因此它属于DarkneTZ、TEESlice、TBNet、GroupCover等模型保护路线，不是Portal/CAGE/ACAI式可信设备分配方案。它不提供多Realm设备身份、SMMU授权、恶意DMA隔离、可信完成中断或跨Client资源回收协议；其“logical isolation”描述模型组件功能依赖，不等于内存和中断隔离。

TEE假设还包括模型安全配置与部署、私有分支代码/参数不被REE直接读写。论文“仅通过SMC通信”是简化背景，实际实验使用共享内存传送中间特征；调用入口存在不能证明共享数据已认证、不可重放或没有TOCTOU。

## 3. 从 TBP/PBT 到 SBT

Training-before-partition先训练完整私有模型再隔离一部分，留在REE的参数仍可能包含目标任务信息。Partition-before-training先划分公开骨干与私有组件，但若TEE分支结构绑定GPU骨干，CPU/GPU串行依赖、传输和小型安全内存可能限制性能。

SPOILER提出search-before-training：先以硬件测量构建候选小网络，搜索准确率/延迟折中，再协同训练骨干和私有分支。图1–3展示这三种路线和外露权重初始化攻击；图4呈现普通训练/对抗训练的攻击趋势以及传输与混淆成本；图5展示搜索和训练流程。图中安全/延迟色条是设计概括，不是形式化比较或精确测量表。

对已有方案的“都硬件无关”“都不能并行”“全模型进TEE理论上完美安全”等叙述应按其限定威胁模型理解。尤其“所有TEE没有GPU”不适用于可信GPU扩展路线，本项目不能因该动机而放弃已经选定的GPU可信控制假设。

## 4. 在线结构和数据流

GPU执行REE backbone；在选定层之后，用无可训练参数的adapter压缩特征并单向交给TEE。TEE执行较小的side branch和分类器，GPU可继续执行后续骨干块，试图让两侧工作重叠。单向的是模型中间特征流，不意味着控制、通知或资源管理不再需要同步。

搜索空间支持CNN的depth-wise/point-wise卷积，以及Transformer的token/channel mixing。分支使用pooling、bottleneck和上采样线性层；两个全局维度因子维持聚合兼容，五个逐块因子控制开关、类型和维度。具体离散取值引用缺失的补充A，主文未完整给出。

“adapter无参数”可以避免在adapter引入新的可训练权重，但不证明输入特征无私有信息。骨干在最终self-poisoning阶段也会更新，不能把其所有外露参数自动等同从未接触私有任务数据的原始公开骨干。

## 5. NAS优化与测量模型

形式化目标是在资源约束H(a)≤Hlimit下最大化验证准确率f、最小化预测并行时延g，再用归一化评分 `S=α·f_norm+(1−α)·(1−g_norm)` 选择Pareto解。作者用SAAS-GP和NEHVI探索高维空间，冻结骨干、对候选分支单epoch训练来降低搜索开销。

单epoch评价是最终训练表现的代理；是否会改变候选排名、需要多少搜索轮次、完整搜索耗时、种子敏感性及最优性差距，主文没有足够数据回答。“optimal”应解释为搜索所得候选，不是穷尽10²⁰空间后的全局最优证明。

g模型先计GPU到首个传输点，再对每个同步区间累加 `max(TEE传输+CPU计算, GPU后续块+adapter)`。这说明可重叠时间受较慢路径限制；共享缓存/内存争用、实际调度、fence等待和数据可见性是否进入各项，需要实测校验，而非只比较FLOPs。

评分目标没有显式包含自适应攻击成功率或信息泄漏约束，安全主要交由后续训练及实测攻击评价。形式上还定义K=0的无分支模式；如作为可部署配置，需要另行检查它是否满足TEE私有功能要求，不能由资源约束和准确率评分自动证明安全。

## 6. Self-poisoning的作用与不能推出的结论

最终目标为 `L=β·CE(Mc,y)+(1−β)·KD(Mc,Mt)−λ·CE(Mb,y)`，Mc为组合模型，Mt为teacher，Mb为独立骨干。最小化前两项维持任务效用，负号项推动独立骨干分类变差；gradient clipping用于限制不稳定梯度。它不是加密，也不是对另一租户或训练数据投毒的运行攻击。

这种目标可能让直接复制/微调骨干的攻击初始化不利，但高交叉熵本身不证明中间表示与标签独立。例如二分类若完整保留判别信息、仅把输出类别交换，原分类器会很差，交换标签或替换头部却可恢复。这是解释论证缺口的数学反例，不是本轮已经攻破SPOILER。

要支持更强模型保护主张，需要评估重置分类头、冻结特征训练新头、多层feature probing、重新初始化部分层、恢复公开权重、适应性查询与不同优化预算。模型对当前输出头不友好和攻击者无法利用任何外露信息是不同命题。

## 7. 最重要的攻击评价边界：攻击者可放弃外泄权重

作者攻击管线先将公开预训练权重与REE外露参数组合，再用1%训练集查询得到标签微调。Black-box基线则只用公开模型和查询。若现实攻击者拥有这两种选择，至少可以选择不加载poisoned权重；增加可选信息不会让最优攻击能力被迫低于同条件黑盒策略。

因而应报告可选择策略中的最好结果，如 `max(公开模型+查询, 外泄权重初始化, 重置头部/部分层等适应策略)`。表中poisoned初始化明显低于Black-box，首先说明这个特定初始化/训练管线变差，不能直接解释为真实攻击者能力降至黑盒的8%，更不能证明通用“优于黑盒保密”。

同条件也需要同一victim查询oracle、返回形式、数据、预算及模型选择成本；论文组合模型与未保护模型准确率不同，需核对基线标签来自哪个模型。主文缺少足以完全重建这些细节的运行代码/日志，本报告不把上面的攻击选择原则当作已运行的新攻击。

## 8. 实验平台与可比较范围

作者使用RTX A6000进行实验，在Jetson Orin测真实延迟：12核Cortex-A78AE、48MB secure memory、OP-TEE/TrustZone；分支用Darknet，GPU骨干用ONNX Runtime，共享内存异步传输。搜索安全内存门槛设24MB，不应混称整机仅24MB可用。

模型为VGG16-BN、ResNet18、ViT-Base；数据为CIFAR10/100和TinyImageNet。CNN输入32×32或64×64，ViT输入统一224×224。攻击预算为1%训练集，不是1%泄漏参数或1%随机查询空间；不直接覆盖未知分布、大预算攻击或自回归LLM。

α默认0.5，三个模型λ分别0.01/0.001/0.005，梯度clip分别0.5/2/2。对照包含DarkneTZ、Serdab、Magnitude、GroupCover、TEESlice、TBNet；作者重实现ViT版TEESlice和TBNet，不能将其结果无条件代表所有原作者版本。本文引用的TEESlice书目为AISTA2022，不冒充我们另读的S&P2024完整扩展。

## 13. 与本项目两大部分的关系

维持既定目标：RMM认证原始Client，可信ProxyRealm控制SMMU，建图时检查对象/实际HPA/权限/生命周期，软件IPA→HPA生成受保护GPU Stage-1，其他设备硬件Stage-2；实际页表/根配置/MMIO与固件受保护。这是可信设备控制路线，SPOILER允许不可信GPU观察变换/训练后的模型，两者应按不同威胁模型比较。

第一部分Arm GPU直通/共享与性能优化，可吸取按真实CPU/GPU/传输耗时组织流水线的思路；不必引入NAS或重新训练用户模型才能共享GPU，也不能将Orin图6当本项目加速结果。优化仍在固定基线下分别测提交、执行、完成发布、IRQ127唤醒和恢复。

第二部分任务隔离，应特别区分“逻辑结果已可用”“所有关联GPU任务已终止”“内存/设备资源可移交”。若允许早返回，私有快照/BO/映射须持有到真实后端fence终态与必要同步完成；reset/撤销还要证明静止及清理，不能由TEE已产生标签就回收给下一Client。

复用GPUVM、认证队列、private plan/snapshot、native fence、cookie/epoch及IRQ127，绑定每次请求、特征对象和输出；按对象权限检查共享输入，防止其他Client替换中间特征、旧请求重放或通知错配。无参数adapter和poisoned backbone均不能代替身份、对象授权或完成证明，无需新建平行身份机制。

如果研究范围进一步包含模型IP保护，再单列允许泄漏、查询oracle和最优攻击者选择，分别测试直接读取/跨Client泄漏与功能复制。真实fence证明执行终态，不自动验证不可信GPU的数学结果；反过来模型分类准确率也不能证明某任务真实在正确设备/Client上执行。

## 14. 建议的后续实验和评价

模型侧应补充忽略外泄权重的黑盒回退、重置head、多预算/多种子、自适应层选择及teacher/poisoning/NAS消融；安全指标采用攻击者可选方案的最好结果，并明确同一查询oracle。系统侧应补充旧特征重放、请求/对象错配、共享缓冲并发修改、提前返回后的在途写入、取消/reset后的快照引用与跨Client回收负例。本轮均为建议，未运行。

性能侧应同时报告标签就绪、全部GPU完成和资源可回收三种时刻，给出吞吐、p50/p99、峰值安全内存及冷/热缓存条件。搜索离线成本与在线推理成本分开，不把单epoch搜索成本或24MB门槛当实际全流程开销。

SPOILER的增量是把TEE小网络架构搜索与抑制特定复用攻击的训练结合，且提供真实TrustZone/GPU延迟实验。主要限制是安全性依赖受限攻击管线，汇总倍率无法按常见口径复算，公开实现和补充细节不足；对项目最实用的启示是可信流水线的完成/回收语义和严格区分模型功能保护与任务隔离。
