## 2. 威胁模型与非干扰边界

§2.2明确假设硬件和OS/hypervisor可信，VM相互不信任。攻击者通过自己访存的延迟推断同机VM活动；缓存、NoC、地址总线及其他泄露面须另行处理。其严格非干扰目标限定于所建模内存控制器，不是整机或全部物理侧信道的零泄露证明。

本项目面对不可信Host时不能直接继承可信OS假设。应将身份、授权、调度和重配置放在既定RMM/ProxyRealm可信边界内，明确由谁认证原始Client、资源域标签以及配置来源；不能允许Host或Client自行声明可信domain tag。

论文依赖每事务唯一安全域标签、每域独立transaction queue及专用逻辑。OS保证域数量不超过队列数量；离线约束求解产生固定无冲突流水线。隔离结论依赖标签路由、队列状态和求解约束的完整性，而非只有轮转计数器。

§5.1明确区分协议非干扰与实际artifact保障：需要经过gate-level验证的实现和无bug OS才能将协议保证传递到实现。本文没有交付已验证RTL，不将其构造式分析改写成已证明本项目代码安全。

与HASP2014带宽预留相比，本文明确构造满足DRAM约束的确定性流水线；前作的固定配额/平均带宽并不足以自动消除时序信道。与HASP2018 MLP-Aware相比，本篇更完整说明了固定数据/命令锚点、返回批处理与重配置排空的前提。

## 3. Rank分区的固定服务流水线

基础例为8线程、8rank，每线程拥有一个或多个rank，每Q周期保证一次服务，空队列使用dummy。每次从空row开始，禁用row-buffer hit收益并采用auto-precharge，避免前次row状态改变服务时间。

以固定数据时刻k·l为锚，读COL在k·l−11、写COL在k·l−5；读ACT在k·l−22、写ACT在k·l−16。命令总线冲突条件归结为不同事务之间的间距不能等于5、6、11、17等偏移差；同时数据burst4加rank切换2要求l至少6，完整约束下最小取7。

独立整数检查：l=6会发生偏移差6的跨事务命令碰撞；l=7不整除上述非零偏移，且满足数据间隔。这个算术只检查所列命令模板，不覆盖refresh、异常、队列溢出、真实RTL或其他未列命令，不能充当完整实现证明。

8个slot得到Q=56 memory cycles，4:1时钟比下为224 CPU cycles；数据总线峰值利用率4/7约57.14%。脚注还说明读写交替下相邻同域事务的相关间隔可能为50、56、62 memory cycles；固定服务窗口不是每种可观测时延都精确56。

固定周期数据与固定周期RAS/CAS属于不同锚点；作者给后者rank分区最小间隔12，而非7。讨论间隔时必须同时给出命令模板，不能只引用某个数字而省略约束条件。

## 4. Bank分区、重排与返回时间

空间层次为channel、rank、bank。正文以4channel×8rank×8bank讨论并写512 banks，但乘积是256，Table 1也列8bank/rank；保留这个容量算术差异，不据其文字阈值直接规划项目Client容量。

bank分区虽然避免同bank竞争，仍共享rank时序和总线。作者公式给ACT约束l至少11、four-ACT约束至少8；读写转换进一步使固定数据锚点要求21，换固定RAS锚点可降到15。HASP2018中15/21的引用必须联系锚点，不能一概当同一规则的互相矛盾。

固定RAS bank分区中，8线程Q=120，利用率4/15约26.67%。更高利用率需要将窗口开始时收集的请求先读后写；论文给重排方案Q=63、8个burst，峰值32/63约50.79%，具体读写命令间隔仍须满足约束。

内部读写重排会改变某个线程读请求早晚，泄露其他线程读写组成。作者因此把读结果统一留到interval末尾集中返回。仅保证所有请求都能执行，并不能保证每域看不到其他域活动；返回接口也是安全机制的一部分。

对GPU项目，可将真实完成记录与面向Client的可见发布分开：native fence确认实际终态，可信完成队列保存身份与结果，再按所选策略通知。固定时刻到达不能生成虚假成功，未完成任务仍须pending或真实失败，错误/取消和数据可见性必须保持。

## 5. 无分区与Bank Triple Alternation

无空间分区时，最坏同bank任意读写组合需要43cycle安全间隔；8线程固定服务周期344，峰值4/43约9.30%。这说明仅把访问平均分配，并不消除前一个域留在资源中的时序状态。

Bank Triple Alternation按bank类别分三组轮转，将连续slot间隔降为15，并使再次访问同bank类别至少隔45，大于43。8线程、3轮总周期360，合适bank分布下能服务多个请求，单个任意请求最坏仍需等待相应类别。

三类别轮转要求保留每域类别进展，不能再随意按读写全局重排破坏对齐。2015方案显式跨round切换类别；不把2018按全局turn编号取模的gcd问题原封不动判定为2015漏洞。Client数量动态改变后仍须重新检查类别覆盖、等待上界与跨边界时序。

本项目可借鉴“可接纳任务集合由实际资源冲突条件决定”，而非照搬DRAM cycle。GPU队列、执行引擎、地址空间、缓存和中断源不一定有相同分区结构，应分别声明哪些资源独占、清理或允许共享泄露。

## 6. 重配置、dummy与能耗假设

可信OS按容量和带宽SLA设定域到rank/bank映射与slot；页着色、迁移和rank粒度碎片化是软件成本。资源映射决定调度，调度不能反过来授权任意物理页；本项目实际HPA所有权、访问权限与生命周期检查仍独立成立。

§5.1明确要求SLA改变时排空控制器状态，类似CPU流水线context switch。迁移到项目时，删除Client调度项、切换epoch或撤销映射均不能代替旧任务/DMA静默；重配置要处理在途任务、回调引用、迟到中断、实际映射和可回收对象。

dummy访问随机选本域rank地址并丢弃结果；rank归属本身并不证明每个实际页有访问权。GPU若使用dummy或预取，仍须限制在经认证的对象、合法HPA范围和权限/存活期内，不能以“结果不用”豁免授权。

作者用sandbox prefetcher产生最多4个高置信预取替换本域空slot。预取队列、地址来源和返回数据仍属于域状态；自适应策略不能借另一个Client的私有历史偷偷改变本域外部可见时序。

能耗优化明确限定不担忧基于功耗测量的物理攻击：可以物理抑制dummy、利用row hit避免部分ACT/PRE、让空rank进入低功耗，但仍按命令已发出更新shadow DRAM状态。保持的是虚拟调度时序，不是实际总线/功耗轨迹相同。

shadow状态与物理状态必须在唤醒、刷新和重新分配时保持约束一致。不能同时把这些节能结果和更强物理隐藏假设拼接成一个无条件结论；原文uniform power的定性讨论也没有覆盖所有数据/地址相关功耗。

## 7. 评估方法与证据限度

Simics+USIMM建模DDR3，主要实验为8核单channel，目标叙述涉及32核4channel。UltraSPARC III 3.2GHz、ROB64、4-wide、32KB L1 I/D、共享4MB L2；8rank/channel、8bank/rank、1600Mbps。Table 1引用的JEDEC条目名为DDR4，正文DDR3的标注差异保留。

SPEC2006 rate模式8份，另有NPB CG/SP及混合负载；fast-forward500亿指令，100万memory reads后终止，混合负载按对应baseline执行指令数截断。非安全比较采用2012 Memory Scheduling Championship的最佳调度器，不简化写成任意FR-FCFS。

归一化weighted IPC按各线程相对非安全基线求和，8线程基线为8；能量由模拟统计结合Micron DDR3功耗计算器得到，不是物理测量。不同核数敏感性实验假定rank数随线程数变化，不能说是在完全固定资源下证明扩展性。

## 8. 性能与分母复算

最佳传统Temporal Partitioning约比非安全基线低57%，FS rank分区较其改善69.3%；按舍入值0.43×1.693约0.728，与正文最佳FS比非安全低27%相容。安全基线上的69.3%增益不是相对非安全基线仅剩30.7%开销。

Figure 3概览rank FS约0.74，正文27%下降对应约0.73；保留概览/聚合/舍入差异，不声称精确原始数据可恢复。FS reordered bank较最佳bank TP改善11.3%，无分区triple alternation约2倍，均对应各自比较对象。

最佳FS平均内存延迟683→288 cycles，绝对少395、下降约57.83%，延迟比约2.37；这与weighted IPC提升69.3%是不同指标，不能互相替代。理论/实际带宽利用率约57%/37%，不是57%的程序加速。

平均36%的事务为dummy，单负载范围2.3%至87%；这是全部事务分母。后文FS比TP多36.6%的accesses是另一分母，不能写成同一比例。若dummy占总量36%，相同口径总访问/真实访问为1/0.64=1.5625，不是1.36。

预取实验中非安全基线42.4%的访问为预取、性能改善6.3%；FS预取访问占13.4%、其中43.7%有用、性能改善11%。13.4%×43.7%约5.86%是全部访问中有用预取的比例，43.7%不是性能提升。

能量正文称FS较TP低11.4%、在非安全基线19%以内，又称三项优化合计降低FS能耗52.5%、优化后在基线3.4%以内。Figure 9各workload柱和AM柱没有直接支持将1.19×0.475组合为1.034；未取得原始值，不自行修正或将不同聚合口径拼接成精确关系。

2/4核情况下FS较TP改善18%/85%，但rank也减少；6线程以下跨round同rank距离最多42，低于43，作者明确要求换bank请求或dummy。安全约束不能因为Client较少就自动忽略。

## 9. 对本项目的取舍

主线继续是RMM认证原始Client、ProxyRealm授权真实物理页并保护直接HPA Stage-1映射，保留private plan、GPUVM/BO、native fence、cookie/epoch及可信IRQ路由。本论文补充共享时序与切换条件，不替代现有内存访问控制。

建议把完成接口定义为可信状态机：接纳→执行→真实终态→数据可见→可发布→通知；撤销/reset还要独立确认在途DMA与引用静默后才回收。中断只能提示读取可信记录，不能凭IRQ号或到达时间证明哪个任务成功。

优先论证来源认证、Client/queue/task/epoch绑定、重放/迟到拒绝、错误归属和撤销安全；若将时序隐私纳入目标，再讨论固定窗口或批量发布。Host可见VM exit、RPC、完成页轮询和调度行为也要纳入观察模型，单独整形IRQ不足以覆盖旁路。

适合作为后续设计评估的是同配额不同细粒度轨迹、重配置旧状态、迟到通知和完成页旁路的对照；当前只提出验证目标，没有执行这些实验，也不把任务隔离等同应用结果正确性或绝对可用性。
