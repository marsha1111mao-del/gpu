## 2. 原论文保护什么、不承诺什么

用户拥有家居/监控视频，应用开发者提供分析模型，Serdab 负责部署，云/边缘服务商提供机器。用户信任应用开发者，不信任 Serdab 编排及服务商；通过 SGX 的远程证明确认 enclave 运行预期代码。摄像头和模型训练环境假设安全，原始视频、受保护模型层在 enclave 中解密和处理。

原文明确把服务商设为希望窃取输入、但仍返回正确结果的对手，并假设服务商没有制造错误输出的动机。另假设资源报告正确，排除 SGX 侧信道和 DoS。因此它不是恶意 GPU/Host 任意篡改结果下的完整性方案；背景提出 code integrity，不代表其后续明文 GPU 分支解决了任意计算作弊。

用户输入隐私是主要安全目标，受保护模型参数也是防止输入重建的重要前提。它不同于 DarkneTZ 的边缘设备模型成员隐私，也不同于 TEESlice 的公开骨干/模型窃取实验。比较时要保留训练数据、模型、当前输入、结果真实性这几类资产和攻击者权限。

## 3. 系统组件与数据路径

应用描述为 DNN 层的 DAG。Resource Manager 记录可用可信/不可信设备；Application Manager 分配各设备的层；privacy-aware placement 服务根据逐层耗时、输出大小、网络带宽和隐私阈值选择分割；本地 Dataflow Engine 负责执行和传输操作。

实现使用 Docker 中的 gRPC 推理服务，Asylo 承载 enclave，TF Trusted 集成 TFLite，各设备的 Apache NiFi 管理数据流，Echo 编排跨设备通信。模型加载后接收视频帧并把分段结果传给下一服务；大部分编排可位于不可信环境，敏感处理和信道端点须在受保护域闭合。

模型所有者向各 enclave 上传各自应服务的加密层。用户摄像头到 enclave、enclave 之间由 TLS 或类似协议保护；各端点的身份、测量策略、当前模型分段、信道密钥和授权邻接关系需要对应。论文用远程证明和加密来表达这些要求，没有给完整协议 transcript、实例/版本绑定或所有错误状态的实现证据。

两个关键执行分支需分开：全 enclave 分支在受保护端点之间传加密特征，允许在任意层分割；enclave 加普通 GPU 分支则在特征被认为足够不似原始图像后，把该特征明文交给不可信计算方。后一分支的性能优势依赖不同的隐私假设，不是对相同加密保护的透明替代。

## 4. 隐私约束与分辨率准则

论文给出两类允许的 placement：C1 所有层都位于可信设备；C2 对任何不可信设备上的层，其输入与原始输入的相似性小于阈值 δ。初始抽象允许 Pearson、MSE、SSIM 等指标，并用 1000 张图像的最大相似性建立逐层 profile。

实际设计最终把中间 feature map 的空间分辨率作为主要隐私代理。作者在可视化网格中观察输出，认为每个通道图像低于约 20×20 像素后难以被人识别；性能评估据此决定何时向普通 GPU 卸载。

空间分辨率低不等于信息少到满足一般隐私目标：通道数量、精度、跨帧相关性及属性可分性仍然存在。作为简单数学例子，space-to-depth 可以降低空间尺寸同时保留全部输入信息；这不是声称论文 CNN 使用了该变换，而是说明仅凭空间尺寸不可能推出通用不可恢复性。

同样，人看不出某个单通道可视化的对象，不证明机器不能从完整特征张量识别身份、推断属性或学习逆映射。1000 张 profiling 图像的最大值也只是有限样本统计，不覆盖任意输入或分布变化。C1 与 C2 不能统称相同强度的“无隐私泄漏”。

§VII 认为输入重建需知道前缀参数或获得输入/中间特征对，并建议认证阻止外部查询。这需要定义实际可见的先验、公开模型、受控输入和合法调用者；认证限制查询者身份不等于限制合法用户、串通客户端或公共数据带来的统计知识。论文没有对所有此类对手证明重建不可能。

对 UNet 这类后部空间尺寸重新增大的结构，作者建议使用多 enclave 分支；该自述本身也说明降分辨率启发式并不覆盖所有网络。它更不能直接推广到 Transformer 隐状态、LLM token、KV cache 或私有 adapter。

## 5. 分割优化、流水线与复杂度

每层 profile 包括各设备执行时间、包含加密的相关开销、输出 tensor 大小及传输时间 D/B。视频按 chunk 分组，目标最小化整批 n 帧的完成时间，同时满足相应隐私条件；chunk 大小也决定重新分割的粒度。

两个 TEE 的主要收益是流水线：TEE1 处理后一帧前半段时，TEE2 同时处理前一帧后半段。大 chunk 的稳态吞吐受最慢阶段约束，不能只优化单帧计算与传输之和。原文 Eq1/Eq2 展示第一阶段为瓶颈的例子，其 n 倍首阶段公式依赖该假设，不是任何 placement 都可直接套用的通式。

在相互独立、每阶段串行、传输也作为独立阶段且无额外争用的简化模型下，n 帧 makespan 为各阶段耗时之和加上 (n−1) 倍最大阶段耗时。共享 NIC/计算资源、不同阶段互斥、背压、可变服务时间及故障重试都会改变这个条件；原文没有据此提供恶意调度下的 deadline 保证。

placement tree 枚举连续分段的分配：先可信处理，再在其他 enclave/不可信设备上继续，可选最后返回初始可信域生成标签。对两个 TEE，作者给 O(M²) 搜索路径上界；R 个 TEE 时为 O(M^R)，依赖 R 是远小于层数的常量。这不是任意 DAG、任意通信图和动态多租户调度问题的通用多项式最优解。

运行中根据耗时 profile 偏离触发重分割。重新选择性能较好的位置，不自动迁移信任和授权：旧帧、旧模型分段、旧队列、输出目的地和新配置 epoch 必须有清楚的转换规则。论文未提供完整的恶意编排下热切换状态机，因此这里列为迁移到本项目时的研究条件。

## 6. 实验环境及用户研究

两台桌面均为 i7-9700K（作者报告 4.6GHz）、32GB RAM、SGX、RTX2080，机器间带宽限制为 30Mbps 模拟 WAN。模型为 GoogLeNet、AlexNet、ResNet、MobileNet、SqueezeNet，来自 TensorFlow Model Library，ImageNet 预训练；没有按未注明的 ResNet 深度补造结构。

三个监控视频源各取一小时，每秒采一帧，共 10800 帧，统一 224×224。这个数据集用于推理流水线；1000 张 profiling 图像与后面的人工调查又是不同样本，不能混算调查规模或数据多样性。

人工研究只有 10 名正常/矫正视力参与者。第一部分从 100 张、10 类 ImageNet 图像生成 25 个选层输出，让参与者识别对象；第二部分每模型一组原图与五个层输出，共 5 道排序题。每人总计 30 题，并允许缩放观察。

作者报告在高于 110×110 时识别率 100%，在 12×12–18×18 时明显下降，认为低于 20×20 是折中阈值；未给出针对完整特征的机器重建、属性推断或形式隐私界。图中的经验阈值不能作为多 Client 明文数据释放的通用安全政策。

## 7. 性能结果的正确口径

| 比较路径 | 作者报告的典型加速 | 应保留的条件 |
| --- | --- | --- |
| 1 TEE | 基线 | 整模型在一个 enclave |
| 1 TEE + 1 GPU | 三模型约 1.15–1.5 倍，AlexNet/ResNet 约 2.5–3.1 倍 | 达到明文特征释放阈值后交 GPU |
| 2 TEEs | 前三模型约 1.8–1.95 倍，另外两模型约 2.2–2.3 倍 | 增加可信执行资源、加密传输、流水线 |
| 2 TEEs + 1 GPU | 约 3.2–4.7 倍 | 更多资源与 C2 隐私策略的组合效果 |

最高 4.7 倍来自 AlexNet：两个 enclave 各做约 19% 处理，把约 62% 留给 GPU。它是 10800 帧整批端到端完成时间的加速，包括相应加密及传输；不是单帧延迟降低 4.7 倍，也不是同等资源、同等隐私假设下单一算法优化的收益。

单帧分析另报告传输约 0.01–0.12 秒，加解密开销低于约 2.5ms/frame，计算约 1.1–7.2 秒；作者因其占比较小在图中省略加密项。4/5 模型分到两个 enclave 后，分段计算之和比单 enclave 少，作者归因于内存压力减少；243MB AlexNet 较明显，5MB SqueezeNet 较弱。没有 EPC fault 原始轨迹，不把该解释写成已独立证实的唯一原因。

## 8. TF Trusted 依赖核查与证据限制

TF Trusted README 明确是研究实验库、not production-ready；先展示 enc-sim，再展示 SGX 部署命令。所读 driver 使用 SimLoader，enclave server 采用 InsecureServerCredentials，源码注释明确说明没有对端认证和加密信道，不适合生产。不能用 README 中“可远程证明”的能力描述代替当前服务代码已经建立 attested TLS 的证据。

proto 定义模型加载与 streaming 推理，输入为重复 float，携带 model_name、total_size 和 return_type，但没有应用级 Client、帧编号、分段版本或请求 epoch。所读服务在 runner 为空时装入一个模型，之后共享该 runner；请求中的模型名称不构成多模型/多租户授权。

服务合并 streaming 输入后复制到 TFLite 输入 tensor，所读 forward 未核对输入元素总数与分配尺寸，也未检查 Invoke 返回值；返回 tensor 的类型和数量还要与请求约定一致。这里是定向静态接口检查，没有完整审计 TFLite、gRPC 和所有构造器，也没有执行异常输入或声称复现漏洞。

客户端 helper 按 chunk 发送、用 RPC Finish 判断成功，再把返回元素复制到输出；注释把 65536 字节写作 4KiB，实际为 64KiB。这个细节不构成机密性结论，但说明必须按活动代码而非注释理解协议尺寸。Host RPC OK 本身不认证具体帧、模型分段或可信计算终态。

WORKSPACE 固定 Asylo0.3.4.2、TensorFlow1.13.1 及对应归档 SHA，不能概括为所有依赖都浮动。另一方面，本轮没有取得 Serdab 对 TF Trusted 的实际修改版、NiFi/Echo 部署图、TLS/payload 加密代码和重分割控制器，故上述依赖事实既不能证明论文的信道承诺已实现，也不能反推作者 Serdab 实际传输一定是明文。

## 9. 与后续论文及本项目的关系

TEESlice 将 Serdab 作为保护前层的代表，与其他模型隐私方案放在公开先验和代理窃取攻击下比较；Serdab 原文的主要目标却是输入隐私、诚实计算和受限查询。应清楚列出后来新增的攻击能力，不以统一 TSDP 标签消除两者目标差别。

对于 PORTAL/CAGE/ACAI 及本项目，保护域间传输的关键不在于特征看起来“不像原图”，而在于目标是否被授权访问该对象。接受 RMM 认证原始 Client、ProxyRealm 控制 SMMU、映射时检查实际 HPA/权限/生命周期并合成 GPU Stage-1、其他设备保持 Stage-2 的假设；不以老 SGX 内存容量否定目标平台。

可借鉴多 enclave 流水线的吞吐建模和背压分析，但须复用已有 GPUVM、认证队列、私有快照、native fence、cookie/epoch 与持久 IRQ127 维持归属。队列位置、模型名、连接成功或返回 OK 都不能替代原始 Client 身份和对象授权，也不建议新增重复 token 体系。

若扩展成多阶段模型服务，阶段完成只能推动它被授权的后继；必须绑定当前任务、对象、配置 epoch 和真实完成，旧阶段的迟到回复不能发布到新任务。重分割、取消和 reset 后，通知接收、结果发布、DMA 静止及旧页安全回收分别满足条件；Serdab 的信任模型没有证明这些恶意并发性质。

可验证项目包括跨阶段错序/重放、同 model_name 不同所有者、重分割时在途帧、伪造唤醒、阶段错误后仍返回 OK、共享资源争用下的背压和取消回收。性能要分别报告单请求、稳态吞吐、整批完成和新增资源；这些是后续建议，本轮未实现、未跑 GPU/SGX。

Serdab 的贡献在于隐私约束下跨 enclave 的 DNN 分割与流水线编排探索；加密 enclave 链路、明文低分辨率特征和诚实结果假设应分别评价。对本项目它补充的是多服务任务流与资源模型，不是可信 GPU 中断或强输入隐私的现成实现。
