## 2. 与 Portal、CAGE、ACAI 及当前项目的关系

这是GPU大规模计算的可信I/O与泄漏约束论文，不是Arm CCA GPU直通/SMMU/GPUVM架构。PORTAL等解决设备交给谁、可信管理层如何介入；IOValve进一步问：获得合法数据的计算软件如果本身恶意，能否通过合法I/O或时序外传秘密？其位置接近MICA的出口策略，但对网络时序通道采用更粗的物理隔离边界。

当前项目继续接受RMM认证原始Client、可信ProxyRealm控制SMMU、按实际HPA归属/权限/生命周期合成GPU Stage-1以及受保护页表/MMIO/可信固件等设计假设。IOValve不否定这些假设，也不要求把RK3588改成BlueField平台；硬件作为机制验证条件。借鉴时应明确新增的安全目标与假设，不能只在Realm内增加加密/轮询便沿用其整机无泄漏论断。

## 3. 威胁模型：软件栈也不可信

数据所有者不信任训练/推理程序、CUDA/NCCL、依赖库、OS、hypervisor及云网络软件；攻击者可主动利用软件可控的硬件侧信道建立隐蔽通道。用户信任DPU上的monitor、固件/硬件与数据中心物理安全。每个DPU由单租户控制，整个Host内部可以视作同一个不可信计算域。

明确排除计算完整性和可用性；输出可能错误、程序可以拒绝服务。物理篡改、增加另一NIC或修改主板配置等被排除。其“云不可信”具体包含恶意内部员工和外部入侵者，作者不将大型云公司本身作为实施硬件攻击的对手。不能把标题Leakage-Free扩展为任意共享平台、任意物理对手、任务正确性或抗DoS保证。

## 4. 核心设计：把沙箱边界移到唯一网络线缆

可信DPU截获整台Host的网络I/O，只允许预置密钥认证的用户后端与伙伴DPU；所有合法数据加密，其他目的地阻断。监控器与恶意应用分处计算机，避免在同一个CPU上共享缓存、分支预测器和调度资源。应用与Host OS不属于保密执行TCB。

必要配置包括DPU是唯一联网设备、Host无法管理/刷写DPU、DPU可控制BMC重置并重新部署Host、单租户DPU。实现采用BlueField Zero-Trust模式、隐藏RNIC，只向Host暴露DMA设备；Host不能访问DPU私有内存。Host拥有GPU原生访问，并非靠GPU内存加密来保护同Host内部不同租户。

这依赖“所有外部可见出口均被覆盖”的整体前提。推广到项目时必须清点日志、显示、共享页、调试、其他设备和管理接口；单独保护一个vmshm通道不能推出整个系统无旁路。

## 5. 两级部署、证明与密钥

用户先部署并证明DPU镜像，再由DPU接收Host镜像并重启/引导Host。DPU通过SPDM等已有机制证明后取得密钥，用于身份区分、DPU间通道和用户后端通道。策略在部署时固定，在reset前持续使用；论文不在实现章节展开完整部署/证明软件。

对不支持IOValve操作的用户后端，设计先将输入/输出暂存在DPU存储，再分阶段交付。它减少交互形态，但项目若借鉴仍须明确传出总量、起止时刻及释放条件是否公开；暂存本身不是对任意应用依赖输出时机的形式化非干扰证明。本轮没有验证完整SPDM/密钥轮换/防回滚与证明链实现。

## 6. 为什么加密后仍需隔离拥塞

普通RNIC若从Host DRAM读取合法数据，恶意程序可以通过争抢DRAM/PCIe带宽改变发包延迟；包内容即使加密，网络观察者仍能解码拥塞节奏。IOValve把网络收发缓冲放在DPU私有内存，RNIC只访问该内存；Host不能访问DPU内存，也不能直接发DMA命令给DPU或干扰RNIC到DPU内存的链路。

DPU主动pull/push Host固定缓冲，Host拥塞可以影响这一内部搬运，却不应控制DPU对外的发送节奏。可信端私有缓冲、独立进度与固定外发机制共同构成保证。项目现有private plan/snapshot具有降低共享状态信任的价值，但如果Proxy与Client仍共享CPU、互连和GPU，不能据“私有缓冲”一项声称阻断所有时序通道。

## 7. 四套环形缓冲与 lazy synchronization

每节点对使用双向单生产者/单消费者缓冲，Host send/recv与DPU send/recv分开。Host adapter提供兼容接口但不可信；DPU puller/pusher控制DMA，分别使用SQ。私有DPU send缓冲仅需本地CPU顺序，跨Host或远端共享缓冲另带元数据同步。

算法1/2在本地保存对方元数据副本，只有`sb == se`才采纳head/tail。生产者/消费者更新前增加起始计数，更新后将结束计数设成起始值；复制按低地址到高地址，计数放在元数据两端。算法3/4直接计算固定slot地址，DMA/RDMA跨缓冲搬运，避免经DPU CPU临时拷贝。作者选择双计数来减少DMA命令，并未使用较慢的DOCA Sync Event。

这是配合内存顺序条件的并发协议，不是元数据真实性认证。论文明确允许恶意Host破坏一致性，认为后果属于完整性/可用性范围外。项目不能照搬该排除项：需按不可信head/tail/长度做范围与溢出检查，固定授权窗口，取得私有快照并绑定请求身份。`sb == se`不证明内容来自合法Client，也不证明ring索引、DMA地址或任务已完成。

## 8. 固定流量：空闲、背压也不能停发

DPU regularizer定期用RDMA Read取得远端缓冲元数据，再用RDMA Write with immediate传送数据及元数据。每次发送固定单位：有真实数据且接收缓冲可用就发送填充后的真实块；否则向专用dummy区域发送同大小假块。元数据读取也固定，ACK流量同样整形。端到端IPsec硬件加速覆盖RoCEv2流量，使外部观察者不能按明文内容或地址区分真假写入。

连接在部署时按节点对建立并持续到终止，不按应用临时增减连接。Host层任意多个逻辑连接由adapter复用，不能让连接数直接决定外发节奏。保护需要同时覆盖大小、时间、连接存在性、元数据与背压行为；只固定payload长度或延迟某条IRQ不充分。

算法4中的`[-1]`表示专用dummy slot的抽象标记，正文解释为独立可RDMA但被丢弃的区域；没有源码时，不能将伪代码记号直接当作C负索引漏洞。固定流量安全性还依赖加密的完整封装、重放策略及可信发送调度，本轮没有相关实现证据，不宣称已逐项核验。

## 9. 中断与完成：论文没有提供什么

实现持续轮询DOCA DMA CQ与RDMA CQ；NCCL插件的test反复尝试入队/出队，CQ poller避免队列溢出。论文未提出CCA可信中断注入、GIC安全路由、多Client完成事件认证或IRQ重放处理。RDMA写完成、远端处理完成和GPU任务完成也是不同事件。

项目应继续将IRQ127解释为可信队列的检查提示，身份来自RMM认证端点和原始Client，终态来自匹配native fence/cookie/epoch。pending、ACK、ARM和重查解决通知丢失/竞态；不能用固定周期轮询或加密消息取代任务身份与权威终态。若另外要求隐藏完成节奏，可选固定预算通知，但必须覆盖队列/日志/资源争用等其他观察面。

## 12. 抗隐蔽通道评估：有力证据与未证明范围

作者qperf用64B负载测纯RDMA RTT，去掉Host-DPU DMA、整形和CPU争用以暴露拥塞影响，每项1000次。DPU路径DRAM压力两样本KS统计量0.069，PCIe压力0.09；Host路径分别1和0.997。这支持所测DPU结构大幅降低拥塞影响，但不等于所有外部轨迹严格不可区分。

若1000个样本分别独立同分布且使用普通连续分布两样本KS近似，5%阈值约0.06082，0.069/0.09并非自动“没有统计差异”。样本独立性、时间相关性、原始序列和检验目的未取得，不能凭该近似宣布真实泄漏攻击已成功；也不能仅凭均值落入误差范围证明零通道容量。进一步应测可重复分类、比特误码率、长序列积累和完整整形输出。

整形实验、拥塞实验与全系统证明需要区分。论文没有实际GPU多租户侧信道/中断攻击；单租户DPU与整个Host沙箱移除了本项目仍存在的多个共享边界。网络故障由对手造成可属于可用性，但若不可信Host能按秘密诱发DPU可观察reset/停发，生命周期行为还需纳入出口约束；这是推广时待验证问题，不是本轮已证实漏洞。

## 13. 与 MICA 的互补，而非简单优劣

MICA在CCA可信固件中限制通道拓扑、共享映射和控制出口，明确排除时序/微架构侧信道；IOValve将执行域扩为整台Host，利用分离的可信DPU和固定网络流量处理主动时序泄漏。前者适合细粒度组件组合，后者牺牲整机共享灵活性换取更简单的外部观察边界。

两者都不能因合法通道加密便证明接收方应获得所有内容。IOValve允许将结果发送给用户授权伙伴，若伙伴本身恶意且拥有解密权，恶意应用仍可把秘密编码在合法输出中。需要明确数据所有者的接收授权与去分类边界；不存在仅凭固定大小网络包识别业务结果是否夹带秘密的通用机制。

## 14. 项目建议：先完成权威事件协议，再选择泄漏目标

第一优先级保持现有可信事件链：RMM绑定来源/端点，Proxy私有快照校验请求几何与实际HPA，native fence确认终态，cookie/epoch阻止跨Client及旧实例复用，pending/ACK/ARM重查保证通知可靠。外部可见ring元数据一律视作不可信输入，不以双计数一致或IRQ到达替代授权。

第二优先级明确输出策略：谁能看到哪些完成字段、错误、日志和结果对象，哪一方能发布；绑定Client/Proxy实例、设备租约与策略版本。共享Proxy具备同时访问A/B的权力，其可信按Client分区依然是TCB，不能依靠网络出口整形消除Proxy内部的授权错误。

第三优先级若论文目标包含流量机密性，可为敏感通道添加固定大小消息、固定时间窗批量通知和空闲填充，并让可信缓冲/发送状态不由Client控制。需分别测额外时延、dummy带宽/CPU成本、GPU吞吐和观察者分类能力；动态减小预算、按任务完成停发、按ring满停止、按错误改变长度都会重新引入可见信息。该模式作为独立可选安全目标，不在未测前进入当前性能路径或宣称解决所有中断侧信道。

安全回收仍独立处理：停止新提交、推进epoch、确认DMA静默与引用释放、撤销映射和失效同步、清理再复用；网络ACK、加密认证或DPU存储暂存都不能证明GPU已经停止访问旧页。当前项目不是裸机单租户沙箱，引用时必须说明保证范围差异。
