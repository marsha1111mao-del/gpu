# VIA：机密虚拟机设备接口、共享元数据与中断驱动状态机精读

## 1. 身份、版本与项目定位

论文：Felicitas Hetzelt、Martin Radev、Robert Buhren、Mathias Morbitzer、Jean-Pierre Seifert，**VIA: Analyzing Device Interfaces of Protected Virtual Machines**，ACSAC 2021，273–284，DOI [10.1145/3485832.3488011](https://doi.org/10.1145/3485832.3488011)。Crossref 精确 DOI 的题名、五位作者、页码和 2021-12-06 出版日期已核对；实际精读为 [arXiv:2109.10660v1](https://arxiv.org/abs/2109.10660v1)，2021-09-22，12 页。显式 v1 与无版本 PDF 字节一致，SHA-256 为 `1d20f2ed10dca254042314e95d2aba48c4e62c3e0c3e642836ffa09a8c6b9bfa`；ACM PDF 返回 403，未逐字比对正式出版版本。

VIA 是 x86 SEV/TDX 机密虚拟机设备接口分析与模糊测试工作，**不是 Arm CCA 或 GPU TEE 架构**。纳入本项目的理由是它直接检验“私有内存被保护，但驱动接受不可信设备响应”这条边界，可支撑 Client–Proxy 队列、设备完成和中断通信隔离论证；不能用它充当新的 CCA GPU 实现数量。

本文完整阅读 §1–10 与全部 64 条参考文献，抽取全文 75,340 字符；视觉核对第 3、5、6、7、8、9 页，覆盖全部 6 个编号图与 6 张表。图 2–5 是代码示意，图注所写调用行号与展示编号有小出入，按实际代码语义理解；无独立编号算法或附录。

## 2. 威胁模型：保护私有页不等于保护驱动语义

§2–3 假设恶意 Hypervisor 不能直接读写受保护 VM 的私有状态，却能提供设备、配置资源、热插拔、修改共享描述符和队列、控制 MMIO/PIO 返回值、设备 DMA 内容以及虚拟中断。恶意 HV 还能影响执行调度并借反馈推测 Guest 执行状态；这是设备输入路径的权限，不能简化成仅有任意物理 DMA。

论文的实际攻击演示为 **SEV-ES、Guest Linux 5.10.8、关闭 KASLR**；作者讨论指针泄漏和侧信道可辅助恢复地址信息，但本轮没有验证这些替代前提。SEV-SNP/TDX 在当时是规格及公开补丁背景，作者将软件输入漏洞推广到两者的威胁模型，不能写成已经在 SNP/TDX 硬件上完成相同攻击。

关键边界是：设备只能直接写共享 bounce buffer，也可能诱使可信驱动依据被篡改的长度、地址或指针，**由 CPU 把恶意输入带入私有内存**。因此 IOMMU/GPT、加密与完整性保护不覆盖驱动自身被授权执行的错误复制。反过来，漏洞也不意味着硬件私有页保护被直接绕过。

项目仍采用 RMM 认证原始 Client、可信 ProxyRealm 管理 GPU/SMMU 的既定假设。恶意 Client 的提交是 Proxy 的不可信输入；Client 收到可信 Proxy 的响应，其真实性依赖通道端点与实际写权限。VIA 中“恶意设备后端”不能直接等同于本项目可信 Proxy 已被攻破，但可以用来审查 Host 是否仍能插入响应、其他 Client 是否能修改完成区，以及可信后端是否过度依赖共享字段。

## 3. 分析系统：有状态设备输入与定向中断

§4–5、图 1：VIA 把 Linux Kernel Library（LKL）、libFuzzer、设备模拟与 harness 放在用户态进程里。驱动作为共享库运行，coverage 只采集目标驱动，内核内存访问另做 AddressSanitizer 插桩；它不是直接在每个测试用例里启动完整 CVM，也不是 GPU 执行模拟器。

设备支持 PCI、Platform 和 VirtIO。PCI/Platform 的 passthrough 模式是按配置创建资源后转发变异输入、忽略驱动输出，**不是本文项目意义的物理 GPU 直通**；VirtIO 还可用遵循基本协议的 emulation 模式，以到达更高层驱动。基本 harness 做加载/卸载，扩展 harness 对网络、块和字符设备执行少量系统调用；覆盖范围取决于选用的 harness。

MMIO/PIO 在内核访问接口处注入输入。Streaming DMA 在同步点填充整个缓冲；coherent DMA 没有显式同步点，VIA 用特殊 ASan shadow 标记拦截读取并注入新值。这让不同读取可能获得不同输入，尤其适合发现共享控制字段未经稳定化的问题；论文说明所测驱动的 DMA 分配未落入编译器省略插桩的例外，不能推广为任意编译器与所有驱动无遗漏。

定向中断通过扩展等待/完成接口记录阻塞线程，在驱动等待设备时通知 harness 注入 IRQ，以减少初始化超时。它的贡献是提高到达有用驱动状态的概率，**没有提供中断来源认证、重放防护或 GPU 完成证明**。只在随机时刻发送 IRQ 可能错过状态转换；只在预期等待点测试同样不能覆盖所有异常中断时序。

延迟优化改写驱动调用的 delay/sleep、部分超时和时间比较，并把 delayed work 延迟设零；wait-event 所需超时保留。输入流耗尽时补伪随机值以降低卡死。VIA 模仿 swiotlb 的映射记录检查，避免因完全不验证 DMA 地址而制造模型错误；这不是 swiotlb 全部语义或并发正确性的形式证明。

论文以恶意 HV 可控计时/中断为依据说明优化的合理性。本项目的 IRQ127 受 RMM 限制，实际攻击者可注入的事件集合更窄，因此借鉴测试策略时必须保留真实端点权限和协议规则；不能把 VIA 宽模型下任何崩溃都认定为本项目可达漏洞。

## 4. 三类案例与可迁移的防线

| 案例及原文位置 | 失效机制 | 对当前 GPU 共享协议的启示 |
| --- | --- | --- |
| vmxnet3，§6.2、图 2 | 设备可写描述符存 Guest 私有对象指针，既泄漏地址又让设备选择后续操作对象 | 共享区只传受会话约束的对象 ID/范围；本地指针、回调、原生 fence 引用保存在私有状态，不能把共享指针转成可信对象 |
| virtio-net，§6.2、图 3–4 | 初始化错误路径释放对象却返回成功，后续设备移除使用已释放状态，其他设备分配可影响该状态 | 审查创建失败、取消、退出、reset 与迟到回调；拒绝输入也必须回滚注册/引用，不能仅证明成功路径 |
| VirtIO/swiotlb，§6.2、图 5 | 共享描述符长度控制 bounce 到私有区的复制，映射地址已有记录仍不足以限制实际复制范围 | 复制/回写长度和目的对象应由私有原始分配记录限定；检查地址、长度、偏移的组合及溢出，不能复用对端返回的容量 |

第三个案例最接近本项目的内存与通信交界：**“这个共享对象已授权”只证明对象可以共享，不证明任意对端自报长度都合法**。Client 在提交时合法拥有 BO，也不能因此让 Proxy 接受该 Client 指定的另一个对象 ID、越界 offset、过期 plan 或其他会话的 completion slot。

私有快照可避免校验后共享字段变化，但快照内部仍须检查数量、乘法溢出、范围、对象归属、权限及生命周期。仅用 READ_ONCE、锁住本端队列或缓存第一次读取的部分字段，并不能使完整多字段请求成为稳定且自洽的消息。合法的 BO 数据区若允许并发 GPU/CPU 写入，应另定义数据所有权，不必为了稳定控制请求把全部 payload 都复制到私有内存。

错误响应与设备移除同样是状态输入。不能把错误码、超时、收到 IRQ 或 fence 被 signal 一概视为成功；取消后的完成不得访问已释放对象。安全回收仍需保证旧 GPU/DMA 访问实际终止、映射及缓存状态失效，VIA 的驱动卸载测试并未证明这些 GPU 条件。

## 5. 结果、算术与适用边界

§6.1、表 2–3：作者在 Linux 5.10.0-rc6 上分析 22 个驱动，20 个发现问题，合计 50 个；其中 19 个驱动对应 QEMU 设备、3 个对应 Google CVM 使用的设备。表 3 的 14 个越界、10 个无效访问、8 个 slab 管理、5 个共享指针、3 个其他、4 个断言、5 个无界分配和 1 个死锁独立求和为 50。作者当时称 9 个已修复或正在修复，不能解释为 50 个均有正式 CVE、均能执行任意代码或目前仍未修复。

发现过程跨 2020-11 至 2021-02，采用间歇 fuzzing；为了继续深入会修复已发现问题并人工移除 e1000/rocker/sungem 的复杂 checksum 检查。表 4 的对照明确称没有修改驱动；表 5–6 使用修补/扩展 harness 等不同条件。不能把后两组 TTB 和覆盖率当作原始未改驱动的直接观测。

§6.3 记载测试机器为“8-Core Intel i7-7700、64GB”，每驱动限一个 CPU core。CPU 命名与“8-Core”表述本轮未独立核实，原样保留而不自行改成确定的物理核数。对照采用空初始 corpus、固定随机种子、10kB corpus 上限、单次 120s 超时，每驱动三小时；固定种子控制变量不代表多种子置信区间。

表 4 为 11 个 PCI 驱动、基础 load/unload harness、Agamotto 与 VIA-D/VIA-ND。按展示数据复算执行数总和之比分别为 **1917.09/2709.96 倍**，接近正文 1915/2706，差异不能在无原始数据时断言错误；逐驱动倍率算术均值为 **2878.65/3663.04**，几何均值为 **123.83/962.45**，与正文口径不同。摘要的 2706 倍只能作为作者所报聚合测试吞吐，不能变成每个驱动或 GPU 系统的加速。

表 4 覆盖率列总和之比 **131/58=2.2586**，接近作者 2.26；逐驱动覆盖率比的算术均值则为 **2.5393**。这是不同驱动覆盖百分比的聚合，不是所有驱动指令按实际数量加权后的总体覆盖率，也不是漏洞检出率翻倍。

表 5 实际展示 **21 行**，虽然正文说对表 2 各驱动运行，表中没有单独 virtio-ring 行；不据此补造结果。ND 执行率算术均值 **569.81 次/s** 对应摘要约 570；倍率算术均值 **163.76** 接近正文 163，但中位数只有 **1.617**，去掉 virtio-rng 的 2282 倍后均值约 **57.85**。收益分布很不均匀，virtio-net 553→400 次/s 是 **−27.67%**，e100 覆盖块 573→569 也有下降，不能说优化对所有目标都提速且覆盖不减。

图 6 的 rocker 定向中断实验为 1000 次运行，对照随机间隔 1–1000ns（原文所写单位），均值 **17.66→6.78s**；独立复算比值 **2.6047**，时间减少 **61.61%**。它衡量到达首个 bug 的时间，既不是可信中断递送延迟，也不是 GPU 完成通知性能；不能把两个指标混用。

表 6 一般为 128 次平均 TTB，应用修补避免低严重度 bug；tpm-tis 的 **7200+s** 明确是少量运行估计且无法稳定触发，不能称所有驱动 128 次稳定成功。未取得逐次 corpus、随机轨迹、统计原始数据或完整未修改实验栈，故没有重算置信区间、图 6 直方图或独立复现论文结果。

## 7. 与本项目现有代码的对应

当前设计入口为 `docs/shared/CURRENT_BASELINE.md`。本轮另外限定阅读 Proxy 的 snapshot publish/watch/unwatch、Client 的 cookie-completed/snapshot-completed 以及 RMM `xshm_irq.c`；这只是相关路径复核，未重做全仓安全审计，不继承历史 PASS 为新安全证明。

Proxy 在私有 watch 中持有原生 fence 引用和 slot/cookie，成功完成才 release-store cookie；取消/移除回调先等待可能在途的回调再释放 slot。Client 用私有预期 cookie、slot 范围和 acquire-load 匹配完成记录。RMM 检查 Host 提供的 LR，拒绝伪装保留 IRQ127，并由可信路径注入。三者分别对应**完成语义、对象生命周期、通知来源**，应分开表述。

这些机制成立仍依赖 completion 页真实访问权限、会话及对象身份绑定、原生 fence 链选择和端点生命周期。cookie 是精确匹配/防旧 slot 混淆机制，**单调计数器本身不是密码学 MAC**；如果威胁模型中的 Host 或别的 Client 能写记录，数值相等不足以认证完成。本轮没据局部代码证明实际页权限，也没发现并验证新的绕过。

项目已有 private plan/snapshot、GPUVM/BO 归属、cookie/epoch 和 IRQ127，应优先把它们的联合不变量写清并验证，无须因增加参考论文再设计一套重复的认证队列。软件 IPA→HPA 翻译授权建立时合法映射，执行期由受保护硬件 Stage-1 限制访问；VIA 补充的是**合法共享通道内的控制语义与错误生命周期**，不会否定这个地址保护假设。

## 8. 建议纳入论文的安全属性与验证方向

| 安全属性 | 建议在现有路径证明的内容 | 研究验证方向，非本轮已执行 |
| --- | --- | --- |
| 请求稳定且对象合法 | 复制后整体校验，数量/偏移/长度不溢出，ID 解析到原 Client/会话/实际 BO，执行引用仍有效 | 描述符重复读取、数量与长度边界、同 ID 跨会话、旧 plan、新旧 epoch 组合 |
| 通知不能制造成功 | IRQ 只触发排空；无对应可信终态时不能完成 fence，错误/取消不发布成功 | 无数据 IRQ、重复/合并 IRQ、通知早于记录、记录可见后 ACK+ARM 竞争、迟到通知 |
| 完成只能消费对应任务 | 私有 slot/cookie 与实际原生提交/依赖链匹配；另一个 Client 无权影响 | 旧 slot 重用、跨 Client 完成记录、reset 前 cookie、依赖未完但 leaf 先完成 |
| 生命周期与回收安全 | 失败回滚、在途回调、最后引用、撤销及实际 DMA 静默后才能清零/复用 | 创建半失败、断连与完成并发、撤销时在途任务、reset/超时后的迟到 DMA |
| 隔离故障传播 | 非法输入在对应 Client 内可拒绝，资源预算限制跨 Client 影响 | 队列耗尽、重复错误、异常退出后受害者继续计算；不承诺恶意 Host 下可用性 |

上述应在现有测试接口中形成状态序列，既覆盖可信正常完成，也覆盖敌手能触达的错误与通知顺序。VIA 的 LKL 无隐式抢占，作者明确承认 race 检测能力受限；不能用用户态顺序模型的 PASS 替代真实多核、缓存、DMA、reset 生命周期论证。本轮只提出后续实验方向，没有编写或运行新的攻击和测试。

## 9. 对研究主线的结论与统一记录

VIA 支持把项目第二部分命名为“面向多 Client Realm 的 GPU 任务与控制通道隔离”：内存部分证明真实页、权限、映射和撤销；通信部分证明请求/响应/中断不会把其他 Client、旧生命周期或错误任务的状态当成本任务结果。地址隔离完成后，可信软件仍有共享字段处理和失败路径的安全责任。

更完整的判定链为：**端点合法 → 请求与对象授权 → 真实 GPU 提交 → 对应原生任务终态 → 按约定同步与发布输出 → 通知/消费 → 旧访问终止与安全回收**。中断提示、任务终态、应用算法正确性、输出发布、DMA 静默和复用资格分别判断；VIA 没有一次性证明整条 GPU 链，本项目也不宜把它们压缩成一个“完成”标志。
