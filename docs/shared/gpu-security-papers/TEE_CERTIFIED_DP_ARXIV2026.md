# TEE-certified DP：可信抽查、延迟验证与 GPU 完成语义

## 1. 文献身份与项目定位

论文：Towards TEE-Certified DP: Verifiable Differentially Private Training on Legacy GPUs。作者 Li Ge、Wenjie Qu、Weitao Feng、Yi Zeng、Jiaheng Zhang、Xiaofeng Wang、Wei Dong，前两位共同一作。研读版本 arXiv:2609.20532v1，2026-09-17。按预印本登记，未核实正式会议录版本。

来源：[摘要](https://arxiv.org/abs/2609.20532v1)、[PDF](https://arxiv.org/pdf/2609.20532v1)、[HTML](https://arxiv.org/html/2609.20532v1)、[论文源码](https://arxiv.org/src/2609.20532v1)。PDF SHA256：08e922a3a2d2ac4a4f6d65ac4c25196a27bba1fa78a6a214e9d0ed01021613c1。

本篇属于 CPU TEE 验证不可信 GPU 训练协议的应用层工作。与 PORTAL/CAGE/ACAI 的设备隔离目标不同，不能当作新的 CCA GPU 保护架构。最直接的项目价值是可信提交、后台验证与最终完成证明之间的边界。

## 3. 它保护什么，谁仍能看见数据

作者模型包含数据提供者、训练公司和监管者。训练方 GPU 不可信，CPU TEE 保存数据及可信状态，监管者希望验证最终模型来自声明的 DP-SGD 协议。原始训练数据仍交给 GPU；本设计不向训练方或 GPU 隐藏原始数据。

DP 讨论的是发布模型对单条记录的泄漏，不等于训练期间的数据机密性。CPU TEE 需要可信数据、重计算栈、模型/优化器、噪声和验证逻辑；不能把其 TCB 描述成一个很小的比较函数。vsock 是实验通信路径，其名字本身不构成消息身份认证或保密证明。

与本项目相接时，RMM 认证 Client、ProxyRealm 管理实际 HPA 归属、受保护 Stage-1/root/MMIO 等既定前提仍然独立成立，不能用训练抽查替换。

## 4. 基本协议：先提交，再抽样和产生噪声

GPU 完成每样本梯度、裁剪及平均，提交步骤号、批次及聚合梯度。TEE 对所有步骤执行结构/聚合范数检查，再用隐藏、独立的 Bernoulli(p) 硬币选择重计算步骤。TEE 生成 DP 噪声并完成可信优化更新，向 GPU 返回该步噪声种子以同步镜像状态。

逐样本梯度裁剪到 C，平均后加标准差 σC/B 的噪声。聚合范数不超过 C 只能约束返回向量，不能证明每条记录的影响受裁剪限制、批次正确或数据真实。作者的始终开启聚合范数裕量为 1+10^-4。

关键顺序是 GPU 的当前提交不可更改以后，才能采样当前审计硬币及揭露当前噪声。项目类比是私有提交快照，而不是只锁住共享队列里的指针。实际实现还需要形状、dtype、NaN/Inf、长度、步骤/epoch及数据版本检查；未获实现，不能把这些需求写成已发现的可利用漏洞。

## 5. 两类偏离与概率保证

作者把反事实完整检查会拒绝的步骤记作 M_full。在提交先于当前硬币、硬币独立且隐藏等条件下，前 M_full 次此类偏离全未抽中的概率为 (1-p)^M_full；自适应地根据过去历史选择偏离仍可满足这个条件。

M_full 不自动等于所有修改步骤数。作者在所测攻击中利用诚实梯度范数和接近边界的伪造梯度来支持二者一致，而不是对每次攻击提交都逐一重验。观察过去检查耗时也不自动预测下一次独立硬币；当前硬币若在提交前泄露则破坏前提。

当 M_full=50，p=.10/.15 的检测率分别约99.4846%/99.9704%；CIFAR 性能点 p=.02/.05 则约63.58%/92.31%。不能把 LLM 的99.5%直接贴在低抽样率 CIFAR 结果上。

## 6. 稀疏攻击并未获得通用 DP 安全证明

作者用 Current、Nearest、Final 等优化器感知的检查点引导攻击，研究少量修改是否明显提高效用或增加成员推断泄漏；稀疏阈值主要取50步。这是限定攻击族的经验论据，不是任意隐私攻击的安全证明。

定理5.1在小采样率及高斯近似记账下给出 ε'/ε≈sqrt(1+(M/T)(4N²−1))。由于任意有界聚合向量仍可能集中针对一条记录，少量违规甚至单步可导致很差的最坏情况 DP 参数；作者对此有说明。把影响分散给 κ 个用户，需要独立证明每用户影响确实缩小，不能由用户数很多推出。

成员推断只覆盖 Purchase/CIFAR 及 IMIA、SHAPOOL，未给 LLM 成员泄漏完整验证。AUC 接近随机不等于 DP 证明。Purchase 的一个50步攻击提升约2.32个百分点，WebNLG/E2E的示例约+.80/+.77，不能普遍称“收益可忽略”。表5逐指标最优值可能来自不同运行，不能组合成同一次攻击的结果。

攻击评估还有单训练 seed、dropout=0、特定攻击位置及部分解码选择等边界。按固定批大小洗牌/drop-last训练，使用 B/N 的常见近似 DP 记账也不自动等于严格 Poisson 采样分析，应明确实际采样器。

## 7. 浮点容差：不能每步免费放行

TEE 首先重算 FP32，用相对裁剪范数的差值 z32 判断。低于 τ_abs 的微小偏离计入累计账本 Z_sub，超过 K_sub 则中止。较大差值再交 FP64 判断；若 z64 不超过 ρ_amb，计入歧义计数 S_amb，超过 K_amb 也中止，否则拒绝。

CIFAR 不使用 FP64，改为 FP32 上同一度量中的第二阈值 ρ_ill=2τ_abs。因此“有容差”并不表示无限次数的小偏离不受约束。FP64 判为可接受也不是数学上精确诚实的证明。

表7主工作点 p=.1：RoBERTa/GPT-2/CIFAR 的 G_extra 为5.478/9.496/2.511，β_extra均.05；其 τ_abs 为.0016/.00174/.00073，K_sub 为.088/.72/.20，K_amb 为25/17/5。参数只在声明的工作点、账本与轨迹条件下解释。

## 8. 联合概率界，不是通过之后的条件保证

附录E对小偏离使用鞅浓缩/反演，对歧义次数使用二项分布反演，得到 Pr[G_tol>G_extra 且该运行被接受]≤β_extra。这里的“接受”指所有后台验证完成后签证书。

这个界不是 Pr[偏离超界∣接受]≤β_extra，也不是偏离的确定上限。G_extra不是 DP 的 ε 或 δ，更不能无条件换算成任意训练上的“恶意步骤数量”。参考计算可按提交在 FP32/FP64间自适应选择，两个可信参考轨迹之差不计入该偏离账本；它不界定距某个唯一诚实最终模型的距离。

正文式6将 G_extra经验换算成引导攻击的等效步数，不能当作完整形式化联合检测率；这一解释还需要其校准假设，并不能悄然省掉 β_extra 风险。

## 9. 校准、误中止和泛化边界

同状态引导尺度比较覆盖 RoBERTa 九个检查点、GPT-2三个状态及九个半径，最大比率约1.00064/1.00038。比较共享相同噪声且两个分支并非独立佐证；论文说明独立噪声时会变化2–3倍，跨攻击与部署轨迹族迁移仍为经验假设。

较广校准含32轨迹、每配置4副本，部署参数还依赖8条试验轨迹中每十步的系统采样。系统样本有代表性是额外假设。7/8在样本内满足目标，qqp-large被排除；唯一冻结参数后新seed完整回放的 held-out 轨迹是qqp-large。

其约4.1×10^-100的误中止上界是给定这条完整已实现轨迹后的抽样条件界，不是未来所有运行的误中止率。GPT/CIFAR无同等 held-out 轨迹证据。CPU/GPU数值对应另只有少量步骤检查；校准/性能优化器分组差异、运行长度变化、软件栈变化均需重新验证适用性。

## 10. 延迟验证：可以先执行，不能先认证

hungry updating 将选中的重计算放入后台；TEE 可以先做暂定更新并释放当前噪声种子，GPU继续下一步。论文明确要求所有排队验证成功且账本合规后才签发最终证书，任一后台检查失败则该运行不接受。

因此 GPU 已算完、CPU已更新或收到通知均不构成认证完成。后台任务须持有重现当时状态所需的不可变快照，涵盖相关模型/优化器、RNG、批次、数据、提交梯度及配置；用最新状态重算旧步骤会检查错误对象。

论文只以证书门控最终模型。GPU 已持有镜像和暂定中间值，签证书前已经释放的信息或外部副作用不能靠最后拒绝追回。这与 Fastrack 的暂定输出问题相通，应把可推测执行和不可撤销发布分开论证。

## 11. 证书、重试与防回滚

论文给出高层 TEE 证书描述，未核实完整证书格式、模型摘要绑定及可复现的证明链实现。面向项目的建议是绑定 Client、任务/设备epoch、run-id/nonce、输入和模型版本摘要、协议参数、抽样/容差账本、最终输出摘要与验证排空结果。

论文的失败标志仅在持久 sealed storage 和 rollback protection 可用时适用，并限制同一 TEE 实例。恶意训练方重建实例或反复尝试，需要外部可信尝试账本、防分叉及验证者颁发的运行标识。单次漏检风险不能自动作为多次重试的总体风险。

数据集摘要还必须绑定到 TEE 实际检查的原始可信数据；只验证 GPU 与攻击者替换的数据集一致，不能证明用户授权数据被正确使用。认证链路也不能替代这些语义绑定。

## 12. 性能条件和数字复核

单 RTX PRO 6000，CPU侧为64 vCPU、512GB的 AMD SEV-SNP VM，vsock通信。任务含 GPT-2 Small/Medium 的E2E/WebNLG、RoBERTa Base/Large 的QQP/MNLI，主要采用 LoRA。不是多GPU或超大模型全参数训练验证。

| 指标 | 论文结果及解释 |
| --- | --- |
| LLM p=.10 | 相对未验证GPU训练增加4.4%–14.9% |
| LLM p=.15 | 增加11.7%–30.2% |
| RoBERTa QQP p=.20 | Base/Large约增加40.5%/57.5%，不可外推低开销 |

CIFAR GPU基线500步而VDP窗口200步，不能直接用1306.04s与743.29/801.80s总量比较提速。其容差预算2.511对应p=.1而非性能点，论文低p重算预算约12.66/5.05，应同时报告工作点改变后的安全代价。

性能采用固定随机子集大小 ceil(pT)，形式分析则用独立 Bernoulli 硬币；二者分布不同。固定子集不能直接套用历史自适应独立硬币推导，性能也没有完整测量 Bernoulli 工作量波动。Fig4 Large p=.2 的Drain是17秒，不能把相邻62等标签拼接误读。

## 13. 并行验证收益与排队风险

论文给出的 n≥pT_iter-veri/T_iter 是平均验证吞吐条件，不是突发队列上界、延迟SLA或资源安全回收证明。Fig5中K=4相对优化配置每检查时延约+29%、端到端约+18%、空闲算力约+3%，说明检查延迟和整体吞吐是不同指标。

对共享 GPU，Client公平性、拒绝服务、快照内存峰值、验证排空和超时恢复还需分别评估。超时不能直接释放仍可能被设备访问的页，后台应用检查结束也不能证明 DMA 静默。

## 14. 对本项目的具体借鉴

第一，保持可信任务记录的权威性：RMM认证的 Client身份、实际HPA授权、任务cookie/epoch、native fence和私有提交快照应形成可核对的记录。中断只提示状态可能变化；不能让Host提供的通知自行决定任务成功。

第二，分别判定设备完成、可选应用验证完成、结果发布和安全回收。应用层检查可以异步，但发布门必须验证所有前置状态；资源回收仍需停止提交、撤销映射、必要失效/同步、DMA静默及清理。沿用既有IRQ127设计不妨碍这些语义细化。

第三，异步状态必须按 Client与epoch隔离，后台任务引用不可变计划和状态，迟到通知/旧验证结果不能改变新任务。失败、重试、reset及重建都应显式定义终态；不应新增与现有cookie/fence重复且无权威来源的共享完成位。

第四，不把10%抽查用于页表授权或中断归属。内存和消息隔离是每次必守的安全不变量；随机复算只适合另行声明概率目标、适用应用和失败策略的计算完整性扩展。本项目目前没有必要为基础隔离直接引入完整DP训练器。

## 15. 与核心论文的关系及后续方向

PORTAL/CAGE/ACAI回答可信设备服务及归属边界，PhantomMap关注实际页和映射生命周期；本篇补充“GPU给出结果之后，可信方如何判断应用协议被遵守”。二者应组合论证，不能互相代替。

中断研究继续以来源、目标、任务绑定、不可重放、丢失恢复和撤销后迟到事件为主。Heckler/WeSee/Sigy等既有精读说明事件注入可能改变可信程序语义；本篇说明即使真正设备完成也不等于数学结果或协议合规。

后续引用候选包括 GINN、TrustFL/TrustFL+ 和 AFTUNE；当前仅记为查找线索，不登记为全文精读。直接 CCA 的 GR-T正式版、XpuTEE、AccShield、FlexClave等缺全文项继续保留，不以应用型论文补齐数量。
