## 2. 与本项目的关系

TensorTEE 是 CPU 与离散 NPU 协同训练的安全内存架构，不是 CCA/Mali GPU 直通方案。其相关性有三处：跨可信执行域传递数据时要同时协调数据和安全元数据；性能优化不能破坏版本与生命周期；设备计算结束和结果可信可发布是两个不同条件。

对本项目，最适合借鉴的是可信状态及发布边界，而不是直接增加论文中的加密硬件。仍按既定假设分析：ProxyRealm 统一控制 SMMU，RMM 认证 Client，映射建立时检查实际 HPA、归属、权限和生命周期，受保护的 GPU Stage-1 在执行时限制访问。TensorTEE 不能替代这些逐 Client 授权条件。

## 3. 背景与瓶颈

CPU TEE 通常为每个 cacheline 维护版本号 VN、MAC 和完整性树；NPU 可利用张量访问规律共享 VN，但仍可能按 cacheline 保存 MAC。两端粒度不一致时，安全传输需要中转、解密及重新加密，额外占用带宽，阻碍梯度计算和通信重叠。

论文把问题分成 CPU 元数据访问、NPU MAC 存储和验证停顿、CPU–NPU 传输三部分。其训练场景让 CPU 执行 Adam 等更新，NPU 执行前向/反向计算，DeepSpeed 风格 offload 导致大量权重和梯度传输。结果不能推广到所有 GPU 图形、交互或低传输任务。

## 4. 威胁模型、可信基与排除项

攻击者可以控制 OS 和特权软件，也能嗅探内存/PCIe 总线、冷启动读取片外存储、篡改或重放数据。片外 CPU DRAM 和 NPU GDDR 不可信，片上 CPU、NPU、cache、内存保护和元数据控制硬件可信。

作者将 TCB 描述为片上架构。解释安全论证时，还必须保留其隐含执行条件：可信 enclave 代码、正确的安全指令及控制、代码/数据请求分类和元数据协议不能被攻击者绕过。不能把“硬件自动检测张量”理解为任意恶意代码都不影响安全，也不能据此把编译器插入的发布屏障从安全依赖中删除。

排除时间、功耗、电磁侧信道、DoS 和对抗样本攻击；模型提取另由正交方案处理。因此该工作不证明设备调度或中断时序不泄漏，也不提供任务一定得到执行的保证。

## 5. 架构：统一粒度而非取消保护

CPU 侧 TenAnalyzer 维护张量范围、stride、VN 和 MAC；NPU 侧采用张量级 MAC、延迟验证及 poison 传播；两端建立互相授权的 enclave，并通过可信元数据通道和直接密文通道传输数据。

统一格式让同一受保护张量在两端不必重新包装加密。这里的“直接”仍依赖安全元数据、密钥、地址语义和同步，绝非绕过授权的任意 DMA。数据通道中传输的是片外密文，可信计算发生在片上明文域。

## 6. CPU 读取：从 VA 访问学习张量结构

普通内存控制器看到的 PA 已经被缓存替换、预取和不连续物理页打乱。TenAnalyzer 因而直接接收 core 的 VA 请求，并与多级 cache 处理并行。每个 enclave 使用独立密钥；上下文切换保存/恢复对应 Meta Table，避免同 VA 跨 enclave 混用元数据。

Meta Table 命中范围时提供片上 VN；边界命中时先用候选 VN，同时读取片外 VN，匹配后才扩展范围；完全 miss 时走普通元数据访问，并交给 Tensor Filter 收集模式。Filter 在设置中的四个地址满足相同 VN 和规律 stride 后初始化条目。

对分块矩阵，短连续段形成多个条目，再按维度、stride 和 VN 合并。该机制推断的是可共享元数据的结构，不是证明调用方拥有这些物理页；项目仍须独立检查 Client、对象和最终 HPA 的授权。

## 7. CPU 写入：共享 VN 的条件比连续地址更严格

为保证张量级 VN 与各 cacheline 的更新一致，论文使用 bitmap BM、Updating Flag 和 Bit State，要求一次张量更新内每个 cacheline 恰好更新一次；完整覆盖后增加张量 VN、翻转状态并结束更新。

若更新重复、覆盖不完整、张量和普通变量混合或合并对象更新频率不同，相关断言失败会使表项失效，回到普通元数据路径，不能继续使用推断出的统一 VN。位图完整副本在 DRAM，由硬件隔离保护，片上只缓存部分内容；不应将此描述为没有片外元数据成本。

对项目执行计划缓存，可迁移的是“模式成立才复用，条件破坏必须失效”。对象句柄、VA 或大小相同，不足以证明对象版本、页归属和权限仍相同。可信的优化缓存必须跟随映射及对象生命周期。

## 8. NPU MAC 与延迟验证

论文将各 cacheline MAC 异或形成张量 MAC；单行 MAC 包含密钥、密文、地址和 VN，因而“异或对顺序不敏感”不等于删去地址或版本绑定。MAC 输出为 56 bit，正文的盲猜量级是 `2^56`，PDF 文本抽取会把上标连成 `256`，本次已用字体大小和坐标核对，不能误记为 256 次。

大粒度 MAC 必须等更多数据才比较完成。TensorTEE 允许 NPU 对尚未完成整张量验证的解密数据先计算，以减少停顿；代码取指始终使用非延迟验证。论文由可信 instruction buffer 提供 `isInst` 标记，不能允许不可信请求自行把指令标成数据。

56 bit 输出空间的论述不是整个协议的独立密码证明。本次没有重新证明 XOR 聚合在所有并发更新、地址重定位和失败路径下的安全性，也不把作者的盲猜分析扩展为任意攻击成功率结论。

## 9. Poison 与验证屏障：结果何时可以发布

未验证输入张量带 poison，使用它产生的输出继续带 poison。编译器将 `#pragma verification barrier` 转成完整性同步操作，通信必须等相关张量解除 poison；论文举例在 `.cpu()` 一类传输函数前自动插入，并用计数器限制未验证张量数。

安全解释必须是成功验证后才允许释放依赖结果；验证失败不能当作正常清除 poison。正文主要描述追踪及通信屏障，没有提供覆盖所有设备接口、所有异常和并发交错的完整状态机或形式化证明。本轮没有代码可独立核验失败传播实现。

这给项目带来一个清楚的语义：物理 IRQ、原生 fence 结束、错误检查通过、所需缓存维护完成和输出可交付应分别有可信条件。如果未来增加认证、解码或结果转换，最终成功还必须等待这些步骤。通知只是让接收者检查可信状态，不能提升结果的可信等级。

## 10. 延迟验证为何不能直接推广到通用 GPU

作者认为 NPU 缺少 OS 和文件 I/O，临时篡改中间数据不能发展为数据窃取；代码先验证、通信受屏障约束是这个主张的关键背景。

对拥有数据相关访存、命令队列、内部 MCU、DMA 或共享输出的 GPU，需要另外说明污染值能否影响地址、控制状态或其他对外通道，以及这些通道是否全部受约束。缺少文件 I/O 本身不构成通用设备无泄漏证明。这里提出的是迁移时所需的论证条件，并非声称已发现 TensorTEE 或本项目的可利用漏洞。

因此本项目可以借鉴“发布屏障”的概念，但没有理由仅因性能收益就允许未认证内容参与任意 GPU 执行；既定内存隔离与固件信任条件继续成立。

## 11. 跨 enclave 直接传输协议

首先创建和证明 CPU、NPU enclave，双方依据报告互相授权，并通过 Diffie–Hellman 一类交换获得共同的加解密密钥；密钥保存在片上。随后 NPU 请求张量范围，CPU 控制器查询片上表，将地址、VN 和 MAC 经可信加密通道发送，同时直接搬运 DRAM 中的张量密文。

元数据和数据可以并行到达，但消费前必须同步。共同内存格式省去重复加解密，不意味着所有 enclave 共用一个全局密钥；隔离应按被授权的端点和会话解释。

正文协议抽象了证明授权、密钥交换与同步，没有完整展开撤销、端点重建、地址改变、乱序元数据和数据版本配对。对 CCA 项目，相应推断是绑定服务实例、Client、对象版本、范围、权限和 epoch，并以原子可见的可信记录确认发布；这属于项目设计建议，不是论文已实现的 CCA 协议。

| 结果 | v1 数字 | 限定 |

| 端到端训练 | 相对 SGX+MGX 平均 4.0×、最高 5.5× | 模拟的组合优化，非单一安全检查开销 |

## 15. 与相邻工作和项目设计的综合判断

与 PORTAL/ACAI 相比，TensorTEE 解决的是已授权异构执行域内部的保护粒度与数据流效率；与 PhantomMap 相比，它关心版本/MAC 一致性，后者提醒实际物理页和类别必须正确；与 MOLE 相比，它的纯 NPU 执行模型不能省去对 GPU MCU 和固件边界的论证；与 PipeLLM 相比，两者都强调提前计算或提前返回必须配套私有状态、验证和可见性控制。

本项目当前已有 RMM 认证队列、私有请求快照、独立真实 GPUVM、原生 fence、cookie/epoch 和可信通知。建议在这些已有机制上补一份任务状态与结果发布不变量：哪个事件允许从执行中进入成功；错误如何阻止成功发布；取消/reset 后旧结果何时失效；哪一步才能允许对象回收和跨 Client 复用。不能把这些已有机制重新包装成尚未实现的新建议。

可验证的下一步包括延迟/重排通知、reset 与原生 fence 竞争、完成后缓存可见性、旧对象版本仍有异步引用以及失败状态被误当成功等测试。若引入新的数据认证层，再专门验证“未认证结果不可读”；不应为套用论文而增加当前架构不需要的机制。论文支持的是研究问题和设计条件，尚不支持本项目已经形成新的完整安全证明或性能结论。
