## 2. 威胁模型：无需读取受害者内存

攻击者运行普通用户权限的 OpenGL 或 CUDA 应用，与受害者共享 GPU，观察自身可调用接口和资源竞争。目标包括浏览器图形工作和 CUDA 计算任务，覆盖 graphics→graphics、CUDA→graphics 与 CUDA→CUDA 组合。

同机/同 GPU 共置是前提，云端如何让攻击者与目标 VM 共置是正交问题；论文不证明任意部署中可强制共置。CUDA→CUDA 同时执行主要利用 MPS，另对不启用 MPS 的时间片交错情形作观察。

这里不需要篡改其他任务页表、越权 DMA 或读出受害者明文。合法共享接口暴露整体使用情况，或者自身任务的耗时/计数被受害者影响，就可能泄漏活动。这说明内存访问隔离与无信息流泄漏是不同安全目标。

论文当时指出 WebGL 缺少实施这些观测所需的接口，因而没有实现浏览器 JavaScript spy；浏览器/WebGL 工作可以作为被本机恶意应用观察的受害者。不能把该威胁改写为访问网页即可发动全部攻击。

## 3. 三类观测通道

| 通道 | 本文实际使用方式与限制 |
| --- | --- |
| 显存可用量 | OpenGL NVX_gpu_memory_info / glGetIntegerv，或 CUDA cudaMemGetInfo；反复查询全局可用物理显存，形成分配/释放轨迹 |
| 性能计数器 | 自身 CUDA kernel 的访存、cache、issue stall、执行单元等计数；即使计数只归属自身工作，也会受到共享资源竞争影响 |
| 时间 | 对自身操作计时，观察并发竞争或上下文切换后的状态影响；限制显式计数器不自动消除时间信号 |

作者讨论集成 GPU 没有同样的独立显存全局用量接口，因为 CPU/GPU 共享内存；其性能计数器可能形成其他通道。不能直接把 NVX/cudaMemGetInfo 的离散 GPU 利用轨迹照搬到本项目 Mali 平台，也不能因此认定集成 GPU 没有泄漏。

## 4. 共置反向分析与实验范围

图形 shader 通过 Nvidia 扩展读取线程/warp/SM ID 与时钟，把信息编码为输出像素，再由应用读取，检查两项工作的执行时间及 SM 是否重叠。被测资源条件下可在同一 SM 共置；这是具体调度行为的观察，不是所有 GPU 的架构保证。

作者在 Tesla K40/Kepler、GeForce GTX 745/Maxwell 和 Titan V/Volta 检查机制，正文定量结果只报告 GTX 745。环境为 Ubuntu 16.04、驱动 384.11、Chrome 63.0.3239.84；Windows/macOS 的表述主要是机制可访问性核验，不能当作相同完整实验已全部重做。

这些是历史驱动权限与行为。文中提及 CVE-2018-6260 及向厂商披露，不证明当前驱动默认仍开放同一接口；向 AMD/Intel 通报也不等于在其全部 GPU 上完成攻击复现。

## 5. 网站指纹：闭集分类与配置依赖

显存通道对 Alexa 前 200 个网站各采十条轨迹，用分配统计、分段斜率等构造 37 个特征，进行十折交叉验证。随机森林的 precision 为 90.4%、recall 90.0%、F-measure 89.9%；三项不能混称同一个 accuracy。

主实验假设启用 GPU rasterization；默认配置下作者仍报告约 59% precision，但不能拿优化配置结果代表默认浏览器。CUDA spy 的计数器通道报告 200 个网站 precision 93.0%、F-measure 92.7%。

这是已知候选集合内的分类结果，没有给出互联网开放世界、跨长期网页版本、跨设备/驱动和复杂背景噪声的统一检测率。十折划分样本不等于进行了跨环境、跨时间的泛化验证。

## 6. 密码框与按键时间：没有完整恢复任意密码

Facebook 示例中，每次重绘密码框会形成约 1,024 KB 显存变化；空闲时约 600 ms 重绘，按键立即触发重绘。攻击利用分配大小识别框类型，再用事件间隔估计按键时序。

作者以浏览器插桩测得的实际按键时间作对照：250 个样本，平均归一化误差小于 0.1%、标准差 3.1%，折算平均约 6 ms，超过 70% 样本绝对误差低于 4 ms；还展示 25 组键对、每组五次的平均值。

这些结果说明可准确提取时序特征，不等于本篇已完成任意密码字符的端到端恢复。由按键间隔进一步推断内容仍依赖其他模型和先验，文章引用既有研究解释其潜在后果。

## 7. 神经网络参数：特定输入层大小分类

CUDA 受害者是 Rodinia 的 back-propagation；改变输入层神经元数，范围为 64–65,536，每种大小十条样本。spy 连续运行短 kernel，采集自身计数器，提取统计特征，按信息增益选择前 20 项。

最好报告 KNN-3 precision 88.6%、F-measure 86.6%。它识别所选网络的输入层大小，不是恢复任意现代模型的全部拓扑、权重和训练数据；论文也将一般化模型提取作为可能延伸。

不启用 MPS 的交错情形中，作者观察到后续 spy 的 cache/访存计数仍随受害者参数变化，但没有给出同等完整的独立分类性能表。该观察足以提醒“时间片未必清除历史状态”，不足以声称已量化所有时间片 GPU 系统的模型恢复能力。

## 8. 期刊新增：窗口尺寸变化会击穿原分类器

只用全屏数据训练、换窗口尺寸测试时，100 网站随机森林 precision 降至 10% 以下。期刊版先估计窗口尺寸，再使用相应尺寸训练的分类器；测试七种分辨率，从 320×568 到 1920×1080。

窗口尺寸分类表列 precision 约 92%–98%，各尺寸网站分类表约 92%–94%。但后者主要是按尺寸训练/验证的结果；正文未独立给出两级分类错误共同传播后的统一端到端精度。不能直接把每级最好值当作总系统准确率。

这项扩展强调攻击对工作负载环境有依赖，也说明仅靠更换窗口尺寸不是可靠防御。对项目而言，不能把固定 glmark 场景下没有发现观测差异当作所有计算/图形应用无泄漏。

## 9. 缓解实验：降低信号，不是无泄漏证明

作者在前 50 个网站上重新训练并评估限速、降低显存报告粒度及二者组合。每秒两次查询仍保留约 40% precision；粒度降到 8 MB 时约 7%；4 MB 粒度配合限速可降到约 4%。

50 类均匀随机猜测约为 2%，4% 不能自动等于统计上无信息；实验也未覆盖任意先验分布。正文对其他攻击和计数器接口具有类似效果的说法是推测，没有完整逐项防御评估。

文章还讨论未来调度隔离/去相关和 GPUguard，但没有在本篇提供面向所有共享资源的完备隔离实现。其“移除共享 API 可完全缓解”等概括应限制到相应 API 信号；自身计时、竞争和切换残留仍须独立论证。

## 11. 对可信 ProxyRealm 多 Client 的直接启发

第一，区分“自己的资源信息”与“别人的活动”。在既有 RMM 身份、GPUVM/授权映射、认证队列和私有快照基础上，逐项确认 Client 能获得的内存用量、全局空闲池、其他队列深度、利用率、错误和调试统计。按 Client 归属返回信息能减少直接暴露，仍不证明共享压力不可观测。

第二，可信通知真实性与通知时序隐私分开。native fence、cookie/epoch、persistent IRQ127 可以为完成归属与去重提供基础；通知到达时机、等待长度和 reset 广播仍可能暴露其他任务活动。定向投递避免把无关事件直接交给其他 Client，不自动让这些间接时序消失。

第三，明确论文承诺。如果第二部分目标是跨 Client 内存访问隔离与可信完成通信，可以明确侧信道范围而不扩展到全面无泄漏；若选择计数器/资源观测防护为增量，则具体列出受保护观测接口、攻击者能力、保留输出及未覆盖通道。

第四，安全回收不仅可能涉及页表/TLB 和在途 DMA，也可能涉及后续共享者可观测的缓存/调度状态；是否需要清理或分区取决于选定侧信道目标。不能仅援引此论文就断言本平台已有可用的通用 flush，也不必因模拟硬件限制否定研究假设。

## 12. 建议验证义务

可在后续工作中按接口列出允许的观测，检查任何 Client 可见返回值是否包含其他 Client 的身份、对象、完整计数或事件。若再研究间接时序，分别测同时执行、时间片、切换后残留、通知合并和 reset，不将一类场景的结果外推到全部。

这些是后续建议，本轮未执行。项目的可信 ProxyRealm/SMMU 控制、RMM 原始 Client 认证及建图时软件合成直接合法 HPA Stage-1 的假设保持；本文揭示的共享观测边界与地址授权机制互补，不要求改回硬件嵌套 Stage-2。
