## 2. 为什么与本项目相关

PORTAL/CAGE/ACAI主要帮助建立可信服务、设备访问和身份/映射归属边界；SESAME进一步讨论多个互不信任租户同时使用加速器时，片内队列、scratchpad、执行单元和流量观察如何隔离。这不是用加密替代设备授权，而是补充映射之外的共享状态保护。

尤其是dependency queue：恶意租户若能注入或消耗其他租户的依赖token，可能使计算在数据加载前执行，即使每次访存都在合法范围内，也会破坏任务执行语义。本项目需要把共享通知、完成记录和依赖链视为安全状态，不能以SMMU合法访存推导任务完成真实。

论文由可信驱动分配tenant ID、查询资源并装载代码，最终轮询配置寄存器等待结果。它没有提供跨VM中断来源认证、可信vIRQ路由、GPU原生fence绑定或完成重放防护；这些仍应由项目既有RMM身份、private plan、native fence、cookie/epoch及可信通知链联合承担。

## 3. 威胁模型和可信前提

软件定义enclave根据部署选择时间共享/空间共享、私有输入/公开输入、私有模型/公开模型。整机隔离不能成为租户可任意关闭的选项：其他Client的页、队列和控制状态始终需要保护；可配置的是当前授权域内额外的秘密隐藏策略。

平台假定可信制造商、安全启动校验bitstream且运行期禁止重配置；CPU与系统内存有TEE隔离，可信编译器/驱动运行在受保护环境，证明后建立TLS并配置密钥。bitstream哈希只能验证与受信版本一致，“无硬件木马”仍是信任假设，不能从测量值单独推出。

Table 1将系统内存MAC与地址总线隐私作为可组合保护，PoC未实现这两项。不能将本篇表述成已经验证片外完整性、防回滚、防重放及地址轨迹隐藏的完整GPU TEE；电磁、功耗、温度侧信道和恶意租户/管理软件造成的DoS也不在其保护目标内。

论文声称运行期计算非干扰，但没有给出覆盖整个实现的机器检查证明。安全论证依赖可信租户身份、资源配置、编译器、硬件执行和秘密标签正确；合法硬件访问仍不能证明应用算法和输出内容正确。

## 4. 片内隔离与可信控制

空间模式将dependency queue分成四份，以tenant ID路由读写，深度经资源BOM校验；instruction queue也使用私有区域和边界检查。隔离必须同时覆盖token的产生、消费和回收，不能只隔离保存token的某一段内存。

Weight/Input/Output/Accumulator scratchpad按16KB区域维护tenant ownership，scheduler的scratchmap与base/bound在每次访问前检查。Zeroizer在teardown时清除私有数据和区域归属；这与项目实际HPA归属检查层次不同，二者可以共同构成片外/片内边界。

GEMM/ALU空间划分为四个8×8单元，带私有load/store buffer。scheduler维护各租户队列、scratchpad、执行tile占用并与驱动交互；相关状态及配置寄存器写权限均应属于可信控制面，不能允许租户通过自报tenant ID取得别人的资源。

论文报告RTL SystemVerilog测试，以及修改租户二进制访问未授权scratchpad时读写被阻止、teardown后读回零。它们支持具体访问检查和清理路径，不代表已经覆盖并发DMA、迟到回调、reset、取消和所有异常交接。

对项目而言，授权映射建立后，还应明确“停止接收新任务→确定在途任务终态→排空设备访问→撤销旧映射/通知身份→清理剩余秘密→允许新所有者”的交接条件。具体操作次序须满足设备协议和互锁，不能仅按上述文字顺序机械实现；已提交清零或发出中断都不能代替静默证明。

## 5. 编译器、秘密标签与安全优化

`allocate_S`把私有属性传播到中间结果，层边界误标公开会警告，并据活跃区间插入ZEROIZE。LOAD/STORE的E、S、SE变体分别表达加密、整形及二者组合；GEMM_C/ALU_C要求数据无关执行，ZEROIZE与冲突访问建立依赖。

公开模型/私有输入可以不隐藏已公开模型的流量结构，但这依赖实际指令和地址选择不重新依赖私有输入。公开权重不使激活值自动公开；自定义GPU内核、动态分支、别名和间接寻址需要独立的标签/授权规则，不能由规则DNN编译结果自动推广。

Figure 3的公开输入/私有模型路径使用整形的输入加载和输出存储，相关输出是否允许公开取决于应用的解密/公开策略。图中的STORE_S本身不足以证明存在泄漏，也不能据“私有模型”推导所有推理输出必须加密；需明确模型、输入和输出各自的安全主体与允许公开内容。

AutoTVM搜索tile，BOM约束scratchpad、queue和compute资源，再做标签、清零、padding、bank冲突处理和配置生成。但PoC明确在autotuning后手工提取BOM、以命令行传给驱动；不能宣称完整自动安全编译链已被端到端验证。

优化复用同安全等级的私有scratchpad区域，减少不必要的清零。迁移到项目时，“同等级”必须至少包含原始Client身份及有效epoch，不能把两个Client都标为private就认为可以共享旧秘密或跳过交接清理。

安全优化应保留实际归属与任务终态检查，缩短可信路径中的冗余工作。本项目已有GPUVM/BO、私有snapshot、原生fence/cookie/epoch，优先核对这些状态共同维护的条件，不因引入新论文而再建立一套平行身份框架。

## 6. 固定流量整形的能力与边界

每租户真实事务队列配固定计时器，将DMA拆成等长AXI INCR burst；无真实请求时产生fake事务，真实FIFO满则反压。编译器补齐burst长度，安排不跨DRAM row边界及降低bank冲突；驱动装载布局必须与编译结果一致。

`shaper_en`、`tenant_id`、`bandwidth`和`addr_range`为租户私有配置。fake事务限制在该租户映射范围内，以免违反访问控制；项目若采用dummy读写，还需指定合法对象、写入不破坏应用数据的保留区域、权限和撤销生命周期。论文描述不充分不能直接认定已发生dummy写破坏。

固定带宽并不自动隐藏地址、bank可用性、共享控制器排队、整体执行时间或通知频率。正文以用户固定执行时长/模型提供者选择的时间片处理端到端时序；需要把这些边界纳入观察模型，不能只画出执行期间平滑流量就宣称所有侧信道消失。

项目可以先把RMM可见唤醒、跨Client中断次数、共享完成页和调度边界列入观察面，再决定哪些事件必须严格隔离、哪些允许泄露、哪些值得固定批次/时间片。吞掉或合并中断仍须可靠保存真实完成状态，不能改变错误/取消及fence顺序。

## 7. 攻击评估的准确解释

评估在FPGA中加入AXI读写字节计数器，观察六个8bit图像模型：AlexNet、VGG11/16、ResNet18/34/50。Figure 6展示单次轨迹，作者称每模型50次、逐采样点中位数恒定；没有提供足以覆盖任意调度/并发/观察者的统计安全证明。

攻击分为层边界发现和层类型分类。整形后攻击者先关闭终止时序保护离线profile可能的层时长，再枚举候选边界；这是论文采用的攻击模型，不能假定现实攻击者始终能取得同等训练条件，也不能将一次失败当作其他攻击都失败。

Table 3中整形后AlexNet精确率0.03，VGG11为0.01，VGG16 easy/all为0.0027/0.00011；后者是0.011%，并非0.00011%。由FP/TP=1/precision−1复算，分别约32.33、99、369.37、9089.91个误报/真阳性，说明候选定位困难，不表示零泄漏。

ResNet的NA表示在引入超过10000倍误报的条件下仍不能完成论文要求的边界识别，并不表示已证明信息论隐藏。正文称未整形ResNet18 easy边界100% precision，但Table 3为0.69，此处保留冲突，以表格和具体口径为准，不静默修订。

论文对整形后分类效果接近只看执行时长的基线给出定性描述；没有足够数字支持“降为随机猜测”。项目若评估通知侧信道，应同时报告攻击先验、边界可见性、错误率、误报率及允许泄露项，避免只报平滑曲线。

## 9. 对项目设计的具体建议

第一优先是为既有完成路径写明联合不变量：可信原始Client、对象/实际页、访问权限、当前任务与epoch匹配；只有受保护的真实原生任务状态可改变终态；通知仅唤醒检查，错误/取消不发布成功输出；迟到事件不能命中新epoch复用的slot。cookie是标识，不能单独充当认证。

第二优先是将共享控制状态纳入隔离论证：依赖链、命令/完成队列、读写索引、完成页写权限、资源归属、reset generation和回收引用，与页表/根配置/MMIO同样重要。跨VM可信路由只是其中一环，不能替代设备任务语义与授权链。

第三优先是清理/撤销协议：区分任务完成、输出发布、撤销生效、DMA静默及安全复用；明确正常完成、取消、超时、Client退出、设备reset下谁推进状态、哪些证明失效。先利用现有状态机补全条件和失败证据，再考虑额外机制。

流量与通知时序隐藏建议作为明确可选研究目标，在隔离正确后评估。将跨Client安全隔离、秘密内容保护、模型结构隐藏、DoS和应用计算正确性分别定义，既避免承诺未实现目标，也能明确第二大部分“内存与中断/通信隔离”的研究贡献。
