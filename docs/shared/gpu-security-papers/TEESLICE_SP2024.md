## 2. 核心问题：隐藏一部分权重是否足以保护私有知识

既有 TEE-shielded DNN partition 把深层、浅层、重要权重、中间层或非线性留在 TEE，将其余部分放到 GPU。论文质疑：公开预训练模型、外部可见私有权重及少量标签查询能否让攻击者恢复比黑盒更强的代理模型？它研究的是训练知识与暴露参数的关系，不仅是权重文件能否直接读取。

论文回顾 15 项相关系统，其中 5 项不符合其具体比较威胁模型；实际代表性评估为 DarkneTZ、Serdab、Magnitude、SOTER、ShadowNet 五类。不能写成 15 套系统均已被同样攻击击破，也不能忽略各原论文的威胁模型和版本差异。

攻击者控制 TEE 外部环境，知道公开模型/数据，可读暴露权重，并以相对训练集小于 1% 的查询预算取得标签；主设定只返回预测标签。模型窃取使用公开骨干与可见权重初始化代理，再通过 Knockoff 风格查询训练；成员推断采用 ML-Doctor 等框架并从代理转移。侧信道和正常黑盒接口固有泄漏不由 TEE 分割自动消除。

accuracy 衡量代理对真标签的表现；fidelity 衡量代理与目标预测一致；ASR 衡量对抗样本转移；confidence/gradient MIA、generalization gap 和 confidence gap 又是不同指标。不能把其中一个低值概括成所有隐私均得到证明，也不能把 50% 平衡成员推断当作一般机密性指标。

## 3. TEESlice 的训练与部署流程

设计从 partition-after-training 改为 partition-before-training：先确定公开且冻结的骨干，再在私有训练数据上学习较小的私有 slices，所有私有参数和相应非线性留在 TEE，公开骨干的线性算子交给 GPU。其可取原则是从知识来源设计边界，让私有训练增量不混入外部公开部分。

作者借鉴 NetTailor 训练稠密混合网络，再按重要性剪除 slices；slice 连接跨度受限，每个 slice 约比相应完整层小 18 倍，以初始化重要性阈值、逐轮剪除数及约 1% 的相对精度阈值控制开销。该过程是任务相关的启发式训练/剪枝，不是全局最优的最小可信计算证明；若无配置满足精度条件，部署还应有明确拒绝或回退规则。

“冻结公开部分”必须包含权重之外的 BatchNorm 统计、更新状态和其他数据依赖持久状态。若这些状态由私有数据更新后导出，公开骨干的 provenance 论证就需重做。即使权重冻结，激活、形状、调用次数、时间和输出也仍可能泄露，须由各自机制或明确排除项覆盖。

在线公开线性层处理掩码激活；TEE 恢复结果、执行私有 slice/非线性，再继续下一层。它需要频繁 CPU TEE–GPU 往返，因此可信 FLOPs 少不等于墙钟延迟同样小。与完全可信 GPU 的方案相比，这是一种改变模型训练与执行方式的选择，不是透明保护任意已有 GPU 程序。

## 4. 激活掩码、Freivalds 与一次性状态

论文用一次性随机掩码保护交给 GPU 的激活：在相应模域把输入与 r 相加，利用线性映射 g 的性质从返回结果减去预计算 g(r)。私有非线性和 slices 在 TEE 内处理；完整性检查引用 Freivalds 方法。对线性计算的定义、秘密随机量和验证路径，这些方案有明确数学前提。

输入 h 被量化为 8-bit 并选择 p 大于 2^8，只约束输入编码范围，不自动保证乘积/累加无回绕、权重与 bias 编码一致、反量化误差可接受，或浮点近似检查具有有限域定理的漏检界。卷积展开、符号、溢出和容差需要一起规定，不能仅写 OTP 或 Freivalds 就省略这些条件。

离线算好 g(r) 可降低在线开销，但不能无限免费使用。附录中的 meta-review 明确追问长期运行时掩码耗尽；回应建议库存低于 5% 后向云端补充。补充内容需可信生成/认证、与当前模型层和版本绑定、一次性消费；耗尽时必须拒绝或安全补充，不能复用 pad 或接受恶意 Host 自报的新 pad。

Freivalds 的逐次可靠性还取决于随机向量对攻击者保密、与当前映射/权重一致、选择时序正确、数值域明确、重复轮数和总任务错误预算。论文的周期性验证措辞本身不足以保证每个输出在被使用前已验证。验证后的缓冲区若还能被替换，也会失去实际结果绑定。

这些条件可支持完整的协议设计，但不能从算法名称推导 artifact 已实现全部属性。真正的对外发布必须依赖当前验证结果，失败返回应封闭后续执行和输出；“稍后发现”和“防止错误结果发布”具有不同语义。

## 5. 隐私实验与论证的限度

主表支持此前分割在指定公开先验和攻击预算下通常泄露显著可迁移知识，TEESlice 可大幅降低额外泄漏。不过 black-box-level 是相对比较目标，不是差分隐私、不可区分性定理或阻止所有模型提取的承诺。

Table II 的 Ours 平均为 black-box 的 1.23 倍，正文为 1.24；个别结果明显高于黑盒，例如 ResNet18/CIFAR10 为 31.40% 对 19.88%，VGG16/CIFAR10 为 30.87% 对 14.62%。应保留逐任务分布，不写成所有场景均与黑盒完全相同。其他 NoShield 均值在引言、正文和表中分别出现 4.24、4.26、4.28 倍，不能合并成毫无差异的精确值。

论文以 p=0.81 未发现显著窃取表现差异、p=0.75 未发现显著精度差异；未拒绝差异检验的零假设不等于已做带容差界的等效性证明。样本数、统计功效和多任务汇总会影响能识别的差异范围。

附表中 Ours/black-box 的 MIA 准确率均固定为 50%、部分 gap 为 0，作者理由是公开骨干不曾用私有数据训练。但通过目标查询获得的标签、相关训练数据和可迁移统计仍可能携带成员信息，故该理由不能一般性推出精确 50% 或零额外信息。报告应区分实际测得值、指定攻击器能力和由假设填入的边界。

## 6. 对 SOTER 与 ShadowNet 的攻击核对

SOTER 恢复脚本用公开模型权重方差估计私有缩放：取 sqrt(var(W_scaled)/var(W_public)) 后除回，再训练代理。其成立依赖微调前后统计接近和正尺度等条件；不是从任何随机初始化模型都能无误恢复。`membership-inference/train_soter.py` 与 `soter-attack/knockoff/attack/soter_recover_scalar.py` 的相关核心可见这一估计，随机种子和选层也为实验控制的一部分。

这说明“外部参数只差秘密标量”不足以自动达到黑盒级保护，与 SOTER 原文中坐标比和尺度先验问题一致。它不反驳受保护 GPUVM 内不可读私有参数的隔离机制，因为攻击前提是外部确实能读到相关变形权重。

ShadowNet 需要更谨慎。所读附录 F 的变形和恢复描述省略了 ShadowNet v4 标准变换中的乘法因子 λ；artifact 的 `attack_shadownet_layer_nolamb` 也明确采用无 λ 路径，并仅打乱前 n 个私有行、让附加随机行留在尾部。`train_shadownet.py` 实际调用这一函数。

因此论文报告的约 95% 恢复应标明所选无 λ 构造和公开权重统计前提，不能写成完整 ShadowNet v4 的通用攻破。100 倍方差与 0.01 阈值属于经验估计条件，也不是一般有限域下的恢复定理。这一版本差异已与前批 ShadowNet 原文解读交叉核对，没有运行攻击。

## 7. 公开原型：安全目标与性能 PoC 分开

real-device README 继承 Goten 原型说明，明确称 insecure proof-of-concept、用于性能，并声明安全信道/远程证明等未完成。其 enclave XML 的 DisableDebug=0，Makefile 中 SGX_DEBUG 默认值与 enclave 是否允许 debug 是不同设置，不能只看到编译变量为 0 就声称生产 enclave 策略已闭合。

EDL 中存在 user_check 指针和 tensor get/set/host seed 接口。Python `set_seed` 把外部 seed/tag 送入 enclave；C++ 对该 RawSeed 编码并初始化 PRG。某些数据供给接口在性能原型中合理存在，但能否承载私有 pad 取决于实际调用者和秘密来源；仅看到 AES PRG 不能证明种子不被 Host 知道或永不复用。

选定 `real-device/python/layers/sgx_freivalds_conv.py` 在 Host 用 torch.rand 创建向量，包含调试停点 st() 和普通 convolution/tensor 传输路径；某些 enclave-mode 初始化也从 Host 权重开始。未完成实际全部模型的 caller 闭环，故不宣称所有测试都走这一路径，但该文件名称不能证明可信 Freivalds 检查已部署。

`real-device/App/crypto_common.cpp` 的所读活动函数使用公开初始化的全零 key_data，并留有“应从 client 获得密钥”的 TODO；decrypt 在 tag 不符后只打印 invalid mac，接口为 void，另留有“应返回状态”的 TODO。AES-GCM 函数存在，不等于生产密钥供应、失败拒绝和后续使用都安全；未沿全部调用链执行验证，不把它升级成已复现漏洞。

`aes-stream.cpp` 的相应 fused integrity 逻辑可见注释代码，`randpool.hpp` 则调用外部实现；不能把注释中的 Freivalds 字样当作活动检查证据。定向阅读足以记录未闭合证据，不足以断言后继清理版或所有原型目录都缺少相同机制。本轮没有执行代码、下载模型 checkpoint 或安装 SGX/CUDA 依赖。

## 8. 作者性能、精度与指标核算

实机为 i7-8700、GTX1080，SGX SDK2.6、GCC7.5、PyTorch1.7、CUDA11.7；作者报告 10 轮平均、变化不超过 10%。可信计算占比均值约 4.95% FLOPs，对比此前为模型窃取目标选配置的 82.13–95.42%、为成员推断目标选配置的 16.51–68.46%。这些是相应保护配置的计算比例，不是攻击成功概率或 CPU 墙钟占比。

“比其他方案都减少 10 倍”的概括不能覆盖所有配置，例如 16.51/4.95 约 3.34。论文使用 Occlum 三种配置检查 FLOPs 与耗时趋势，也不能证明所有 CCA 平台、模型和共享 GPU 下都保持相同比例。

Table V 中 ResNet18/CIFAR10 从 95.47% 降到 93.65%，为 −1.82 个百分点；CIFAR100 从 79.94% 降到 76.79%，为 −3.15 个百分点。其他任务有升有降，AlexNet 一部分收益来自更大骨干。作者汇总的约 0.34% 平均相对损失不等于逐任务无损，也不能混同百分点。

作者报告吞吐 41.29–85.79 images/s、相对全 SGX 平均 18.37 倍加速。Table VI 中个别倍率与对应数字不符，例如 288.56/7.67 约 37.62 而表列 36.56，58.03/7.67 约 7.57 而表列 6.26。未用不一致单元重新构造一个更精确的全表平均，也不把这些作者数据当作项目复测。

时间分解为传输 35.61%、slices 40.49%、GPU 2.84%、非线性 20.96%，舍入合计 99.90%。这支持继续关注跨边界通信成本，而非仅优化 GPU 计算占比。预计算、训练、pad 库存补充、启动/证明和多租户调度成本需要与在线吞吐分别计量。

BART 实验覆盖 SST2、MRPC、RTE 三项 GLUE 分类任务；它不是自回归 LLM 多请求 serving，也没有建立 KV cache、token 流、动态 LoRA 或多 Realm GPU 并发的安全证据。文中 LoRA 属于未来扩展讨论，不写成已实现结果。

## 9. 与本项目两部分研究的衔接

第一部分 ARM GPU 直通与共享可从本文借鉴跨边界开销拆解、公开/私有处理路径区分及同条件基线方法，不能直接迁移其倍速。第二部分隔离则可借鉴“私有状态来源与合法使用范围一致”的思路；它仍需要 PORTAL/CAGE/ACAI 的设备归属、PhantomMap 的实际页和生命周期、以及可信完成协议支撑。

接受 RMM 认证原始 Client、可信 ProxyRealm 统一控制 SMMU、映射建立时校验对象/HPA/权限/生命周期、GPU 使用合成的受保护 Stage-1、其他设备保留 Stage-2 的项目假设。TEESlice 没有推翻该内存方案，也没有证明任意 GPU 算子结果真实性；不同威胁模型应明确列入 related work，而非因硬件模拟能力否定目标。

对将来的共享公开模型、私有 adapter 或 KV cache，可复用已有 GPUVM、对象归属和认证队列记录私有状态来源及访问范围；公开骨干只有在真正冻结且无私有可变状态时才可按公开对象共享。不能因权重文件公开就允许跨 Client 共享所有中间张量、工作区、缓存和完成记录。这是设计推论，本轮未实现 LLM 扩展。

对中断通信最直接的启示是：唤醒与授权消费分开。继续复用私有提交快照、真实 native fence、cookie/epoch 和持久 IRQ127，让完成记录只由可信 Proxy 按实际任务终态发布；验证、错误、取消、撤销及页复用有各自条件，不通过新增一套身份 token 来掩盖状态机问题。

后续可验证私有 adapter 跨 Client 别名、公开对象被私有更新污染、旧 epoch 结果、验证失败后输出可见、pad 耗尽/重复和服务重启。已有机制是否满足这些性质须逐项看代码和测试，不以本文推论声称现有实现缺陷；本轮仅文献和有限静态阅读。

TEESlice 的主要研究价值是明确暴露权重与私有训练知识之间的联系，并尝试把私有增量先隔离再训练。其经验攻击、理论目标和不安全性能 artifact 的证据等级应分开；对本项目，它是模型层保护与隔离策略的补充，不能代替底层设备任务隔离或可信中断研究。
