## 2. 研究问题与安全边界

固定强度的TEE可能同时保护公开预训练权重、私有微调层和私有输入，造成不必要开销。Triton允许应用声明哪些数据需要加密encr、完整性inte和流量整形shap，并根据时间共享或空间共享配置资源隔离。

论文的三类部署为私有模型/私有输入、私有模型/公开输入、公开模型/私有输入；每类分别比较三种保护组合，共九种策略。它们的安全保证不同，不能把从强策略切到弱策略的收益写成同安全目标下的纯性能优化。

§4描述最强模式：主存秘密被加密认证、counter防重放、流量整形、计算及缓冲分区、重分配前清除秘密。§7给出机制推理而非形式化证明；后面的模拟时延数据不能单独验证这些保证全部成立。

信任链包含安全协处理器/固件、启动验证、证明根、配置加载器、TVM编译器和硬件。作者假设TLS安全通道与TPM证明接口，借鉴ShEF部署；固件验证及协处理器自身侧信道不在本文验证范围内。

§5.3.7说配置随二进制在bootstrapping写入；不能据此声称任意不可信租户可自行关闭其他租户保护。完整部署仍需明确谁能选择策略，以及身份、二进制、配置、密钥和当前会话如何被同一次认证绑定；论文未展开nonce、策略回滚及密钥生命周期协议。

## 3. 编译器与标签传播

扩展TVM API为对象/子矩阵标注encr、inte、shap，并用sec_pragma声明空间共享与完整性粒度，用res_pragma声明带宽、scratchpad和计算资源预算；示例inte_gran为1024B，预算各为0.25。

VTA基础load/store指令增加三个安全标志；译码后选择加密、认证及流量整形模块。compute另有常时标志，但数据驱动优化的评估被作者明确留作未来工作，不能算作已充分验证的常时GPU执行。

Figure 1按输入标签并集传播输出标签；需要不同保护的区间拆成不同kernel。反向传播可把部分区间提升到更强标签后合并kernel，以减少碎片。公开权重与私有输入相乘后的激活不因此公开，输入敏感性必须沿依赖传递。

论文演示算术数据流，未给出覆盖动态索引、别名、条件控制、自定义算子及全部地址依赖的完整规则或证明。应把这些列为证明范围缺口，而非宣称已发现某个实际泄漏漏洞。

机密性和完整性是不同要求：公开模型权重可无需保密，但若攻击者能篡改它们并影响可信输出，完整性仍可能必需。标签取并集本身也不能证明被污染输入产生的结果符合应用语义。

调度先执行公开kernel以预取私有kernel的counter/MAC，再减少私有数据搬运；标签边界、调度顺序及模型结构本身是否公开需要明确。部分模型公开也不自动抵抗模型提取或中间特征反演，需与TEESlice等工作的攻击目标分开讨论。

Listing 1用于说明扩展API，含非标准np.array(start,stop)及简化索引写法；未将其当成可直接运行的完整实现，未执行或修复作者示例。

## 4. 硬件资源与共享生命周期

scratchpad以4KB region追踪tenant ID、valid、读写及secret位；时间共享由当前租户拥有各region，切换时使秘密失效并写零。空间共享静态划分instruction、dependency、request、MAC/counter等缓冲与计算资源，允许一个租户占多个分区但不超卖。

这些规则可作为项目可信资源租约的参考：所有权应覆盖页、队列、计算上下文和遗留事务。invalidate/zero不能单独证明异步工作已经停止；切换前还需说明在途请求何时排空、晚到写入何时被阻断，以及密钥和旧句柄何时失效。

本文未定义GPU fence、跨VM通知认证、reset后的epoch或设备DMA静默证明。保护scratchpad不等于已经解决本项目GPU任务完成与安全回收；不因其模拟硬件而否定机制，但必须保留抽象与项目执行协议的差异。

Table 1时间模式为1租户、128GB/s、256×256计算单元；空间模式每租户32GB/s、64×64、共4租户。scratchpad容量6144/6144/2048KB相对1536/1536/512KB，counter128相对32、MAC64相对16，后几项按4租户求和一致。

独立复算：256×256=65536，而4×64×64=16384，总计算单元仅前者25%。正文未充分解释该资源口径；不能把两模式解释为总计算资源完全相同的四等分实验，也不能据此直接断言作者实现错误。

空间共享评估同时运行四个相同benchmark实例，时间模式按层边界切换；不是不同恶意租户混跑的安全实验。作者也指出大负载可能放不进小分区，选择多个分区会改变并发与性能条件。

## 5. 流量整形的保证范围

shap启用时把访问拆成固定长度事务、固定请求节奏、轮转bank，并采用closed-row策略；缺少真实请求或bank冲突时发fake请求。§5.4.3明确：fake不真正访问memory bank，其响应被忽略；只有请求队列中存在shap=1事务时整形才启动。

因此需要限定攻击者观察面：总线请求是否能区分真假、响应时间、bank内部活动、功耗，以及启动/停止/总执行时间是否可见。固定包长与closed-row不足以独立证明所有这些观察面都不可区分；论文没有给出完整泄漏函数及跨观察面证明。

“按需启用”还要求秘密相关的整形起止不暴露敏感阶段。论文的隔离论证可作为设计假设，不能把模拟器没有建模的共享控制器、功耗或固件路径写成已通过攻击验证；本报告也不据此虚构已复现攻击。

## 6. 评估与独立算术

作者使用TVM、cycle-accurate SCALE-Sim及配置为HBM的Ramulator，AES/MAC以参考时延建模，数据在认证延迟完成后可用。不是已执行密码硬件/固件，也未见篡改MAC、counter溢出或nonce复用攻击实验；可信counter根、持久化和异常恢复需要额外说明。

负载包括AlexNet、ResNet50、FasterRCNN、DLRM、AlphaGoZero、Translate和基础Transformer。包含Transformer不等于已验证现代大规模自回归LLM、KV cache或跨设备训练，论文也未提供本项目glmark数据。

范围冲突保留：引言贡献写时间模式9–64%、空间6–62%；§6.2正文写最强时间62%、空间64%，弱模式9%和6%。不擅自选择其中一版给出统一精确结论；Figure 2仅作可视趋势核对，无原始数据不从柱高恢复精确结果。

摘要“64%→6%开销”相差58个百分点，开销相对减少90.625%；若归一化时延为1.64→1.06，则实际时延下降35.37%。但端点跨保护策略/秘密范围，不能宣传为同等安全保证下90.625%的运行时间提升。

Figure 3公开预训练部分、只保护私有微调层，时间模式全保护开销83%与部分保护7–21%，空间38%与8–15%；公开句子输入。多个柱子同时改变秘密范围或e/i/s策略，应逐条件比较，不把最小端点当最强策略结果。

§6.3.3的ResNet50证件照案例公开尺寸与背景，仅40%像素含私有人脸；不使用shaping但保留加密/完整性。时间开销18%→8%、空间20%→12%，分别减少10和8个百分点；实际时延1.18→1.08下降8.47%、1.20→1.12下降6.67%，不同于55.56%/40%的相对开销下降。

这些案例说明保护范围会影响成本，但秘密分类正确性、应用输出披露策略及公开部分是否被认证都是前提。没有原始测量、置信区间或匹配运行artifact，本报告只核对论文条件与算术，不宣称独立复现。

## 7. 与本项目的对应与建议

以`CURRENT_BASELINE.md`为当前实现入口，保留现有GPUVM/BO、私有plan/snapshot、原生fence/cookie/epoch与通知链。RMM认证原Client、ProxyRealm授权实际HPA并建立受保护直接HPA Stage-1的方案，是本次分析前提；不把研究假设都写成当前已部署证明。

建议分为两层：强制层始终检查Client身份、对象与物理页归属、权限、映射/任务生命周期、可信完成来源和安全回收；可选层才是声明过的流量隐藏、资源预算和应用级保密范围。后者必须由有权主体批准，不能弱化前者的跨Client隔离。

将可选策略与可信Client身份、当前任务plan和会话epoch绑定，避免Host替换成较弱配置或把旧策略套到新任务。若未来增加证明，测量应覆盖策略、编译器/运行时及实际执行配置；不能仅证明固件摘要就推导全部应用标签正确。

中断只用于提醒读取可信状态：由Proxy根据原生终态及cookie/epoch认证完成，并处理丢失、重复、乱序和跨Client通知。Triton没有给出这套协议，不能用其资源分区代替本项目中断通信隔离设计。

回收应区分通知到达、任务终态、输出发布和DMA静默；对reset/取消后的迟到写入与旧fence/旧映射复用维持独立约束。内存归属与中断可信性在安全交接点共同发挥作用，并非两个互不关联的检查表。

部分秘密标签可作为未来应用优化研究，但应先说明静态依赖覆盖与解密/公开权限；不建议为了引入新论文立即给当前通用GPU RPC协议添加未经验证的标签框架。硬件仅用于模拟测试，不将特定板卡缺少功能当成否定架构的理由。
