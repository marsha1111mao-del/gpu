## 2. 要解决什么问题

GPU 编程框架允许弱内存行为，但编译器和运行时必须遵守其承诺的一致性规范。传统测试依赖专家搭建环境、只测少数设备，难以知道结果能否推广到不同编译器、架构和浏览器后端。

GPUHarbor 提供浏览器 WebGPU 和 Android Vulkan 两个入口，将 litmus test、压力调参、执行和结果收集做成较易参与的流程，扩大设备覆盖。它沿用 MC Mutants 的方法，用允许出现的弱行为调优环境，再运行相关的禁止行为测试。

必须区分两件事：**合法弱行为不是漏洞；规范禁止的行为被观察到才构成一致性违规证据**。没有观察到某种行为，也不能推出规范或设备永远禁止它。

## 3. 模型、可信前提与排除项

论文不是恶意 Host 下的 TEE 威胁模型，没有新的安全 Monitor/TCB。测试结论依赖测试定义、生成器、后端编译链、结果统计和设备信息记录；实验会检查行为计数总量，但没有建立对恶意志愿者、恶意数据提交或被篡改浏览器的远程证明体系。

主要考察跨 workgroup、device-wide memory，测试访问使用 atomic，避免把测试主体的数据竞争未定义行为当成规范违规。WebGPU 侧主要测试 relaxed atomics 的 coherence/SC-per-location；Vulkan 也使用相应范围来形成统一比较，不是测试完整 Vulkan 内存模型或全部 acquire/release 组合。

因此本研究不能证明 CPU↔GPU、DMA↔CPU、VM↔VM 共享页、SMMU 更新或中断 MMIO 的内存顺序。迁移测试思路时，必须重新写本项目的参与者、内存属性和同步规则。

## 4. 测试例子与正确性判据

Message Passing：线程 A 先写数据 x=1，再写标志 y=1；线程 B 先读 y，再读 x。若只有 relaxed atomic，B 看到 y=1、x=0 在目标弱模型中可能合法。若协议要求看到标志就能读取数据，必须使用足以建立该语义的同步。

MP-CO 将操作约束到同一原子位置，检查单位置 coherence 是否被破坏，例如同一线程两次读观察到值倒退。它与普通 MP 的判据不同，不能把普通 MP 中允许的结果误报成硬件漏洞。

本项目中的 ready、cookie、序号、门铃和真实 fence 也需要分别定义：哪一个字段是发布点，消费者读它以后可依赖哪些内容。身份认证和内存可见性是两条都需要成立的性质。

## 5. 工具与数据流

JSON 定义每个线程的动作和结果分类；LitGen 生成 WGSL，或先生成 OpenCL 再经 Clspv 转 SPIR-V；WebGPU 以 JavaScript 调度，Android 用 Java/Vulkan 及 EasyVk 包装。测试 shader 与结果汇总 shader 分开，避免汇总本身依赖待测的跨线程同步，并减少逐实例 CPU 回读。

压力参数控制线程分配、内存位置和额外压力工作。先对 mutants 调优，再用最有效配置运行相关 conformance tests。Web 结果通过 REST API 进入 SQLite，Android 当时尚未集成该后端，作者手动导出结果。

随机配置使用相同 Park-Miller seed，使不同设备经历可比较的配置。数据集提供统一条件的部分保障，但不同驱动、浏览器、功耗和系统负载仍会影响结果。

## 6. 测试集合与规模

32 个 mutants 中 24 个属于允许弱行为；主要分析 MP、LB、SB、S、R、2+2W 六类四指令/双线程模式，另有 20 个 conformance tests。四操作模式覆盖特定成对重排，不是任意并发程序或完整协议的穷尽覆盖。

论文共收集 **106 次设备测试记录、确认至少 58 种不同型号、7 个厂商**，不是 106 个不同型号。WebGPU 98 个，Android Vulkan 8 个；各设备记录合计约 3955 亿次实例、3540 万次弱行为。其“比以往规模大至少 10 倍”按论文比较的设备记录数量理解。

Web 98 份数据合计 31.1 小时、平均约 19 分钟；每设备 50 组随机压力配置，Android 150 组。目标让志愿者 10–20 分钟完成，慢设备可能超过 90 分钟。不同实例不是彼此独立的真实机器数量。

## 7. 数据质量及统计边界

测试核对结果总数与预期实例数；浏览器因休眠导致的单测试/配置超过一分钟的时长被过滤，并以邻近测试估计时长。它帮助避免明显休眠污染，但不能使所有吞吐数字都成为直接测得、同条件的时间。

98 份 Web 记录中只有 67 份报告精确型号，31 份只有厂商/架构信息。推测未知设备型号属于基于行为相似度的推断，不能反过来当作已独立确认的型号元数据。

志愿者样本有选择偏差；不同模型的弱行为发生率与压力调优结果有关，不应把厂商平均排序解释为总体产品安全排名。

## 8. 两个新问题和一个未确认问题

| 平台 | 论文观察及响应 | 证据边界 |
| --- | --- | --- |
| Arm Mali-G71 / G78 的 Vulkan | MP-CO coherence 违规；Arm 确认，编译器补 missing fence，并加回归 | 是当时编译链问题，不代表所有 Mali 版本或本项目当前驱动都有同一漏洞 |
| NVIDIA Tegra X1 / Quadro P620 | Vulkan 路径 MP-CO / RR 违规；NVIDIA 定位并修复编译器，作者称影响 pre-Volta | 多型号观察帮助定位同一类问题，不重复包装成多个独立新漏洞 |
| Apple 平台后端 | 8 份 Web 记录有 RR 违规，涵盖 Intel/NVIDIA/AMD GPU | 延续 MC Mutants 报告的问题；论文时未确认/修复，不能称已由 Apple 确认 |

Arm G71、G78 和 Tegra X1 上，允许 MP 弱行为与 MP-CO 违规率在 150 个压力配置中的 PCC 分别为 0.732、0.759、0.832。相关性支持调参方法，但不证明所有未知协议缺陷都有相同触发分布。

## 9. 弱行为分布、聚类和指纹

WebGPU 样本中 AMD 平均弱行为率约 1.5%，Intel 约 0.06%，比值约 25.3 倍。这是合法弱行为频率，不能称“AMD 不安全程度高 25 倍”。同厂商不同代也可能差异很大。

Android 的 Mali-G71/G78 仅 MP 出现弱行为，约 0.04%/1.56%；Adreno610 和 PowerVR 样本未观察到弱行为，Adreno660 的 SB 约 14.37%。零观测既可能来自更强实现，也可能是压力方法未有效触发。

作者用非顺序行为组成向量，计算 cosine similarity，并用 k-means/elbow 选 6 个簇。不同厂商可能同簇，同厂商也可能跨簇；选择测试设备不应只按厂商各取一个。行为还能推断部分被浏览器隐藏的型号，提示 fingerprinting 风险，但本文没有完整评估恶意网站的跟踪能力或识别误差率。

## 10. 锁实验为何与安全有关

作者在 Mali-G78 与 Adreno610 上运行 TAS、TTAS、CAS 锁，分别有/无正确 acquire-release fence；每类 1000 次测试。在 G78，无 fence 版本分别有 18/11/7 次临界区计数错误，正确 fence 版本均未观察错误；Adreno610 两版本均未观察错误。

因此“错误实现也能在某块设备稳定通过”是可见的实验证据。全部 G78 锁测试约 67.9 分钟，Adreno610 约 3.5 分钟，不应将触发率按相同时间解释。论文的无失败不等于形式化证明；它用反例说明仅做常规运行不足。

## 12. 与本项目和 CCA 主线的关系

PORTAL/CAGE/ACAI 讨论谁可以控制设备和访问哪些页；本篇补充“被允许共享的内容何时对接收方可见”的验证方法。它不推翻项目软件授权合成 GPU Stage-1 的假设，也不要求更换模拟硬件。

项目已有认证队列、私有快照、GPUVM、native fence、cookie/epoch 和 IRQ127。应在现有机制上明确：请求内容先于发布序号；消费者获取序号后再读快照；完成内容在通知之前发布；消费者不能在验证 generation 前使用结果；撤销完成记录不能先于实际设备停止访问。

这些是研究目标示例，尚未从当前源码证明各项成立或不成立。CPU 内存模型、跨 VM 映射属性、DMA coherent/noncoherent 路径及 MMIO 屏障应分别建模，不能复制 WGSL atomic 的语义作为 Arm 跨域通信证明。

## 13. 独立评价与可验证建议

优点是把压力调参、统一测试表达和可参与的分发机制结合，并以真实编译器问题和错误锁实现说明价值。局限是小范围 MCS、样本偏差、归档与现行工具版本关系、以及有限负面结果不能证明无错。

建议将共享协议拆为少量有明确 forbidden outcome 的测试：见到 ready 却读到旧描述符；消费新 generation 时接受旧完成；页已重授新 Client 仍被旧事务修改；真实 fence 已记录但结果数据尚不可读。先明确每个反例在项目约定下为何非法，再设计压力和对照实现。

设备覆盖可以参考行为特征与后端差异选择，而非厂商品牌；首要仍是同一实现上的线程/IRQ/恢复交错覆盖。项目不必引入浏览器采集平台，值得复用的是可量化、可重复的压力方法和固定输入记录。
