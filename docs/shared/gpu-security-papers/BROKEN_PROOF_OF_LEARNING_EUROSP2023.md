# Proof-of-Learning is Currently More Broken Than You Think（EuroS&P 2023）精读

## 1. 定位和核心判断

本文重新审视Proof-of-Learning（PoL）的安全假设，给出针对固定数值容差和top-Q选择策略的两种廉价伪造，并区分“无效轨迹骗过验证”与“更便宜地生成有效同终点轨迹”。前者有作者实验支持，后者仍是开放问题。它是GPU训练完整性的支撑文献，不是CCA GPU保护架构，也没有展示对Realm、SMMU或可信中断的突破。

对本项目最直接的启发是：可信方既要认证谁提交了证据，也要控制证据适用的执行规范和接受策略。允许Client自报元数据、选择容易检查的子集，然后以“这些项通过”推导全任务成功，会留下语义缺口。当前项目应继续把设备完成、应用结果正确、通知与安全回收分别定义；无需把PoL默认加入直通和共享数据路径。

## 3. 原始PoL、先前攻击与本文增量

原始PoL保存P=(W,I,H,A)：模型检查点、批次索引、数据摘要与超参数等辅助信息。验证者从某检查点重算k步，允许终点差异δ；为节省计算，每epoch仅选变化最大的Q段。随机初始化以分布检验检查，预训练初态需要来源证据链。论文认为这混合了两种不同职责：判断轨迹是否满足计算规范，以及判断提交者是否比知道最终模型后再造证据者更早/付出更多工作。

Zhang等人的“Adversarial Examples for Proof-of-Learning”通过合成输入试图操纵梯度，部分方案需要二阶优化且未成功收敛；本文指出其有效性依赖较大的k/δ，不能据此覆盖全部PoL配置。输入维数小于梯度维数是可达性直觉，不构成一般不可能性证明；非零损失也不必然意味着非零梯度。本文对先前工作这些解释要与实测失败分开理解。

本文增加三项分析：重算噪声容限是否足够紧；选取子集是否真正能代表完整轨迹；知道最终权重后能否廉价生成完全有效轨迹。贡献在于明确假设、给出两类协议反例及限定实验，而非提供通用安全PoL实现或训练证明不可能定理。

## 4. 威胁模型和攻击条件

攻击者知道最终模型及结构、δ/Q与检查项选择机制，不知道诚实训练的检查点、随机初始化和批次轨迹。基础讨论给攻击者数据访问；两种结构伪造的核心不要求知道原始数据，而重建有效轨迹实验使用原始数据增强攻击者。附录C进一步允许控制优化器内部状态，明确超出基础PoL模型，只作探索。

无穷小更新依赖验证者接受攻击者提交的极小学习率等元数据；blindfold top-Q依赖知道或上界估计Q、允许产生足够大的合法更新，并有剩余未检查区间。不能把这写成对固定Client批准训练规范、任意k/δ/Q或全部更新都重算的普遍成功攻击。正文§3承认已知验证参数，附录D却批评先前工作知道δ不合理，并称本方仅需最终参数，表述存在张力；分析采用更具体的§3和实际策略条件。

在本项目里，认证的Client也可能恶意，但Client不能改变另一Client的执行授权。若审计者需要验证指定训练任务，必须先由授权方固定允许的模型、优化器、学习率、数据和调度规则。仅验证“存在某套自报规则可解释若干检查点”不是同一安全目标。

## 5. 无穷小更新攻击：利用绝对容差

攻击者在随机初态与受害者最终权重之间生成间距很小的检查点，再提交足够小学习率，使验证者每段重算产生的更新也很小。只要伪造更新和重算更新之差低于δ，检查即可通过，尽管二者方向和完整轨迹并不一致。生成主要是权重插值，无需正常训练，也不必求解高维逆梯度。

其几何依据是三角不等式，但“两个向量各小于δ”本身只保证差小于2δ。要保证差小于δ，需明确各自预算之和低于δ；跨全程还要求检查点数量足以连接两端、梯度有限且极小学习率实际可表示。有限精度、Inf/NaN或零梯度边界不能靠η趋零一句话涵盖。

论文声称不必让攻击者控制k，且在全量重算下也可成功；这说明“多抽一些”无法修复宽松的单区间验收语义。另一方面，固定轨迹长度T和容差δ时，若端点距离超过可分配的总跳跃预算，不能任意断言插值可行。实际代码也会在间距超过阈值时要求增大num_steps，不能把抽象“总能构造”直接扩大为所有固定任务条件下保证成功。

## 6. Blindfold top-Q：让验证者检查预先准备的片段

每epoch先计算Q个大的真实SGD区间，然后用较小的插值区间连向下一epoch目标。由于验证器按更新大小排序，前Q个真实区间占据检查名额，余下无效区间可能完全不被验证。本文以Q5评估，Figure5在验证预算不超过攻击者准备的名额时未选中无效区间，增大Q后才出现检测。

这里主要突破的是抽查覆盖，而非单区间数值验证。相对阈值可识别被检查的小伪造区间，但若它们根本未被选中，仍不能修复top-Q遗漏。论文§4.1提“阻断所有当前和过去攻击”的表述，结合附录Figure11应限定为所测数值容差攻击；没有证明只改δ就消除blindfold选择漏洞。

增大Q使攻击者需要准备更多合法段，但没有建立任意固定Q安全。事前承诺后的不可预测随机挑战，可给定坏区间数量时提供概率检测界；它也不能自动获得“验证子集等价于验证全量”的确定性保证。对本项目同理，只抽查某些完成条目或只验证最大BO，不足以给未检查任务或页授权。

## 7. 理论结果：可用直觉与需保留的证明边界

Lemma1/Corollary1讨论在梯度分布绝对连续、接受球边界零测度等条件下，为给定诚实接受率找最小半径；Lemma2考虑给定攻击分布时控制误接受的最大半径。这是受限球形阈值族内的存在性，不表示能够估计未知分布，也不表示对任意自适应攻击最优。有限浮点数实际为离散分布，需要说明连续近似；τ=1且分布无界时未必有有限最小半径，均值存在也需条件。

文中“cosine similarity是metric”的措辞不严谨：标准cosine distance一般不满足三角不等式，零向量也未定义。Lemma1固定诚实梯度均值为球心，而实际重算端点是随机的，应用需处理两次重算差异的联合分布。Lemma2若攻击分布在中心附近已有质量，也不能无条件保证λ=0存在非空可用半径。

Lemma3用相对阈值δ=α×min(norm(g),norm(g′))限制方向与幅度差，优于对所有幅度使用相同绝对容差；α1和缩小100倍学习率的诚实实验显示实用潜力。但零向量、θ0、严格/非严格比较与有限精度必须单独规范。norm(g−g′)本身也受方向影响，不能把原L2检验描述为完全不看方向；问题是固定绝对阈值对小更新过松。

Definition4把“发现任何坏区间时，子集必含至少一个坏区间”定义为代表性，Lemma4据此得到子集与全量验收等价。该结论直接依赖定义，不给出廉价发现这种子集的方法。整条序列总是自身的代表性子集；要求更小且可廉价找到，是额外假设，不是已经证明可实现的算法。

§5将成本C定义为证据上的函数，以c-cheap表示平均成本低于诚实训练的c倍。实际生成成本常取决于算法和硬件，同一证据可由不同算法生成；把成本只定义在证据上时，需说明取最小生成成本或固定生成过程，才能与攻击者运行代价一致。

Lemma5用方差界讨论廉价生成算法输出集中于诚实分布的低概率区域。但印出的证明从C(P)<E1+a跳到以(E−E1+a)为偏差的界，通常应先要求E>E1+a，再用E−E1−a；不能无条件采用原加号分母。仅c-cheap均值条件也不保证有此分离。本轮指出的是可见公式推导边界，不声称已执行攻击或修正整套定理。

Lemma6讨论从诚实分布独立反复采样，找到成本≤cE证据所需查询数的下界；其P=Var(C)/((1−c)²E²)仅在0<P<1等范围内有非平凡对数表达式。这不是对任意利用最终权重的优化算法的查询下界；高概率成功所需预算也不同于“任意运行都必定至少查询这么多次”。

“凸模型必有唯一全局最小值”需要严格凸性等额外条件；普通凸性不保证唯一或有限步精确达到。非凸训练实验未找到同终点廉价轨迹，也不是不存在该类算法的证明。论文将这一点保留为开放问题，比摘要中的绝对措辞更适合作为研究结论。

Figure7把两损失分别归一化后展示相反趋势，只支持所测交替优化的冲突；损失数值不能当原始距离或安全下界。Figure8 RNA距离200epoch后仍非零，显示该候选失败，但200epoch相同不等于加入额外系数优化后计算量相同。

## 9. 固定公开源码：实现覆盖和复现限制

7文件包括README、requirements、`attack.py`、`infinitesimal_update_attack.py`、`blindfold_top_q_attack.py`、`utils.py`、`model.py`。依赖锁torch1.10.0和torchvision0.11.1，其他常用包未锁版本；README仅给两攻击生成命令和外部最终模型路径。完整树没有验证器、诚实训练器、Figure4–13绘图脚本或完整实验数据，不能据此宣称一键复现全文。

**无穷小更新生成器。** 入口加载CIFAR，保存实际随机增强后的data与label数组并插值模型，最后复制受害者模型文件。这比仅记录原始索引更明确，但没有保存学习率、允许训练规范、优化器/调度器状态或签名承诺，也没有在仓库内执行微小学习率重算验证。脚本没有lr参数；论文策略和生成材料不能混称完整协议攻击。

**插值与初始化。** `attack.init_w_0`按最终权重排序索引重排初始值，保留初始值的多重集合，说明KS这类边际检验不能认证独立随机生成；但代码未先排序初始值，不能直接认定它实现了全局最短距离匹配。`sample_w_t.next()`对完整状态做线性插值，却默认按可训练参数计算阈值距离；失败时抛出要求更多num_steps，显示固定长度与阈值并非无条件可满足。

**blindfold生成器。** 使用实际SGD梯度，再按d0/epochs/update_size缩放每步更新，注释视为学习率；默认epochs200、steps200、q5、save_freq10，名义每epoch50个真实步加200个伪造步，即250步。它不是原文每epoch390批默认配置，传参才能另行比较。生成的检查点只保存net，没有每步缩放学习率、数据/标签、优化器状态和认证元数据，尚需独立验证器与完整日志规范。

**最后端点和buffer。** epoch插值先生成w_next，再从真实更新后模型连向它；辅助对象主要往返可训练参数，未统一承诺BatchNorm buffer和完整状态。无穷小入口显式复制最终文件，blindfold没有同样的最后文件复制/逐状态相等断言；不能仅凭插值参数趋向受害者就宣布完整终态逐bit一致。

**数值和接口。** `utils.compute_distance`的cos使用两边范数乘积，已不同于原PoL仓库的单边平方分母；但零向量、NaN/Inf、索引/shape与数值有限性缺少安全服务级验证。`get_parameters`在squeeze且含非训练状态时用加法组合两个tensor，并非一般的拼接；无buffer模型又可能在空列表cat处失败。核心调用多使用默认trainable_only，不能把这些未触发分支当作已实测失败。

`torch.load`及命令行`eval`属于本地研究原型接口，不适合作为恶意远端提交入口；没有安全反序列化schema、配额、Client身份、请求epoch或可信失败结果。源码的有限覆盖不推翻论文协议反例，但限制独立复现与对原型完整性的结论。本轮未加载任何检查点或执行生成器。

## 10. 与CCA GPU项目和文献链的关系

原PoL报告已完成；本文补上系统攻击分析。Optimistic Verifiable Training通过控制非确定性和日志修正支持审计，其完整重算/争议机制不同于PoL的top-Q；它也需绑定完整状态、日志与终态，不能因精确hash一致就省略允许执行规范。LightGuard的抽查/同步同样需要说明抽查覆盖和误差接受依据。上述属于应用计算完整性层，与PORTAL/CAGE/ACAI的设备管理及Realm授权互补。

继续接受RMM认证原始Client、可信ProxyRealm统一控制SMMU、映射期校验对象/实际HPA/权限/生命周期、软件IPA到HPA合成受保护GPU Stage-1的项目假设；其他设备硬件Stage-2与实际页表/根配置/MMIO保护照原设计分析。硬件是实验载体，不用平台模拟限制否定安全协议。

建议从本文吸收“可信策略不能由被验证者替换”：private plan/snapshot冻结对象和执行输入，RMM身份决定会话归属；native fence只对真实设备终态负责，cookie/epoch把终态绑定到原任务，IRQ127只提示查询。若未来增加应用审计，验证策略版本、允许超参数、模型/数据/标签/预处理、完整优化器与随机状态、终态输出摘要应随身份与任务联合绑定。

时间戳、签名、hash和epoch分别解决承诺先后、内容来源、内容固定与旧会话重放；它们不自动证明计算正确。Host延迟通知、Client伪造“审计通过”、旧结果晚到等必须由权威状态机处理。未认证的共享内存字段不能推进任务成功，也不能让已撤销对象重新可访问。

不把top-Q或类似“重要项先查”的启发式用于映射授权、任务身份和回收安全的不变量。每个被授权实际页、对象范围及权限都需可信准入；每个完成条目都需匹配任务。抽样可以评估性能或作为另有概率保证的应用验证，不能替代必须逐对象成立的安全检查。

审计通过不代表GPU停止DMA，审计失败也不能提前释放仍在途BO。保持GPU/验证器引用、同步、撤销、设备停止/复位与清零回收条件；旧epoch的验证结果不能复活取消任务。当前两部分研究结构保持“Arm GPU直通共享与性能”和“GPU任务内存及中断通信隔离”，本篇作为语义边界与可选完整性扩展的依据。
