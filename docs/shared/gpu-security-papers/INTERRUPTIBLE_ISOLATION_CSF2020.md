# CSF 2020：可中断 enclave 的可证明隔离与 GPU 通知设计边界

## 研读结论与材料范围

这篇论文最有用的贡献，是给“允许不可信软件中断可信执行，是否增加攻击者的观察能力”建立明确的参照模型与证明目标。它不负责认证 GPU 完成事件，但能帮助本项目把中断完整性、允许泄漏的时间信息和服务可用性分开定义；即使中断来源和目标都可信，中断到达时间、恢复时间及可中断次数仍可能泄漏受保护执行的内部进展。

论文为 Matteo Busi、Job Noorman、Jo Van Bulck、Letterio Galletta、Pierpaolo Degano、Jan Tobias Mühlberg、Frank Piessens 的 Provably Secure Isolation for Interruptible Enclaved Execution on Small Microprocessors，IEEE CSF 2020，262–276 页，DOI：10.1109/CSF49147.2020.00026。[正式书目](https://doi.org/10.1109/CSF49147.2020.00026)；[实际研读全文](https://arxiv.org/pdf/2001.10881v1)。

## 1. 为什么固定中断入口时延仍然不够

论文先区分原本就存在的时间泄漏与允许中断后新增的泄漏。密码比较的分支若分别执行 18 和 16 cycles，即使没有中断，调用者也可能从总时间区分秘密；本设计不承诺消除这类原有泄漏。

给较短分支补 NOP 可以令两条路径都为 18 cycles，却不能自动抵御中断观察。在条件跳转之后的同一时刻发出 IRQ，当前可能正在执行 4-cycle 的 MOV，也可能是 1-cycle 的 NOP。处理器完成当前指令才进入 handler，IRQ 延迟因而暴露内部路径；相同总运行时间没有隐藏内部指令边界。

只把进入 ISR 的延迟补齐也不够：恢复后的剩余指令时间仍可能是 1 或 4 cycles，攻击者可观察恢复到退出的时间。进一步反复中断，还可把不同路径的指令数量转化为可观察的中断次数。因此要同时约束进入、恢复、重复中断和最后一条指令退出等路径。

这解释了项目为何不能只以“真实硬件 IRQ”“固定 IRQ127”“统一可信 handler”作为全部中断安全论证。它们分别解决部分接入或路由问题，不能单独说明内部调度、完成聚合和通知节奏泄漏了什么。

## 2. 攻击模型与不能省略的前提

形式模型以 Sancus/openMSP430 为背景：16-bit、小型字节寻址内存，单个 enclave、单个物理入口和受保护代码/数据区域。攻击者控制全部非保护代码、非保护数据、ISR 以及确定性 I/O 自动机，能以周期精度安排 IRQ，并观察非保护执行。

基准机器 SancusH 忽略所有中断，包括非保护模式下的中断；扩展机器 SancusL 在保护与非保护执行中都处理受模型约束的中断。它不是把一个已有复杂 OS 的全部异常机制直接形式化，也不含 GPU、DMA、多核并发、cache、推测执行或一般设备队列。

证明假定保护代码不能访问非保护内存，也不能直接执行外部 I/O；保护执行不能改变 GIE；存在待恢复备份时禁止重新进入 enclave。秘密初始内容被视为安全装入，远程证明和密码协议未纳入证明。这些限制是定理的条件，不是可任意删去的实现细节。

论文讨论可使用可信 copy-in/copy-out runtime，或把明确的非保护访问纳入较弱且更贴近应用的参照语义；这些是扩展方向，不是本文已证明的一般共享内存实现。本项目已有认证队列和私有快照，应该说明其输入固定与可见性语义，不能因此直接套用“禁止全部共享内存”的机器模型。

## 3. 双重补齐与中断状态保护

令 r 表示 IRQ 到达后至当前指令结束的剩余时间，Tmax 为最长指令时间，论文中 Tmax=6。进入 handler 前补齐 Tmax−r；恢复保护执行前再补齐 r。前者隐藏 IRQ 命中了多长指令的哪个位置，后者避免把差异移到恢复后的总执行时间。

普通一次完整中断的互补 padding 合计为 Tmax，而非固定增加两倍 Tmax。论文也分别给出每段不超过 6 cycles 的上界；重复 IRQ、恢复阶段新中断和未完成片段需要按状态机分析，不能只用一句“每次各加 6 cycles”替代实际规则。

硬件进入/派发成本为 6 cycles，RETI 为 5 cycles。附录性质将完整中断片段计为额外 11+Tmax=17 cycles，另加 ISR 本身的执行；这不是完整 handler 的 17-cycle 服务上界，也不是 GPU 通知端到端延迟。

进入阶段 padding 期间的中断被忽略，否则攻击者仍可从嵌套观察中恢复剩余时间。handler 期间发生的新请求在边界串联处理，不建立一般嵌套 ISR 模型；恢复 padding 自身则可以被中断，并按受保护指令的规则处理。

如果被打断的最后一条受保护指令本来要跳回非保护模式，也必须正确完成恢复 padding；否则跳出边界会成为额外计时出口。此处的跨边界顺序，比仅检查正常 enclave 内部的 handler 更值得迁移到项目异常路径审查中。

寄存器在中断时保存、清除，在恢复时还原。备份不仅不能被攻击者读取，也不能被 enclave 自己观察：若存到其正常栈或可读内存，程序就可能检测“自己是否曾被中断”，从而产生基准机器中没有的可观察行为。

这是一种针对透明中断语义的强要求。若实际系统有意让可信服务感知中断，应把感知接口作为允许行为写入规范，而非宣称它符合本文完全相同的透明性定理。

## 4. 全抽象性究竟证明什么

核心标准是上下文等价的双向保持：`M ≃H M′ iff M ≃L M′`。在无中断机器上所有攻击上下文都无法区分的两份 enclave，加入受约束的中断后仍应无法区分；反向要求则保证原本可区分的行为没有被实现错误地合并。

上下文等价最终以终止/发散区分定义。它不意味着攻击者只能看见程序是否结束；寄存器、I/O 或时间差可以被上下文转成终止与发散，因此这是一种表达更一般观察能力的形式化方式。

定理保存基准已经允许的泄漏，包括某些端到端运行时间差。它既不是全部程序恒时，也不是消除所有中断侧信道的无条件定理；基准如何定义输入、输出和允许时间观察，会直接影响“安全”这个结论的内容。

双向标准还意味着不能机械地把新增所有隐私增强都解释成与基准等价：若故意隐藏基准可观察的差异，可能需要采用安全保持的一向性质或重新定义参照接口。项目宜先列出允许的完成时间、任务数量和错误可见性，再选择适合的性质。

附录 I 定义字/字节访问、越界及非对齐检查、特殊地址、PC/SP 对齐、GIE 与内存访问约束；附录 II 给出 H/L 机器的完整规则。这里的边界条件支撑证明，不能只引用双重 padding 的图示就认为取得同样保证。

附录 III 用细粒度轨迹记录时间推进、handler/RETI、进入/退出及终止；再以粗粒度轨迹记录入口寄存器、出口寄存器与耗时、终止。物理中断没有被任意假定为不可观察，而是通过规则与证明说明这些额外观察不会增加区分能力。

证明区分保护状态的 P-equivalence 与攻击者状态的 U-equivalence；后者涉及时间、设备和 GIE。性质 III.1 计算指令时间与完整中断片段开销，后续性质对齐 handler 派发、设备推进及片段数量，引理分别处理上下文执行与模块执行。

反向方向可构造不请求中断的对应上下文；安全保持方向通过反向翻译，把 L 中能区分的有限行为转成 H 中的区分上下文。算法 1/2 使用至多约 25-word 的固定代码片段、必要的出口地址，以及为所选有限轨迹构造的足够大的有限状态设备，并非实际部署需要无限硬件。

算法中的终止判定量服务于存在性构造，不能当成能自动决定任意程序安全或终止性的实用检查器。论文给出手写数学证明，未确认匹配的 Coq、Isabelle 或其他机器检查证明 artifact；不把“形式化语义”写成“已机器验证 RTL”。

扩展稿最终定理对两个方向引用的引理编号，与引理本身的陈述方向有对调；III.8 附近的路线描述与实际引理陈述也有记号差异。本报告以陈述及论证内容解释目标，保留编辑问题，不由此宣称定理已被反例推翻或实现存在可利用漏洞。

## 5. 原型结果与性能口径

作者在 Xilinx XC6SLX25 Spartan-6、speed grade −2、ISE 面积优化条件下，比较单模块 Sancus 2.0、64-bit attestation key 配置。基准为 1,239 slice registers / 2,712 LUT；加入 shadow state 后为 1,488 / 2,849；再加入 padding 后为 1,499 / 2,854。

据表重算，总增加 260 registers，即约 20.98%；增加 142 LUT，即约 5.24%。padding 自身相对中间版本只增加 11 registers / 5 LUT，约 0.74% / 0.18%；若用最初基准作分母，则约为 0.89% / 0.18%。这些口径不能混作同一个开销百分比。

特定实现利用已有跳转周期保存/恢复 shadow registers，因此这两步没有另加周期，不代表中断整体成本为零。若改为受保护 RAM 备份，论文讨论每个寄存器再增加一个周期；不能把当前 shadow 实现的时间成本推广到任意实现。

作者报告正常未中断指令路径无需额外执行周期。这个结论依赖小型处理器的既定微结构与定时，不适用于现代 cache、推测执行或 GPU 的不规则延迟；作者也明确指出在此类平台仅做 padding 通常只能成为启发式保护。

本文没有 GPU workload、glmark、多 Client 共享或 CCA 服务的性能数据。上述面积和周期数字均为作者结果及本报告算术复核，不是本项目测量，不据此推算 GPU 吞吐收益或 LLM 延迟。

SPM 模块检查进入受保护区域、入口和秘密区访问，但本轮未建立模型要求的普遍“保护代码不能访问非保护内存/I/O”约束，也未在该模块看到依赖备份状态的完整再入禁令。该模块本身没有备份状态输入，仍需追踪其他层；不得把局部未见等同于全局不存在。

## 7. 与机密计算中断研究的关系

Nemesis 解释攻击者如何利用中断延迟和指令进展；本篇以受限机器模型证明透明中断不应增加区分能力。两者共同提示：只保护寄存器内容不等于保护执行轨迹，时间与次数也是接口。

Aion 关注可信 timer、IVT、有限原子期、准入和调度 WCET 对服务时间保证的作用。本篇允许不可信 handler 不返回，不能推出公平调度、抗 DoS 或 GPU job 的完成上界；机密性证明与可用性保证需要各自前提。

AEX-Notify 在不同 SGX 模型下通过恢复入口等机制限制确定性 single-step，不能与本篇全抽象性混为同一定理。Heckler、WeSee、Sigy 则更接近伪造事件原因、处理器/handler 状态和业务副作用的完整性；padding 不验证这些事件真假。

因此应分别检查四个问题：来源/原因是否真实；目标与任务是否匹配；内部进展是否产生超出策略的观察；通知或恢复是否具有服务保证。任何一个方向的论文都不能自动证明另外三个方向。

## 8. 对本项目可迁移的设计

保持既定前提：RMM 认证原始 Client，可信 ProxyRealm 统一控制 SMMU；建图时检查对象、实际物理页、权限和生命周期，软件 IPA→HPA 合成为受保护的直接 HPA GPU Stage-1；其他设备保留硬件 Stage-2。实际页表、根配置、关键 MMIO、可信固件与撤销后回收的保护继续成立。

本篇不要求本项目额外设计新的硬件 padding，也不否定上述内存方案。它建议补充一份“允许观察与可信副作用”的接口规范：Client/Host 分别能看到哪些提交时间、完成时间、通知次数、批大小、错误类别、队列压力和恢复行为；哪些因设备共享而不可避免，哪些必须隐藏。

首先，以已有认证队列、私有快照和 GPUVM 定义合法请求的参照语义：经过授权且固定的请求，只能访问其授权对象；未通过检查的共享字段变化不能成为实际执行输入。把直接访问共享区、轮询和错误上报列为显式接口，不能从受限 CPU 定理推出它们自动安全。

其次，在已有 native fence、cookie/epoch 和 persistent IRQ127 上明确完成发布规则：硬件/驱动终态要关联原始 Client、GPU 上下文和当前请求；输出可见后才能发布相应终态；重复、过期、目标错误或原因不匹配的通知不能额外授权发布、唤醒错误 Client 或回收资源。这里的语义由项目协议证明，双重 padding 本身不提供它。

再次，折叠 fence、合并 IRQ、批量唤醒与减少往返这些性能优化，应相对同一请求/终态规范审查：可允许通知次数改变，但不能丢失必须交付的终态、混淆不同 epoch，或让错误变成功。哪些批大小与时间差允许被观察，要单独声明，避免把“功能等价”写成“全部侧信道等价”。

恢复与异常路径同样需要参照语义。Client 断开、超时、reset、撤销、晚到 fence 和队列槽复用，不应把旧状态恢复到新请求；成功 ACK、真实 fence 或超时各自能够证明什么应分别定义。回收必须有旧访问已终止的依据，不能因看见一个可信通知就推定全部 DMA 静止。

如果确需增加时序隐私，可先选择粗粒度通知窗口或可公开的批次语义，并评估对延迟与吞吐的影响；它们是待分析方案，不因“加了延迟”就满足本文定理。GPU 的任务时长和并发微结构不支持直接照搬 MSP430 的最大指令时长常数。

建议的验证对象是现有状态转换和异常交错：相同授权请求在多种通知交错下保持同样的合法终态与目标；重复/过期通知没有额外副作用；撤销与复用之间存在明确停止旧访问的顺序。若以后建立模型，应先固定允许泄漏及公平性前提，验证结果也只对模型覆盖范围成立。本轮没有新增测试或声称上述组合性质已经证明。

## 9. 研究价值与当前限制

本篇适合作为项目第二大部分“GPU 任务隔离”中，中断观察与执行连续性的小节依据；Portal/CAGE/ACAI 等支撑设备信任、归属与授权架构，PhantomMap 支撑实际页与生命周期，本篇补充“增加中断接口是否扩大攻击者能力”的问题。它不能替代多 Client 完成认证协议，也不能单独构成本项目新颖性。

最值得落实的增量是把内存授权、任务身份、真实终态、结果发布和安全回收写成同一份有阶段区分的规范，再为时间与次数定义允许观察。已有 cookie/epoch 等字段继续使用；不为引用新论文再叠加重复 token 框架，不把待证义务冒充已发现漏洞。
