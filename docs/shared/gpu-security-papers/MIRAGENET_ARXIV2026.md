## 2. 研究目标及与 CCA 路线的区别

作者关注边缘部署的模型知识产权：模型方希望利用第三方设备GPU计算，但不想将原始权重交给设备拥有者。简单部分权重隐藏会遭权重定位与微调攻击，完整混淆又可能增加开销，于是尝试通过卷积核分解、共享基、诱饵和排列降低开销。

此处TEE保护恢复参数和部分计算，GPU及TEE外部信息均可见。Portal/CAGE则研究如何以可信管理、隔离或任务约束让设备执行进入受保护边界；用户项目的ProxyRealm及映射授权也是这一方向。不能把“GPU在TEE外运行混淆模型”与“GPU任务已获硬件访问隔离”混为一谈。

论文目标含保密、完整性、效率及与cuDNN/TensorRT兼容；但其完整性定义首先是恢复后的forward pass与原始模型在数值容差内一致。诚实GPU上的代数等价不自动涵盖恶意GPU篡改输出、遗漏计算、重放旧结果和错误完成通知。

## 3. 威胁模型与可信基

作者假设TEE完全安全，攻击者不能读取密钥、排列和恢复系数，不能篡改TEE执行；能够观察所有外部权重、激活、中间结果和控制路径，知道架构、公开预训练模型及防御算法，并可获最多10%原始训练数据及进行模型查询，另测1%数据条件。

“最多10%训练数据”是实验威胁条件，不是任意攻击者的能力上界；“maximum capability”也不能当作无限自适应攻击证明。正文还称保护层拓扑，但威胁模型已允许知道架构且外部控制路径可见，需明确仅想隐藏何种额外结构，不能直接宣称全部拓扑机密。

安全目标声称泄漏不足以恢复排列、真实/诱饵身份与系数，达到信息论或计算意义的不足；全文没有与这些措辞对应的完整形式化游戏、归约或所有自适应观察下的泄漏界。所展示主要是有限攻击和相似度统计，结论应保持经验性。

可信基至少包括TEE运行时、密钥/系数供应、恢复、mask生成与管理、必要非线性及跨层对齐；TEE内参数字节数少不等于总TCB少。所读稿件没有明确选择SGX、TrustZone或CCA，也没有给出RMM、SMMU或可信中断实现，不能补造平台架构。

## 4. 离线分解与在线恢复

一般形式把每个卷积核写成 `Wi = Bi + Σk αi,k Pk`，其中Bi为被改写的kernel，Pk为共享patch basis。GPU计算每个Bi和Pk的卷积，TEE按系数组合后恢复，依靠卷积线性保证诚实计算的代数关系。

为了复用，§4.3和算法1采用每层共享系数：`Wi = Bi + S`，`S = Σk αk Pk`。GPU只需计算一次共享基的feature maps，再用于各输出channel；额外卷积规模随基数K增加，而非为每个原始kernel独立计算全部补丁。

算法1还注入fake kernels并排列索引；正文描述对原始kernel线性组合做QR/Gram–Schmidt正交化、谱与统计匹配，另增加channel与kernel排列。需要注意算法1实际写的是同分布随机生成K、共享U(0,1)系数，与正文由原始kernel构造正交基/诱饵的描述并非完整一致；缺源码时不能选一个替作者补全。

输入channel排列要同时作用于kernel与相应输入，§4.4公式8–10展示这种一致重标号可保卷积结果。输出kernel排列σ则是另一轴。不能仅说TEE将输出做π逆排列，就认为Cin和Cout不同、残差连接或跨层对齐均自动正确；算法2的符号和完整协议仍需明确。

在线流程对输入加mask，GPU计算混淆kernel和辅助kernel卷积，将结果送入TEE；TEE组合、减去mask的卷积贡献并恢复排列，之后应用输出mask。非线性、batch normalization、残差和跨层mask/排列如何接续，正文没有与完整模型逐算子对应的协议。

## 5. mask 新鲜性与执行位置仍需明确

§4.5写 `X̃ = X + K`，GPU计算 `Conv(X̃,W)`，TEE减去 `Conv(K,W)`。这种线性等式给出恢复方法；要称为OTP，还需明确数值域、mask分布、独立性、一次使用、熵和浮点误差。实数/浮点的加法噪声不是仅靠“随机”二字就具备有限域OTP的完美保密证明。

算法1先生成global mask m，并预计算M；算法2却对每个输入/mini-batch重新生成m再使用预计算M。若m更新，M必须同步更新或从预计算池一次性消费；若复用m，跨请求差分可能消去mask。稿件未给出pool耗尽、索引归属、失败重试和重放处理，因此不能判定其已经实现新鲜OTP协议。

§3.4说TEE恢复排列/组合，§4.6又称排列和组合是向量化CUDA kernels。GPU不可信时，若秘密排列或系数直接由可见CUDA执行，会改变保密边界；也可能只把公开步骤放在CUDA，但全文没有足够接口细节确认。这里记录描述待澄清，不把猜测当作源码证据。

正文提及sealed metadata和per-layer digest，却没有展示它们如何绑定每次请求、mask、层号、输入与结果，也没有恶意结果检测流程或漏检概率。sealed存储保护与执行时GPU结果认证是两项不同保证。

## 6. 共享分解可见结构：本报告的限定推导

在§4.3明确采用同一共享S的条件下，若两份真实damaged kernels为Bi与Bj，则 `Bi − Bj = Wi − Wj`。共同input-channel排列会将右侧一并排列，但不会隐藏全部差分结构，且保持欧氏范数、内积和距离；输出kernel排列只重排该组关系。

因此，“所有权重均被改写”和“同位置cosine下降”不足以推出所有模型结构信息都被隐藏。可考虑对差分距离矩阵、中心化kernel、排列不变量以及多版本/多会话关系进行专门评估。这个等式是对共享系数子方案的代数观察，不是本文已执行的攻击或完整权重恢复证明。

推导也有明确前提：攻击者仍需区分真实damaged kernels与诱饵、解决排列及剩余公共偏移；一般的逐输出不同系数αi,k版本不能直接套同一消项。不能将这条限定观察夸大为全方案已攻破，也不能忽略算法/正文分歧而断言部署必然使用某一版本。

论文关于cosine热图条纹、低阶统计匹配、Gini和off-diagonal energy的结果，只覆盖所选统计及攻击。匹配norm、variance、kurtosis不等于所有联合分布不可区分；TEE保护恢复参数也不自动证明GPU可见关系不泄漏模型信息。

## 7. 结果完整性不能由恢复准确率推出

按所述线性恢复，如果GPU将某个damaged卷积输出改为原值加Δ，而其他值保持不变，则TEE恢复值也对应改变Δ；代数恢复不会自行拒绝。全文未展示可识别该类主动篡改的验证器，即使诚实计算时所有Top-1准确率都一致，也不能推出对恶意计算的完整性。

这项分析针对公开描述中的机制缺项，没有源码执行或漏洞复现。若完整系统实际存在额外认证或计算验证，需要给出对应证据。Slalom等研究将隐私和验证分开设计，不能因为同属TEE–GPU外包而默认继承其验证能力。

对本项目，native fence能表明受信任设备栈报告任务终态；其能否支撑结果正确性仍依赖可信固件、受保护命令/输入和GPU硬件等既定假设。若将GPU自身也视为任意恶意计算者，单靠fence同样不成为数学计算证明，需额外验证或缩小安全目标。

## 8. 作者报告的安全和准确率结果

方法章节列CIFAR-10/100、SVHN，AlexNet、ResNet18/50、VGG16_BN；攻击包括knockoff、cosine对齐、统计检测和1–10%数据微调。表2仅给跨任务ASR/blackbox汇总：未保护2.60、Magnitude2.44、Soter2.25、ShadowNet1.95、GroupCover1.14、ConvShatter0.56。

0.56表示作者选定攻击结果相对blackbox基准的比例，不是所有攻击者的最优上界。若攻击者拥有与blackbox基准相同的查询能力，它可以忽略外部混淆权重改跑blackbox攻击；因此不能将“低于blackbox”解释为阻止其达到相同blackbox基线的无条件保证。这里的困难是攻击公平性/最优性解释，未执行重测。

正文称趋于random guessing，10类为10%、100类为1%；但只有相对比例不足以确认每项绝对ASR确在随机水平，表2没有逐模型/数据集攻击准确率。图5测试500至30000查询预算，图注不替代完整数值、置信区间、攻击调参和重复实验。

表3列12组原始/恢复Top-1完全相同，平均loss为0；例如ResNet18在C10为95.30/95.30、C100为80.00/80.00，VGG16_BN在C10为92.70/92.70。相同分类准确率可支持所测诚实执行的效用保持，不能证明逐元素完全相等、所有架构通用或主动攻击完整性。

正文还报告K取4–16、保护25–33%层、诱饵10–25%，以及cosine对角Gini下降45–60%、非对角能量升30–50%。这些为作者汇总，所读稿件没有给出相应完整逐条件实验表，不作为独立复核通过的数据或项目参数建议。

## 11. 与当前设计的关系和可取内容

用户项目目标仍是RMM认证Client、可信ProxyRealm统一管理设备，建图校验对象/实际HPA/权限/生命周期并合成GPU Stage-1；平台保护页表、根配置、MMIO与可信固件，其他设备保留Stage-2。本论文不能替代这条身份及内存授权链，也未讨论可信设备IRQ与多Client回收协议。

可借鉴的是区分离线准备和在线热点、共享可重用计算、减少跨边界传输；但模型改变、预计算项和复用key仍需Client/对象/版本归属。GPUVM、认证队列、private plan/snapshot、native fence、cookie/epoch和IRQ127可继续作为项目已有机制，不因读到mask/metadata就新增第二套身份框架。

若未来增加模型服务层，需分别定义模型方机密、用户输入机密、跨Client硬件隔离、实际执行终态和恶意计算结果正确性。mask/precompute还应在提交、重试、cancel、reset和撤销时保持一次使用及归属；这属于未来扩展要求，不声称项目已经存在这套模型混淆实现。

对论文主线的建议是将这篇放入“替代信任路线与边界比较”，优先度低于Portal、CAGE、ACAI、Devlore、PhantomMap和MOLE。它提醒我们不能将效用不变或统计攻击下降代替完整隔离与通信安全证明，而不是要求项目引入未充分论证的kernel混淆。
