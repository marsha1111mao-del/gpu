## 2. 研究问题与安全目标

论文关注模型部署到用户边缘设备后，恶意用户、应用或被攻陷的 REE 能否利用模型内部激活、梯度、损失及输出推断训练成员。其问题区别于服务端 TEE 保护用户输入：边缘设备的用户可能正是模型提供者希望限制的对手。

威胁模型给予攻击者完整 REE 访问权，只信任 TEE 中的软件和数据。模型预训练及敏感层供应假设安全；硬件/固件和 TEE 软件构成相应可信基。其经验主目标是降低指定白盒 membership inference attack 的效果，不等于任意模型提取、任意输入隐私或设备任务隔离的形式化保证。

原文以 Nasr 等人的白盒 MIA 为依据，强调末端层携带较强成员信号，并对保护前层与后层做资源及攻击效果比较。它的贡献是 Arm TrustZone 上的分割原型和逐层测量，不是扩展 CCA、管理 SMMU 或建立可信 GPU 中断。

## 3. 架构、供应与在线流程

模型被划为 REE 中 CA 执行的前缀与 TEE 中 TA 执行的敏感后缀。论文描述 CA 构建网络、读取外部参数；遇到敏感加密层交给 TA，用安全存储中的密钥解密并驻留安全内存。在线先在 REE 计算前缀，通过共享缓冲区传入激活，TA 计算后缀，再按策略处理预测输出。

fine-tuning 还包括向 TA 提供标签、计算损失、反向传播边界梯度和更新参数，最后加密受保护层交给 CA 保存。因此推理、训练、保存和输出并非同一种权限；私有后缀不外露也不意味着所有导出接口天然安全。

论文建议 OEM 预置或远程供应模型，并把带远程证明的 SIGMA 变体列为可扩展方案；不能据此写成 artifact 已实现完整在线证明与秘密供应。PFS 主要保护历史会话密钥泄露后的安全，抗重放仍需协议的新鲜性和状态检查，不能只引用 PFS 这一性质。

模型存储的认证加密还需绑定模型标识、层位置、形状、版本及必要的防回滚状态。合法旧密文、层交换与新模型授权是不同问题；初始 TEE 隔离不能独自解决这些生命周期条件。论文正文称实现 AES-GCM，公开后续代码的实际路径另见下文。

## 4. 输出保护到底隐藏了什么

原文把 cost 和 softmax 作为敏感末端处理，保护一个“最后层”的实验分组可同时包含这两部分；不能把这一配置描述为已经隐藏所有分类权重。普通 fully-connected 分类层是否进入 TA 必须按实际分割点区分。

隐藏输出与隐藏输出的可推导来源也不同。如果不可信前缀已产生完整 logits，而后续只有已知的标准 softmax，那么攻击者可以从 logits 重算置信度；只限制正常返回 API 并不消除可重算信息。这是针对明确配置的数学条件分析，不是本轮执行的攻击，也不宣称所有分割点都有同样问题。

fine-tuning 会向外部前缀传回梯度，攻击者还能选择输入与标签。即使原生预测 API 仅返回 top-1，其他操作的可观测信息也必须纳入同一隐私边界。TEE 并不自动阻止正常授权查询造成的 label-only、统计或自适应泄漏。

保留原模型计算、不加噪声有助于维持预测精度，但不能因此认定它与差分隐私具有相同的安全目标。DP 约束相邻训练集下的分布差异，本文的主要依据是指定攻击器的经验效果；二者不能仅按精度和开销相互替代。

## 5. 公开 CA–TA 接口的定向核查

README 演示用 `-pp_start` / `-pp_end` 在 TA 中放入首、中、末任意连续层，既支持训练也支持推理。Host `forward_network` 按分割点进入 TA，若 TA 后面还有 REE 层，则用 `FORWARD_BACK_CMD` 取回原始边界张量；正常末端预测则使用 `OUTPUT_RETURN_CMD`。

`OUTPUT_RETURN_CMD` 的 TA handler 默认移除置信度，选择最大值后输出 one-hot；但 `FORWARD_BACK_CMD` 的 handler 直接复制 TA 最后一层的 output。两个命令均在同一公开分发表内，未见按模型策略或 inference-only 模式限制原始导出。前端通常不调用某条命令，不等于控制 REE 的对手不能请求它。

同时存在 `SAVE_WEI_CMD`、权重导入、训练更新、标签设置和反向导出等能力。实际 deployment 是否允许这些命令，应该由可信实例策略决定。这里记录静态可达的接口与缺少策略证据，没有运行恶意命令序列、认定所有部署均可绕过，或把它升级为新 CVE。

CA 用 TEEC_LOGIN_PUBLIC 开会话，TA 开会话仅检查参数类型，未使用 `sess_ctx` 建立模型持有者或角色策略。TA 配置注明 multi-instance，状态则使用实例全局变量；不能据全局变量直接断言不同会话共享模型。OP-TEE 实例生命周期与应用级授权是两件事。

所读多个 handler 在检查参数类型后直接按固定索引读整数数组，或按调用者长度复制数据、选择层号；`netta.input` 直接指向传入 memref，工作区命令也接受外部指针。参数类型正确不证明尺寸、范围、初始化顺序或读取期间内容不变。本轮没有完成整个依赖栈的参数封送审计或 fuzzing，不据局部阅读宣称所有共享访问都能攻击。

README 说明仿真用途下禁用层进出 TEE 的加解密；但所选提交的 TA parser 仍调用 AES-CBC，并在 helper 中设置固定公开测试 key 和 IV。正文 AES-GCM、README 说明与当前源代码不是同一证据。该 CBC 路径也未展示 tag、AAD、远程供应密钥或版本保护，不能作为论文安全存储协议的完整实现证据。

TA 配置为 1MiB stack 和 10MiB data，README 指向 OP-TEE 通用构建和另一数据仓库，没有固定完整系统 manifest。Host Makefile 未启用 GPU 宏；network 源码虽保留通用 GPU 分支，也不能据此声称实现了 GPU–TEE 分割安全执行。未下载或运行数据/模型、刷写设备或构建模拟器。

## 6. 性能评估：条件与指标

作者实机为 HiKey960：4 个 Cortex-A73、4 个 Cortex-A53、4GB RAM；固定 A73 为 903MHz、A53 为 533MHz，每轮前冷却 120 秒至低于 40°C。16MiB 安全内存中 14MiB 给 TA、2MiB 给 TEE runtime，另有 2MiB 非安全共享内存。这是该原型环境，不是本项目目标架构的硬限制。

CPU 时间区分用户态、内核态，作者把 REE 内核和 TEE 执行共同计入内核时间。RSS 不含 TEE 内存；TA 映射通过稳定运行后触发 abort 获取，报告固定 11408KiB 映射。映射预留大小不等于每个配置的实际活跃张量/峰值内存，也不能把 REE RSS 下降直接写成总体内存节省。

Monsoon 以 12V、50Hz 测整板功率；功率单位 W，不等于每推理能量 J。性能试验每配置 20 次、95% CI，MIA 每配置 5 次、95% CI。MIA 在另一个 Xeon/Quadro RTX6000/PyTorch1.0.1 平台运行，不能混成 HiKey 的 GPU 推理性能。

小模型为 AlexNet 和 VGG-7，在 CIFAR100 / Tiny ImageNet 上做训练和推理；另测六个预训练 ImageNet 模型，大小约 4–159MB，仅保护最后层。该处论文使用的 AlexNet/VGG-7 实例结构需按文中定义理解，不直接按其他实现的同名模型参数量比较。

末端保护约 3% 开销的摘要结论不能覆盖所有分割配置。§5.1 对充分利用 TEE 的训练报告约 10% CPU 时间增加，却对一次性多层推理写到最高约 10 倍；§5.1/5.3 将其与创建 TA、首次分配和加载联系，并建议预加载。报告分别保留冷启动、持续推理和训练条件，不把摘要的 10% 作为所有场景上限。

六个较大 ImageNet 模型仅末端保护时，作者报告 CPU 时间、RSS、功率变化均小于 2%；模型越大，相对附加开销可能越小。该结果既不是全模型隔离，也不是 GPU 加速相对基线。论文明确当前实现只使用 CPU，安全总线访问 GPU/NPU 仅为后续方向。

## 7. MIA 结果与证据强度

| 数据集 / 模型 | 训练 / 测试准确率 | 无防御 MIA precision | DarkneTZ precision |
| --- | --- | --- | --- |
| CIFAR100 / AlexNet | 97.0% / 43.9% | 84.7% | 51.1% |
| CIFAR100 / VGG-7 | 83.8% / 62.7% | 71.5% | 50.5% |
| CIFAR100 / ResNet | 99.6% / 72.4% | 88.3% | 50.6% |
| Tiny ImageNet / AlexNet | 40.3% / 31.5% | 56.7% | 50.0% |
| Tiny ImageNet / VGG-7 | 57.1% / 48.6% | 54.2% | 50.8% |
| Tiny ImageNet / ResNet110 | 62.1% / 54.2% | 54.6% | 50.2% |

Table1 的 CIFAR ResNet 行标为 ResNet-100，而实验设置写 ResNet-110，故表中用 ResNet 保留差异，不补造另一已测架构。训练攻击器时成员/非成员数量不平衡，测试又采用相等的 5000/5000；precision、recall、accuracy 和攻击 advantage 不是一个指标。precision 接近 50% 需与 recall、基准率和测试分布一起解释，不能写成任意先验下只能随机猜测。

正文关于输出策略的描述与 Figure8 图例不完全一致：正文列若干带置信度输出，图例则包含 all classes with scores、top-1 with scores、top-5 ranks 和 all ranks。没有匹配的 MIA 原始训练脚本/数据闭环，不能据它推出“无论返回什么分数都同等安全”。

TEESlice 后续利用公开预训练骨干、可见权重及少量查询训练代理，再做窃取和成员推断，扩展了直接使用剩余激活/梯度的威胁设定。两组结果应按攻击者知识、模型和查询预算比较；后续攻击效果不等于同一个实验被推翻，早期 precision 结果也不等于对后续攻击模型的证明。

## 8. 与 CCA GPU 项目的关系和后续设计

DarkneTZ 是 Arm TrustZone 模型分割与输出策略的 related work，PORTAL/CAGE/ACAI 则建立设备访问与可信执行域边界。项目接受 RMM 认证原始 Client、可信 ProxyRealm 控制 SMMU、映射时核验对象/HPA/权限/生命周期并合成 GPU Stage-1、其他设备保留 Stage-2 的假设；不因本文旧平台资源否定这些目标。

最直接的设计启示是把模型、对象或设备的“允许操作集合”落实在可信入口。复用现有认证队列和对象归属，检查每条导出、更新、reset、取消和完成操作的合法角色与状态；不能依赖 Client 驱动不会调用危险命令。已有政策是否覆盖相应入口要按代码验证，本报告不凭类比断言项目缺陷。

私有提交快照、GPUVM、真实 native fence、cookie/epoch 与持久 IRQ127 继续复用。预测 API 正常返回和 GPU 任务真实终态应分别论证；调试、统计、错误处理和旧完成路径不能另有可绕过的发布规则。若将来提供私有模型服务，还需说明哪些推导性信息在授权接口外可见，而不是简单增加 top-1 过滤。

后续可验证 inference-only 对象是否拒绝训练/权重导出、原始输出旁路、可见 logits 的策略一致性、共享输入检查与使用不一致、旧模型保存/恢复及跨 epoch 完成。测试应复用原有身份和状态，不新设一套重复 token；本轮只提出研究和测试条件，未实现或执行。
