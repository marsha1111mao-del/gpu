## 2. 问题、角色与威胁模型

模型提供者希望向不受信任的边缘机器交付推理能力，同时隐藏私有参数并发现外部计算篡改。将整个模型放入 SGX CPU enclave 会丢失 GPU 加速；直接把模型交给普通 GPU 则暴露参数和中间状态。SOTER 尝试用细粒度算子分割、参数变形和挑战指纹折中。

模型提供者、SGX 硬件/固件及所选 enclave 软件可信，外部 OS、驱动、GPU 执行和通信可被攻击者观察或操纵。Graphene、模型处理和协议实现也属于相应 TCB，不能把 SGX 本身的隔离能力当作这些软件逻辑正确的证明。正常查询输出导致的黑盒泄漏和侧信道在其边界之外。

论文里的 client 是部署和推理参与方，不等于本项目经 RMM 认证的原始 Client Realm。它没有建立恶意多 Realm 的 GPUVM 所有权、SMMU 归属和中断路由协议，也不应被归为另一套 CCA GPU 直通架构。

## 3. MTR 参数变形与执行流程

提供者按分割比例 θ 随机选择可变形算子，在可信环境产生缩放因子 µ，并将 GPU 部分参数变为 µW；保留一部分算子和靠前的 top-W 处理在 enclave。默认 θ=0.8、W=2。θ 指算子选择比例或概率，不是 GPU 承担 80% FLOPs、80% 权重或 80% 执行时间。

在线输入先进入 enclave，执行保留部分；中间结果交给 GPU 的连续算子组，返回后在 enclave 用相关缩放因子的倒数恢复；跨越下一段可信算子后再次调整尺度并继续，最终规范化和返回预测。连续分段的尺度传播、含偏置算子的处理和每种非线性的适用条件决定数值正确性。

对正尺度 a，ReLU 和 max-pool 可满足正齐次性，例如 ReLU(ax)=aReLU(x)。这要求尺度符号和具体算子满足条件；一般 affine 层还须说明 bias 的对应变换。不能把某个缩放恒等式推广为所有算子、任意系数或任意数值域都成立。

参数乘一个未知标量仍保留零坐标、非零坐标比和归一化方向，因而不是语义安全的参数加密。论文引用 Hill cipher 推导一个 coin 可安全使用的查询次数，但一般矩阵密钥的未知量论证不能直接证明单标量变形的安全预算；还需定义攻击者先验、公开预训练模型、查询可见性和要隐藏的属性。

论文的小型模型窃取实验能说明指定代理模型和训练预算下的经验表现，不能证明任意恶意推理请求都只能获得黑盒能力。TEESlice 后续使用公开预训练权重统计估计尺度，恰好补充这里未充分覆盖的攻击者先验；后续实验也有自己的模型与数据假设。

## 4. 指纹设计及数学适用范围

论文设计先在 enclave 中为每个卸载算子产生 K 个可信输入/输出 cornerstone，默认 K=10。在线随机选择若干 cornerstone 和随机系数，用输入线性组合构造新挑战，并用相同系数组合已知输出；GPU 返回的挑战结果与 enclave 的期望值比较。每个用户推理的跨边界位置都发挑战，避免仅偶尔抽查。

这一步需要可加性，强于参数恢复所用的标量齐次性。明确反例：ReLU(1+(-1))=0，而 ReLU(1)+ReLU(-1)=1。即使使用正的组合系数，输入仍可能跨越非线性分区。对含 bias 的 affine 映射，输出组合也一般多出与系数和相关的偏置项。论文 Equation 2 到 §4.2 的推广必须按实际被检查算子组重新约束，不能仅以“associativity”一词完成证明。

对纯线性算子，组合指纹具有正确性依据；对固定激活分区内的算子组也可能在附加条件下成立，但需证明输入始终满足这些条件。报告没有据此宣称所有实验均错误，而是指出论文的通用论证不足以覆盖其声称的所有非线性算子。

挑战是否可辨识还取决于攻击者看到的完整序列、调用顺序、张量形状、时机和输入分布。两类样本具有相似的 L2 距离直方图，不等于完整联合视图不可区分。若攻击者能学习有限 cornerstone 形成的低维空间且真实输入不局限其中，也可能获得判别信息；这是一项有条件的分析，不是本轮执行的攻击。

独立挑战正确，不自动认证旁边那次真实推理的返回张量。若攻击者能够区分两者，就可只对挑战诚实；即便不能区分，也需明确作弊成功概率、重复挑战的独立性和验证前是否已有输出。可信预计算、挑战秘密性、实际结果绑定和失败阻断是不同条件。

作者称以 99.9% 概率在 10 次挑战内发现篡改。§6.4 的经验依据是 10000 次随机参数扰动及检测统计，报告零误报；它不能直接等同任意恶意 GPU 对每次推理结果的密码学 soundness。经过若干任务后发现故障，也不能倒推出此前错误结果未被消费。

## 5. 公开 VGG 路径与论文协议的差异

所选 GPU server 的两个分段在 `morphpara` 中直接使用公开常量 scalar=4，TEE client 也按相应常量恢复；变形发生在不可信服务侧。该路径没有呈现模型提供者秘密随机 coin 的供应协议。模型在主路径随机初始化、输入由 torch::rand 产生并重复用于计时，未见读入已训练 checkpoint，不能据它验证训练模型隐私。

论文要求 cornerstone 的参考输出在 enclave 内可信计算；所读 TEE client 的准备阶段却通过 GPU RPC 取得并存储相应输出。这样预处理的真实性依赖外部服务诚实，与论文默认的可信 ground truth 不同。不能把外部回复缓存后称为可信参考答案。

该路径以固定系数产生三个派生指纹；在线 `srand(time(NULL))` 后 `rand()%2+1` 仅在前两个中选择，不是论文描述的 SGX 可信随机数每次产生新组合。真实结果 RPC 后固定发送一次挑战 RPC，二者未隐藏混排，也未建立请求、Client、模型版本和 epoch 的认证绑定。

`integrity_check` 及小张量变体仅比较一个索引元素，按代码中的两位小数舍入表达式判断；不匹配只打印 Detect breaches，没有向调用者返回失败或阻止使用。主函数仍无条件打印 Completed successfully。这个 selected path 不能作为完整张量验证或失败即拒绝的实现证据。

gRPC 使用 InsecureChannelCredentials / InsecureServerCredentials，server 直接按 request tag 选择模型分段。非安全传输本身不必然破坏一个正确的可验证计算协议；但本路径没有展示多 Client 鉴权、challenge 不可辨识和实际结果绑定的闭环。这里只报告静态事实，不声称已经复现生产攻击或覆盖所有目录版本。

图 8a/8b 的所读 histogram 生成器使用固定 `checkpattern_indexlist` 重复写入距离值；先按维度除以常量、取 floor，再把少量成对距离展开为输出样本。它们没有实现对完整正常查询/挑战视图的通用分类器评估。README 建议重复生成以得到正常形状，也不增加统计证明力度。

`script/check.py` 负责读取或补跑延迟数据并绘图，不是协议完整性验证器。Graphene manifest 开启 insecure argv、指定 4GB enclave 和 16 线程，区分 trusted files 与 allowed files；这些部署设置还需结合真正入口和输入验证评估。论文描述共享内存/pickle 及共置 GPU，artifact 的部署说明则采用两机 gRPC；不能混成同一端到端测量。

## 6. 作者评估及数值核对

论文平台报告 E3-1280 v6 CPU 2.60GHz、64GB RAM、SGX 与 RTX 2080Ti 11GB，评估 MLP、AlexNet、VGG19、ResNet152、DenseNet121、Transformer，默认 batch=1、每项 10000 次输入取平均。artifact 的所选演示循环为 1000 次。CPU 型号/频率按作者报告保留，未现场核验。

作者相对全 CPU TEE 报告 1.21–4.29 倍加速，相对 AegisDNN 报告 1.03–1.27 倍延迟。全 enclave、无检查分割及带检查方案的安全目标不同，不能把这些倍率当成同等安全条件下的全部性能优劣。1.84–2.92 秒的预处理/bootstrap 不计入在线推理延迟。

## 7. 与 CCA GPU 主线及本项目的关系

PORTAL/CAGE/ACAI 主要控制真实设备与可信执行域之间的访问权；SOTER 则在不信任 GPU 时尝试通过变形和验证外包计算。它可作为替代信任模型的 related work，不能直接替代 RMM 身份认证、ProxyRealm 授权或设备执行隔离，也不提供可信虚拟中断方案。

接受项目的既定平台假设：ProxyRealm 统一控制 SMMU，按原始 Client 核验对象、实际 HPA、权限和生命周期，将 IPA→HPA 软件翻译合成为受保护的 GPU Stage-1 映射；其他设备继续硬件 Stage-2。本文不因 RK3588 模拟方式否定这些目标假设，也不建议为了套用 SOTER 再加入一套重复身份或 token 框架。

可以直接吸收的是“验证对象必须等于实际使用对象”和“失败必须阻断副作用”。在已有认证队列、GPUVM、私有快照、native fence、cookie/epoch 与持久 IRQ127 上，可信 Proxy 应只对已绑定任务的真实终态发布完成；Client 唤醒后从受保护完成记录取证，不能把通知次数或共享 success 字段当作结果真实性。

真实 fence、可读取的结果和可安全复用的页也须分别论证。错误、取消和 reset 不能借一次可信通知伪装成任务成功；旧 epoch 的完成不能落入新 slot；撤销后需满足设备静止、翻译失效及安全清理条件。SOTER 的检查机制没有解决这些设备生命周期问题，但它暴露了“检测”和“授权消费”容易脱节的通用风险。

## 8. 可验证的研究建议与独立评价

建议继续完善现有任务状态机的不变量：只有绑定原 Client、GPUVM、请求快照和当前 epoch 的真实 fence 能使任务进入对应终态；只有合法成功终态允许发布成功结果；错误/取消单独报告；内存回收还必须经过相应访问撤销与静止条件。这是复用已有机制的组合验证，不代表本轮发现现有实现缺失这些检查。

后续可在授权测试中覆盖伪造唤醒、重复通知、完成/取消竞态、reset 后旧完成、返回张量与提交快照不一致、验证失败后仍发布、slot 复用与旧 RPC。分别记录通知投递、任务状态、输出可见性和页复用，避免以“收到 IRQ”作为所有性质的测试 oracle；本轮未执行这些测试。

SOTER 的系统贡献是展示算子级分割、尺度恢复和低成本挑战的组合探索；本报告保留作者实验结果，同时指出通用非线性公式、模型隐私证明和所选原型的验证闭环均有限制。对本项目的研究价值主要在于明确结果发布语义与替代威胁模型，不宜把参数缩放视为额外内存安全层。
