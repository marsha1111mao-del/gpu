## 2. 研究问题与贡献边界

加密内容与隐藏访问地址仍可能保留“何时传输、传输多少”的差异。权重和激活受片内容量限制而分tile装载，模型层尺寸、tile布局、计算/访存比例不同，形成带宽时间序列。攻击者不必知道每个地址对应哪个对象，也可能区分执行阶段。

Figure 1将整个攻击分成带宽采集、层边界检测、层类型分类，再借助黑盒查询重建模型或构造对抗样本。论文主要演示前面的结构推断阶段；后续模型权重重建、相近精度训练和对抗迁移借用相关工作，没有本篇端到端攻击成功率证据。

正文交替使用layer type、dimension和model architecture描述目标，但表格直接报告边界与层类型分类，没有逐维度误差、完整计算图恢复率或准确权重恢复结果。研究报告应按实际指标描述，不能用“恢复模型”笼统代替。

与SESAME的作者、平台及结果有明显重叠。SESAME先于本篇公开，本篇更集中描述带宽攻击、DWT/时间窗口和防护；Table I/II/III的数值对应SESAME的相关表格，不把它们当独立平台上再次复现的三组证据。两篇独立报告有助于分别核对攻击与系统边界，但不能重复统计实验可信度。

## 3. 威胁模型和攻击者前提

论文假设恶意特权软件、恶意共租户及可能的物理观察者；设备采用数据加密、完整性和地址保护，攻击只使用带宽。该保护是假设中的攻击约束，不是本篇PoC实现了完整TEE、ORAM或地址加密的证明。

攻击者被允许离线profile所有可能的layer/tile配置，受害者选择性能最优tile。这个强先验使训练特征更容易匹配；实际GPU编译版本、融合算子、调度并发、动态形状和不同内核实现可能造成分布偏移，论文没有评估这些条件下的泛化保证。

恶意Host可访问LLC、DMA或DRAM控制器的高精度流量统计。另一条路径是无特权租户通过共享接口争用观察自身带宽下降；正文解释这种机制，但PoC明确将攻击者建模为恶意hypervisor，未给出无特权竞争探针的代码、隔离配置、误差和独立成功率。

因此，禁用非可信性能计数器能关闭已演示的一类直接观测接口，却不能据此断言全部侧信道关闭；反过来也不能把理论上的争用渠道写成已在本项目打通的攻击路径。需要分别验证观察者实际能读到什么、时间精度和噪声。

## 4. 原型与采样机制

原型为Pynq-Z1上的100MHz VTA，软件栈为TVM；修改DMA controller加入读取事务字节计数器，经MMIO由runtime driver以250kHz读取。独立复算采样间隔为4微秒；这不是CPU中断频率，也不表示4微秒内所有单事务地址或顺序均可恢复。

作者认为推理期权重不更新，因此只看读事务足以推断模型特征。这是该只读推理工作负载下的选择，不能推广到训练、KV cache更新、动态GPU数据结构，或由此认为写通道与GPU安全无关。

六个模型为VGG11/16、AlexNet、ResNet18/34/50。论文还称经ACP连接LLC后采到了相似需求特征，但因篇幅未展示；公开图表支撑的是DRAM接口轨迹，不能为未展示的LLC攻击补造相同精度结果。

Figure 2以VGG16给出三类相邻层：tile尺寸不同、tile尺寸相同但数量不同、尺寸与数量均相同。相同局部签名说明短窗口本身未必唯一标识层，仍可能依赖总时长、前后文和先验。Figure 3展示六模型流量形状，不能只凭视觉差异认定未知模型可被唯一恢复。

## 5. 两阶段攻击与实验指标

边界检测先从滑动窗口提取传输总量、median/peak、标准差及DWT频域特征，再用bag-of-words聚合时间/频率信息和聚类产生候选，以离线layer终止时长验证候选、减少误报。论文没有完整公开窗口、训练/测试划分、重复次数和跨运行置信区间，不能据短篇方法描述声称已可精确复现全部分类器。

边界位置稀疏，非边界远多于边界；作者明确不用整体accuracy来评价检测，而报告precision/recall。项目若研究伪造/重复完成事件或中断边界，同样应防止“几乎总判无事件”得到虚高准确率，并分别统计误接受和漏报。

Table I中AlexNet/VGG11/VGG16的easy/all precision均为1；ResNet18为0.69/0.64，ResNet34为0.66/0.72，ResNet50为0.33/0.33。all recall列为1，但这伴随不同的误报率，不能描述为所有模型都被无误恢复。

easy/all标题中的边界数量分别为3/4、5/6、8/11、22/23、24/36、50/52；easy recall约为这些数量之比，提示其分母与全部边界有关，不宜直接解释成“仅在easy集合内的召回”。作者称overall检测73.9%，但未说明足够的聚合细节。

独立复算上述easy数量总和112、all总和132，比例84.85%；easy recall简单均值81.67%，按all数量加权约84.95%，均不能直接重建73.9%。这说明公开表格和文字的聚合口径仍待原始样本澄清，并不证明分类器实现存在已复现错误。

层类型分类使用SVM、MLP与CNN，并对照有/无DWT。Table II明确假设层边界完美识别，是条件分类性能；不能与前一步precision/recall无条件合并，也不能把分类accuracy当完整模型拓扑恢复概率。

Table II overall：仅执行时长0.826、SVM0.927、MLP含DWT0.949/无DWT0.934、CNN含DWT0.953/无DWT0.934。相对时长基线，SVM增加10.1个百分点，CNN增加12.7个百分点；CNN加入DWT增加1.9个百分点。这些均不是本项目GPU正确性或完成认证成功率。

正文称从84%到93%，与表格基线82.6%不完全一致。以Table I每模型all边界数加一作为层数，SVM/CNN加权约92.741%/95.276%，接近其overall；相同时长行加权约87.072%，无法重建82.6%。这只是一项明确假设下的算术检查；未取得原始统计权重，不静默改写表格。

尤其是AlexNet/VGG11仅凭已知层终止时长就能100%分类，说明敏感的不一定是精确地址。在本项目中，如果Host本来就能观察每任务切换或完成时间，即使隐藏计数器，也需要单独说明允许泄露的粒度。

## 6. 防护：固定tile与流量整形

第一种建议是所有层固定tile尺寸以降低带宽变化。论文对每模型800个tile配置探索，Figure 4显示median约1.2×，部分配置约1.6–2.0×；这是配置搜索分布，不是800次独立重复实验，也不是固定tile后完整安全证明。

恒定tile尺寸不必然使所有可观察轨迹相同：tile数量、算子种类、计算间隔及结束时间仍可不同。正文没有给出覆盖所有这些面的证明或攻击复测。因此只能将其视为待完整评估的限制优化方案，不能承诺“一律固定tile即可消除模型泄露”。

第二种防护按与秘密需求无关的节奏传输：真实需求不足时填fake事务、超过时限流，将请求padding后拆成定长事务并等间隔发送，再基于固定带宽优化tile。安全要求针对的是攻击者能区分的传输，不是仅让程序记录的平均带宽相同。

正文讨论规则写请求和加密valid flag区分真/伪存储。实现中还必须确保fake写不破坏应用对象、flag不能被攻击者篡改并绕过检查、地址仍在授权域内、旧epoch的事务不可访问新所有者；本篇没有提供足以证明这些生命周期条件的完整实现证据。

流量节奏还必须考虑可见开始/停止、总时长、真实与dummy可区分性、读写方向、共享controller排队和资源竞争。论文主要评价带宽边界分类器，没有覆盖全部观察面的不可区分证明，也没有跨Realm通知时序实验。

一个自构算例：细粒度流量[8,0,8,0]与[0,8,0,8]总量同为16，每两格聚合均为[8,8]，但细粒度完全可区分。它说明“某个采样窗口恒定”不能推出更细观察者无法区分；该算例不是对作者实际硬件实现的攻击复现。

## 7. 整形实验与开销的准确解释

Table III整形后AlexNet precision0.03、VGG11为0.01、VGG16 easy/all为0.0027/0.00011；对应最后一项0.011%。由FP/TP=1/p−1计算，分别约32.33、99、369.37、9089.91误报/真阳性；这支持定位成本上升，不表示零信息泄露。

ResNet的NA表示即使引入10000倍误报，分类器仍未能识别要求的真实边界，正文阈值写precision小于0.0001。不能把NA换成零攻击成功概率，或把这种特定攻击失败提升为任意攻击者无法推断。

正文称overall precision低于0.01%，但公开表格未给聚合overall、NA实际计数或详细阈值，VGG16 all单项也为0.011%；二者不必然矛盾，却不能从该单项直接推出整体值。没有足够样本信息就不自行补出总体precision。

防护配置固定200MB/s，作者报告geomean运行时间开销14.6%、最坏19.3%，即时间倍率1.146/1.193；在相同工作量条件下对应吞吐下降约12.74%/16.18%，不是相同百分比。论文未提供完整逐模型防护时延表、能量、fake流量占比和尾延迟，不能把这两个聚合值用于推导这些指标。

摘要称软件防护1.6×，正文配置分布median约1.2×、部分1.6–2.0×，口径不相同；硬件整形14.6–19.3%的平均/最坏也不能笼统写成每模型均落在该区间。这里保留报告方式，不拼接为统一可比性能表。

## 8. 对项目内存、共享和中断设计的影响

映射授权回答“谁能访问哪些实际页”，带宽/通知观察回答“旁观者能推断哪些执行特征”。RMM认证Client、ProxyRealm控制SMMU和直接HPA的Stage-1约束仍是前者的基础；地址隔离正确不能替代后者，而后者未解决也不能反推前者失效。

中断安全至少区分事件真实性、归属/路由、重放与时序隐私。该论文只给出活动节奏可泄露的证据，没有证明攻击者能伪造GPU完成，也没有提供可信通知协议。项目应保留native fence/真实终态与Client/cookie/epoch绑定，避免把时序隐藏方案错误地当成完成认证方案。

建议先建立观察面清单：非可信Host可见的VM exits、调度/切换时间、虚拟IRQ次数、共享完成页更新、RPC提交/应答、性能计数与跨Client资源竞争。分别记录哪些是实现已暴露、哪些只是推测，明确保护对象是用户输入、模型结构、任务内容还是任务存在性。

在安全主体相同、错误语义保留的前提下，可研究合并唤醒或固定通知批次，降低直接可见的逐任务边界。真实任务完成记录须持久可检查，漏中断不丢完成，重复通知不重做回收；内部native fence仍按实际硬件结果完成，不能为隐藏时间伪造成功或改变依赖顺序。

固定通知并不自动隐藏完成页轮询、MMIO、调度或带宽活动。选择一个通知整形点后，要同时判断攻击者能否绕过它读取更细状态；如不能封闭观察面，应明确只承诺减少某种可观测信息，而非所有任务时序完全隐藏。

reset、超时、取消和Client退出常产生明显异常节奏。它们必须首先维持权限、真实失败终态及DMA静默；公开异常是否属于允许泄露项需写入模型，不能为了恒定时序拖延必要隔离或把失败任务输出标为成功。

## 9. 可执行的研究方案，而非本轮测试结果

可先在现有单/双Client流程记录可信任务开始/真实终态，以及各非可信边界能观察到的事件；再比较仅总时长、通知间隔、通知数量与可访问带宽统计的分类能力。按运行而非相邻窗口划分训练/测试，避免同一次执行的高度相关窗口泄露到两侧。

逐步加入不同输入/模型、运行并发、调度策略和编译配置，分别报告边界precision/recall、完整任务/模型分类、误报数量和不确定性。先验已知模型集合与真正未知模型分开；不将层边界已知条件下的分类数值写成端到端成功率。

保护候选应与相同安全条件和资源预算对照：通知批处理延迟、真实GPU工作时间、吞吐/尾延迟、Host开销、丢失/重复/迟到事件语义及回收正确性共同报告。这里提出的是研究计划，尚未执行；不借用论文的14.6%或95.3%替代项目测量。

两大部分的划分仍成立：直通/共享部分研究实现与性能，任务隔离部分研究实际页授权和可信控制/完成链。侧信道可作为第二部分明确限定的扩展目标；强隔离、应用正确性、DoS和全面时序隐藏不能因引用论文被合并成一项已实现承诺。
