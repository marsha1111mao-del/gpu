# NanoZone：CCA 进程内多域隔离、权限切换与可信服务边界

NanoZone 是 CPU/CCA 细粒度隔离支撑工作。被保护的进程运行于 Normal world，由 Root EL3 Monitor 执行保护，不依赖 Realm 中的 RMM/Guest 栈。它不是 GPU 直通、共享或 GPU TEE 架构；与项目的联系在于可信服务内部的最小权限、域切换及异常上下文。

正式 DOI 与实际所读 arXiv v2 的身份分别记录；本次没有取得 IEEE 排版全文做逐字版本比较。也不将 v1、v2 和正式索引算作三篇论文。

## 2. 问题与相对已有工作的变化

CVM 保护 Guest 免受外部 Host 读取，但 Guest OS 仍可能访问应用秘密；SHELTER 将边界缩小到进程，进程内存损坏仍可泄漏同地址空间中的其他对象。NanoZone 关注单一服务进程同时保存多个 Client 秘密时的内部隔离。

仅有快速用户态权限切换不够：攻击者可能复用合法切换指令、跳到 trampoline 中部，或者劫持到本来合法的调用点。最后一类借用入口的攻击说明，合法 PC 与合法业务授权不是同一性质。

论文把容量、切换成本和不可信 OS 三者结合：用 POE 快速切换，以 PIE 和 GPT/GPC3 扩展容量，并保护通往切换点的控制流。它引用 CCAegis 为相关工作，但未明确宣布自身是 CCAegis 的期刊扩展；不能根据作者重合建立这种版本关系。

## 3. 威胁模型和 TCB

可信基础包括正确实现 RME、PIE/POE、GCS 等能力的硬件、经安全启动加载的 Root firmware/Monitor，以及干净的离线编译环境。OS、驱动及 Secure/Realm 软件栈不可信；考虑越界读写、控制流劫持、OS 修改映射/寄存器/异常返回及恶意 DMA。

明确排除物理攻击、微架构侧信道、DoS、保护域主动泄密及域内漏洞；Iago 防护主要覆盖内存映射，不能推广成所有 syscall 都安全。

作者报告新增 Monitor 约 3K LoC、非可信驱动约 1K、离线工具链约 500。3K 是新增模块规模，既有 Root firmware 和硬件仍受信任，不能写成整个系统 TCB 只有 3K。

## 4. 三级隔离域

| 层级 | 机制 | 切换与容量 |
| --- | --- | --- |
| L1 | POE，更新用户态 POR_EL0 | 当前采用的编码中有 7 个可用域；大多数切换不进入 Monitor |
| L2 | PIE 基础权限与 POE 叠加 | 利用 4 个可用 PIE 编码组合为 28 个域；跨 L2 需 Monitor 更新权限 |
| L3 | GPT 的 no-access 页与每核 GPC3 bypass window | 不同物理区间复用 PIE/POE 编码；跨区间由 Monitor 调整窗口 |

POE overlay 与 PIE base 共同限制访问，清空 overlay 后，即使基础权限或 bypass window 尚保留，非可信代码也应无法访问域数据。L3 页保持 no-access，Monitor 只打开事先定义的合法窗口，避免每次切换把 GPT 项改为开放状态。

“无限扩展”应理解为不再受固定 POE 编码数量限制；实际仍受物理内存、窗口大小、元数据和分配条件约束。论文的 L3 要求 CMA 提供 1–64GB 物理连续区间，不能等同低成本支持任意碎片化对象。

每线程按 28 域连续块分配，使相邻连接和请求尽量落入同一 PAS，降低昂贵层级的切换率。这是对象放置策略的效果，不能把高 L1 命中率视为任意负载的硬件常数。

## 5. 控制流与切换权限

离线扫描去除应用预先嵌入的未授权权限写指令和显式 GCS 写指令。GCS 保护返回地址；Monitor 管理的 PIM 保存函数指针备份，受 GCS 页属性保护，通过只读线程寄存器定位。指针高位携带 PIM 索引，调用前检查索引范围、备份值和函数类型摘要。

该方案阻止许多任意目标劫持，但 §VIII 明确承认同类型合法目标复用仍有残余风险。不能据“严格双向 CFI”措辞推导任意调用者都只能调用其业务上获准的域，也不能将类型兼容等同 Client/对象归属授权。

对项目的启发是先明确授权接口：映射、提交、取消、完成发布、回收应各自检查哪些受保护状态；之后才评估是否需要 Proxy 内部的 CFI 或组件隔离。现有 RMM 身份和对象检查不能被合法调用点检查替代。

## 6. OS、页表与异常隔离

OS GPT 阻止内核访问进程数据、代码、页表、向量表和控制流备份；proc GPT 供进程运行。Monitor 在接收委托内存时检查不重叠，并在其他世界获得内存时同步收紧进程视图。

进程到内核的异常先经过受保护向量，进入 EL3，切换 GPT、保存并清理敏感上下文，再转交 OS；返回时恢复权限、GCS/PIM 及相关寄存器，防止 OS 暗中禁用保护。跨 L2/L3 的理想快路径借助 RNG trap 直接进入 Monitor。

Monitor 管理实际受保护页表，核验 OS 提交的更新。所有可执行页在启动时装载审计，委托后禁止新页面变为可执行；JIT、运行期 dlopen 不受支持。SMMU 使用保护 GPT、执行 GPC 并维护翻译缓存，阻止设备 DMA 旁路。

异常拦截保护的是被中断上下文与恢复状态。本文没有给出跨 VM GPU job 的事件来源、完成记录、cookie/epoch 和撤销后迟到 IRQ 协议，也没有证明事件代表合法业务原因。

## 7. 原型：功能与性能证据分开

功能原型使用 FVP、LLVM 16、TF-A 2.9.0 与 Linux 相关支持，测试真实架构语义。性能原型使用 RK3399，锁定 A72 为 1.8GHz、关闭 A53，以替代寄存器、普通 store、完整 TLB flush 等模拟缺失能力。

这符合采用模拟硬件验证设计的研究方法，不据此否定架构。需要保留的是证据类型：SoC 测量的是替代路径成本，不是该 SoC 已执行所有保护；FVP 阻断实验也不是实际板端攻击防护测量。

性能原型以两段 svc+smc 替代理想 RNG trap，作者据此预期原生硬件会更快。但这种预期不是已经测出的新硬件结果；GCS、翻译缓存和检查路径的真实成本仍需后续验证。

## 8. 安全评估及证明范围

FVP 上评估 10 个已知 CVE，分别涉及越界访问和控制流劫持；另测试恶意内核修改 PTE 域索引、处理 syscall 时篡改权限寄存器。作者报告均被防护阻断。

这支持特定机制可工作，不能替代完整形式化证明，也没有覆盖任意并发释放、所有编译器语义或同类型复用。论文报告向 SHELTER 作者反馈一个跨世界 GPT 更新风险；本次没有独立复现，不把作者报告直接写成本项目或所有 SHELTER 版本已证实漏洞。

L1 命中率在默认分配下约 96%–100%，round-robin 压力下降为 77.29%。表 V 与相邻正文在 28 域对应命中率/开销的描述有不一致，报告保留基本操作和整体趋势，不根据混合列值重建新结论。

## 11. 与项目已有设计的对应

项目已有 RMM Client 认证、GPUVM、认证队列、私有快照、native fence、cookie/epoch 和 persistent IRQ127。NanoZone 不构成“这些机制尚不存在”的证据。

| NanoZone 问题 | 项目可以进一步明确的性质 |
| --- | --- |
| 合法 gate 被借用 | 合法 RPC 入口仍须验证当前 Client、对象、权限、代次和任务状态 |
| 内核改异常上下文 | 可信任务状态和返回记录不能由转发组件修改；恢复必须关联正确会话 |
| 权限切换与多核视图 | Client 切换、reset、撤销时 CPU/设备及授权缓存视图保持一致 |
| 常用对象局部化 | 优化私有元数据访问及切换时保留完整授权键，命中不得跳过生命周期检查 |
| 进程内多域 | 若要缩小 Proxy TCB，可研究解析/调度/映射权限的组件边界，但须独立设计 Realm 内适用机制 |

采用 Normal-world GPT 隔离的具体寄存器安排不能直接搬进既有 ProxyRealm；迁移目标是最小权限和授权语义，原有可信 Proxy 统一控制 SMMU 的假设继续成立。

## 12. 对论文主线的建议

项目第一部分仍可讨论 Arm GPU 直通/共享和性能；第二部分讨论任务隔离，并把内存授权和异步终态联系起来。NanoZone 可放在第二部分的“可信服务内部边界与最小 TCB”相关工作，不必为覆盖文献新增三级 CPU 权限系统。

更贴近项目的研究问题是：现有私有快照、映射授权、真实 fence 和 epoch 如何共同限制每一次状态转换；重复/迟到通知不得形成第二次成功，撤销/错误/reset 不得被转换成成功，资源复用前必须满足停止访问和内容清理条件。本文可支持入口复用与上下文保护的论证，但逐 GPU job 的证据仍需项目自己建立。
