## 2. 研究问题：统一四种模型任务

内存一致性模型规定共享内存中的读可以取得哪些值。权限决定能否访问一个地址；一致性决定获准访问时可以读到哪个版本。一个合法、认证通过的完成记录仍可能因为错误同步而与旧结果一起被观察到。

作者将四个问题统一为：寻找程序 P、Q 和状态 σ，使 σ 在模型 M 下不能由 P 产生，但在模型 N 下可由相关程序 Q 产生。

| 问题 | 变化的对象 | 用途 |
| --- | --- | --- |
| Q1 一致性测试 | 比较指定模型与无限制行为 | 找出硬件或编译器不应产生的结果 |
| Q2 区分模型 | 同一个程序、两个模型 | 解释规则修改增加或删除了什么行为 |
| Q3 检查优化/单调性 | 同一模型、变换前后程序 | 检查增加顺序或增强 memory order 是否反而引入行为 |
| Q4 检查编译映射 | 语言模型、架构模型及翻译 | 查找软件禁止而目标实现允许的结果 |

对项目的可迁移方法是把“原协议”和“减少通知、批量发布、缓存授权后的协议”当成两个行为集合，要求优化不增加被安全规范禁止的观察。论文没有替项目定义身份、授权、撤销或中断的安全规范。

## 3. 核心方法：先求执行，再恢复测试

直接寻找“存在一个程序，使其所有执行都不能得到某状态”带有昂贵的存在/全称量化。Memalloy 先求一对执行图 X、Y，再从图构造 litmus 程序。

执行图使用纯事件集合，类型、线程、地址、读来源和 coherence order 都由关系表示。重要关系包括 sequenced-before、reads-from、coherence、from-read，以及地址/数据/控制依赖。这样两个层次可以复用事件身份，也不用事先枚举全部地址和数据值。

省略初始写能缩小求解范围，但读取初值时必须补上相应 from-read 关系。线程内顺序可以是偏序，输出语言用顺序组合、无序组合、条件语句和 CAS；不支持任意循环，且要求 N-free 的顺序图，才能从执行恢复该语言中的程序。

所以“所有小执行”始终是指定表示、语言和关系约束中的执行，不是所有真实驱动、任意 GPU 二进制或任意设备行为。

## 4. deadness：一个禁止执行不等于一个有效反例

假设执行 X 在 C11 下不一致，按它构造测试后，另一个执行 X′ 可能没有完成 release/acquire 同步，进而发生非原子数据竞争。按论文采用的未定义行为语义，不能再用该测试结果指控实现违反模型。

作者引入 semantic deadness：从禁止执行得到的最小测试，在所有一致候选中都不产生该结果，也不因数据竞争而失去意义。实际搜索使用语法近似，包括固定可观察 coherence 边、禁止部分零值条件、dependable happens-before 和 self-satisfying cycle。

论文用 Alloy 检查近似蕴含 semantic deadness，对不超过八事件的执行未找到反例；更大范围在四小时后超时。作者明确没有给出整体反例提升规则的通用证明，并以另一个 Java 模拟器枚举生成测试的候选来补充检查。确定性 LIT 算法还可能将一个条件体拆成多段，不能保证输出程序严格满足最初代码变换关系。

这里的 deadness 是验证技术名词，不是任务被停止、设备 quiescence 或安全回收。不能把它写进撤销协议并声称因此已经停止 DMA。

## 5. 历史 GPU 贡献：跨 scope 的累积同步

论文研究的旧 PTX 模型 PTX1 可以分别约束 workgroup 与 device scope，却不能完整承接跨 scope 的同步链。OpenCL 的某条同步经过不同 scope 传递后，仍要求相关数据可见；自然的 OpenCL→PTX 映射在 PTX1 上存在反例。

PTX2 将较小 scope 的传递关系纳入较大 scope fence 两侧，使同步可以跨 scope 累积。作者也讨论把所有 fence 升级为 device scope，但考虑性能成本而选择调整模型并检查硬件证据。

这不是通过软件把硬件改成更强的模型。它是一项规范候选：先发现旧模型比已有硬件可能过弱，再用区分测试检查更强模型是否与测得行为冲突。

本文映射明确排除 RMW、local memory 和多 GPU，主要使用旧的缓存绕行访问与 membar。它不能替代现代 PTX 的完整规范，更不能直接移植成 Arm Mali、CPU、跨 VM 与 SMMU 的统一内存模型。

图 16 的事件标签表明，device scope 同步后再通过 workgroup scope 传递，末端可能读到旧 x；正文有一处对 scope 顺序和旧值变量的描述与图标记不一致。本报告按图和映射解释累积问题，不照抄该句形成额外结论。

## 6. 定量结果与可靠性口径

| 项目 | 作者结果 | 解释 |
| --- | --- | --- |
| OpenCL→PTX2 映射 | 不超过五个软件事件、十五个目标事件未找到反例；更大范围四小时超时 | 是有界检查，非通用正确性定理 |
| 区分 PTX1/PTX2 | 全部十四个七事件测试，另找到十二个八事件测试后超时 | 八事件集合没有穷尽 |
| 历史 GPU 结果 | 二十六个测试中二十二个查询既有数据，四个单地址测试新增实机实验 | 未观察到候选更强模型所禁止的行为 |
| 新增单地址测试 | GTX Titan，作者页面各列 0/100k | 有限次数未观察到，不是行为不可能的证明 |
| C11→Power 漏检 | 先前六软件/六目标事件未找到 bug，已知 bug 原需六/十三事件 | 小 bound 可漏过真实问题 |
| 精简 Power 映射 | 去掉线程首尾冗余 fence 后，可用八目标事件找到反例 | 缩小表示有助搜索，但变换理由也要审查 |

作者服务器为四颗 16 核 2.1 GHz AMD Opteron、128 GB RAM。表 2 分开编码与求解耗时；OpenCL→PTX2 一项约 4 秒编码、9719 秒求解。其结果不能作为本项目协议检查速度估计。

Plingeling 完成全部列出的任务，MiniSat、Glucose 各有超时；结果不是求解器普遍排名。Power 递归关系的真实不动点需要高阶 AlloyStar，固定展开较快，但小范围两次展开足够的观察不是任意范围等价证明。

## 8. 与项目的具体关系

本项目采用可信 ProxyRealm、RMM 认证原始 Client、软件 IPA→HPA 授权及受保护 Stage-1。本文不改变这些假设，也不重新提出项目已经具备的 GPUVM、认证队列、私有快照、native fence、cookie/epoch 和 persistent IRQ127。

可把验证对象收敛到三条性质：正确 Client 的合法映射才能被执行；终态成功只能对应真实完成且结果可见的该代任务；旧任务和旧授权不能在对象复用后再次生效。三者可以共享事件框架，但权限、数据顺序、真实性和撤销各自需要规则。

建议先建立一条抽象发布链：GPU 结果写入及必要可见性操作 → 可信 Proxy 确认真正完成 → 发布包含身份/任务代次/终态的记录 → 投递通知 → Client 验证并读取。每一箭头都应标出由 GPU、DMA、CPU 屏障、锁、队列协议或可信固件中的哪一机制保证。

release/acquire 不能自动跨越所有设备一致性域，物理/虚拟中断到达本身也不能自动建立这些边。这里只给出论证要求，没有认定当前同步有错；实际反例需结合项目代码和平台约定。

## 9. 可开展的协议比较与负例

| 研究对象 | 规范应禁止的观察 | 可比较的优化 |
| --- | --- | --- |
| completion 发布 | 验证到当前成功终态，却读到上一代结果 | 批通知、减少 worker 交接、提前观察真实 fence |
| 授权缓存 | 旧 Client/旧 epoch 的命中为新对象提供授权 | 持久映射、热点元数据缓存 |
| 撤销与复用 | 撤销确认和分配给 B 后，A 的旧访问仍成功 | 异步回收、批量失效 |
| VM 通知 | A 的真实完成推动 B 的终态，或重复通知重复完成任务 | 中断合并、共享通知入口 |

这是未来模型与验证计划，本轮没有构造或运行这些测试。模型需要主动表示错误/取消/reset、并发 Client、丢失/重复通知、epoch 更新和缓存失效；仅把既有正常顺序录入模型会得到过强且无用的保证。

可以先做有界反例搜索，再对关键不变量补充归纳论证。报告应记录 bound、模型假设、被排除的执行和超时；没有小模型定理时，不能用一次无反例结果证明任意 Client 数和任意长生命周期。

## 10. 与相关文献的分工及评价

GPU Concurrency（ASPLOS 2015）提供历史弱行为与实测基础；Memalloy（POPL 2017）提供自动比较及反例生成；Formal PTX（ASPLOS 2019）进一步研究现代 scope 模型及特定映射证明。它们有继承关系，不能把三篇的假设和证明拼成一个从未建立的完整 GPU 证明。

PORTAL/CAGE/ACAI 与 PhantomMap 负责可信设备服务、归属和映射生命周期问题；Devlore、SHELTER 扩展及机密 VM 中断攻击论文提供中断边界。Memalloy 适合补足这些设计中“实现的可观察行为是否细化安全规范”的验证方法。

独立评价：最值得借鉴的是把协议优化转成行为集合比较，以及作者对不完整性、提升算法和小 bound 漏检的坦率披露。它没有提出新的机密计算机制，但能帮助项目把“内存和中断隔离”从机制清单推进到可反驳、可验证的性质。
