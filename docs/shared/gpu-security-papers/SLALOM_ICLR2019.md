## 2. 它解决的问题与信任边界

Slalom 的问题是：CPU enclave 可以保护完整推理，但直接在其中执行大规模线性计算较慢；能否把主要计算交给同机更快的 GPU，同时由 TEE 保留输入隐私与结果完整性。可信端负责随机数、预计算、验证、非线性层和最终交付；GPU、Host 软件及外部缓冲区均可不可信。

这里的远程用户 C、服务器 S 和服务器内 TEE 是三个角色。TEE 是受信任的协议参与者，不是 GPU 的可信驱动保护域。只信任 CPU TEE 而不信任 GPU，与项目通过可信 ProxyRealm、GPUVM、SMMU 和固件保护设备执行的基础不同。

完整性定义允许输出失败符号，要求错误结果被接受的概率很低；它不保证恶意 Host 一定调度 GPU、按期返回、保持服务可用，或允许多个敌对 Client 安全共享任意 GPU 指令。输入保密、结果正确、多租户内存隔离和中断完整性不能互相代替。

论文明确不对 TEE 自身安全做完整形式化建模。附录 A 讨论 SGX 侧信道与推测执行攻击，并以标准 DNN 操作的数据无关性降低部分担忧；这不是整个运行库、错误路径、服务调度及密钥生命周期的无泄漏证明，也不是所有 TEE 已天然满足所需前提。

## 3. 核心流程：线性层外包、可信端验证与非线性处理

将输入、权重和偏置量化到整数，再嵌入有限域。对一个线性层，可信端有输入 x 和权重矩阵 W，GPU 提交声称的输出 y。Freivalds 检查比较 `y·s` 与 `x·(W·s)`；若 y 错误且 s 为独立均匀秘密挑战，一轮漏检概率至多 `1/|S|`，k 次独立重复为 `1/|S|^k`。

预计算把 `W·s` 提前放入可信状态，在线阶段只做输入和输出的内积；固定模型使每次验证无需重新读取全部权重。一般线性算子每次验证需要与输入、输出大小同阶的工作；卷积可利用结构而无需显式展开完整稀疏矩阵。

论文另有按 batch 把输入/输出压缩后检查的方案，但作者旧 SGX 平台受保护内存较小，大 batch 未必合算。预计算与 batching 是不同优化，不应把所有收益都归给 GPU 或单个 Freivalds 调用。

只要保护完整性，GPU 可以先跑完整网络，再把各线性层结果交给可信端逐步检查；可信端从原始输入重新计算激活/池化，防止 GPU 用自己伪造的中间状态定义后继期望。加入输入隐私后则需要逐层交互，非线性层仍在 TEE，下一层收到新的盲化输入。

ResNet 的两个分支均需覆盖所有线性层，再由 TEE 执行合并与激活；只检查其中一个分支或最终形状不够。模型有状态、动态形状或其他算子时，原协议不会自动成为任意 CUDA/OpenCL 程序的验证器。

## 4. 输入隐私依赖一次性盲化与可信预计算

离线阶段为每次调用、每层生成秘密随机 r，并可信地计算 `u=f(r)`；在线发送 `x+r`，收到 `f(x+r)` 后减去 u，再验证并执行非线性。这里 f 指线性部分；若实际层包含偏置，解盲式必须单独一致处理偏置，不能把含偏置的仿射函数直接套进线性等式。

论文将解盲因子加密存入不可信内存或磁盘，在线用原种子再生成 r。它要求 PRNG 安全、r 未暴露且每份只用一次。若同一 r 用于不同输入，两个盲化输入相减就暴露输入差；GCM 密文认证本身不能阻止重启、回滚或错误游标导致的一次性材料复用。

需要区分两类随机性：Freivalds 的秘密检查向量可在受论证范围内复用；输入盲化向量 r/u 必须一次性消费。两者都叫随机数，不代表具有相同生命周期。检查向量与模型预计算也必须绑定实际模型、维度和量化规范，模型变化后不能只更新 GPU 权重而保留旧期望。

隐私模式的离线预计算并非免费：每份一次性材料仍需计算线性操作并存储对应解盲数据。论文适用场景是有空闲时间提前准备、在线突发处理；不能把在线吞吐倍率解释为包括材料持续补给、远程证明和所有存储成本的长期端到端吞吐。

Slalom 不向不可信服务器/GPU隐藏用户提供的模型权重和架构。服务器自有模型可相对远程用户保密，但需要可信服务提交特定模型并通过认证通道交付结果；这不等于防止用户从合法输出进行模型提取，也不能覆盖 GPU 自己可读的模型。

## 5. 安全界、随机数复用和证明文字的限制

所读版本正文 Theorem 3.2 与附录 B 写出 `n/|S|^k − negl(λ)`。本报告保留这一原文符号，但不将其当作标准 PRNG 混合论证可直接推出的更强数值界；通常需要加上不可区分优势或明确误差项的约定。未确认作者勘误，不擅自改写为原文已经写加号。

附录完整性定义限制的是“返回错误且未失败”的联合事件；证明开头却写成条件于不失败的概率，随后又使用非条件的 union bound。恶意服务器可通过选择何时失败改变条件分布，因此不能把论文解释为任意选择性中止之后，所有已返回请求仍有相同条件错误率保证。本报告不据这一文字问题直接宣布整个方案失效。

正文说同一秘密检查向量跨 n 次检查复用时，误差至多随检查次数线性增长。部署仍需限定会话中总尝试次数、失败后是否停止/换随机状态，以及可见的验证反馈；不能把每层 40-bit 界无限次复用成整个长期服务恒定 40-bit。

作者配置为两次检查，随机元素约取自 20-bit 范围，声称每层约 40-bit 统计可靠性；50 层的一次推理整体界约 `50/2^40`，即约 220 亿分之一。它不是 128-bit 确定性认证，也不是现代长期多租户服务的总失败概率。若按同一界累计 Q 次推理，应另预算总风险，而不是只重复单次数字。

秘密 s、可信 `W·s`、完整层覆盖、精确域运算、输入/输出一致快照以及错误时阻断发布共同支撑论证。把挑战交给 GPU、用公开固定向量、只比较统计总和，或用日志代替拒绝，都不能继承上述概率界。

## 6. 数值语义与浮点实现

论文采用 `p=2^24−3`，通常以 8-bit 小数缩放量化输入和权重，偏置使用对应双倍缩放，再逐层舍入。完整性目标是约定量化网络在域中的结果，不是逐 bit 等于原始浮点网络，更不是证明模型预测在语义上必然正确。

附录 F 用 double 保存整数域乘法与积累，约 24-bit 数据乘约 19-bit 挑战，再限制模约简间隔以维持 53-bit 有效整数精度。安全依赖实际数值范围、带符号表示、累积长度及舍入规则一致；“使用 float/double”本身不是精确算术保证，GPU 的异常值也不能绕过结果拒绝。

论文说所测量化网络精度损失不超过约 0.5 个百分点；Table 3 例如 VGG16 top1 71.0→70.6、top5 90.0→89.5，ResNet50 top1 76.9→76.4。MobileNet fused 与若干 ResNet 变体的性能测试未使用已训练模型，不能由吞吐测试外推精度或任务质量。

固定公开代码的 `sgxdnn_main.cpp` 实际将盲化模数设为 `(1<<23)+(1<<21)+7`，验证模数仍为 `2^24−3`。这是论文统一域叙述与后来性能实现需要另核对的差异；不能直接据单个常量认定存在可利用攻击，也不能把论文域上证明当作已经覆盖该组合。

## 7. 评估结果及必须保留的条件

作者平台为 i7-6700 Skylake 3.40GHz、8GB RAM、NVIDIA TITAN XP；可信端主要为单线程 SGX。比较基线是同类 DNN 完全在 enclave 中执行，不是本项目 Native GPU、CCA ProxyRealm 或固定频率 glmark 基线。

摘要汇总验证推理约 6–20×、隐私并验证约 4–11×。详细正文还有普通 MobileNet 验证约 3.6×，不能省略这个低收益情况。正文与 Figure 3 的部分具体标值不同，例如 VGG16 20.3×/10.7× 对图示 19.8×/10.4×；未取得对应原始表，不将它们混成唯一精确数字。

预计算减少大权重在可信端的常驻压力，VGG16 示例从约 550MB 权重到约 36MB 输入侧检查材料；还需输出挑战、工作缓冲与运行库，不能把 36MB 当总 enclave 内存或总 TCB。VGG16 权重超出旧平台受保护内存，部分速度收益来自避免分页，不直接等于协议在任意 TEE 都会获得相同倍率。

普通 MobileNet 的隐私并验证图示约 2.7×，fused 约 4.1×；fused 去掉 depthwise/pointwise 间激活，属于模型结构变化。它能减少受保护交互并合并线性算子，但不能说对原网络完全等价且没有改变任务条件。

ResNet 结果声称验证约 6.6–14.4×、隐私并验证约 4.4–9.0×。正文明确：后者是执行所需操作、却没有正确构造解盲因子的初步实现；它提供性能估计，不能算完整正确隐私推理已实证。18/34/101/152 层变体用未训练模型，ResNet50 才有对应量化精度结果。

微基准预先把数据装入 enclave，仅测可信端计算/验证，不能与所有端到端柱形图混用。隐私结果的解盲材料放在不可信 RAM；换成磁盘、加入材料供应与恢复、网络认证后，需要重新测量。4 线程标准 CPU 扩展不是已经得到相同性能的 SGX 并行实现，SGX 外层并行收益有限、内层线程池未实现。

能效段按 GPU/CPU 活跃时间加权得到约 35.5W，并假设空闲资源可供其他任务使用，进而估计约 3.4–17.1× 能效。它不是完整服务器墙插功耗或可信多租户共享实测，不能忽略同时上电、空闲功率、离线预计算与资源隔离成本后照搬。

训练仅列开放问题：权重更新破坏预计算复用、量化变化、隐私材料需重新生成，以及模型隐私需求。没有完成通用训练或现代 LLM attention/KV-cache/多租户推理证明。

## 8. 官方性能原型的安全边界

固定提交 README 明确声明仅为性能测试 PoC，存在便于调试的安全弱化，缺远程认证通道和可验证证明流程。本报告遵循作者界定，不把这些已公开说明当作新发现的生产漏洞。

`randpool.hpp` 的初始化 key/seed 为零并留有随机生成 TODO；`Crypto.cpp` 的 GCM key 也为固定零值、注明应改为客户端提供。非 SGX 分支的随机 IV 填充函数为空。它们不满足论文的秘密安全 PRNG/密钥前提；不把非 SGX性能路径说成安全 enclave 部署。

`slalom_get_r` 把 producer 盲化随机数直接写到 enclave 外；Python `prepare_blinding_factors` 使用该 r 在外部 TensorFlow 计算 z，再通过 `slalom_set_z` 送回加密。两处源码均说明这是不安全的简化。事后给外部提供的 z 加密，不会恢复已泄漏的 r，也不会证明 z 是正确的可信预计算。

Python `model_to_json` 在外部准备部分完整性向量，使用固定 NumPy seed，pointwise 分支还有全 1 向量；这些不是秘密独立挑战。即使内积运算全部执行，也不能因此继承论文每层约 40-bit 的对抗性错误界。

`Crypto.cpp` 的实际 decrypt 在 MAC 不匹配时仅打印 `Decrypt: invalid mac`，没有返回失败状态；`slalom_relu` 调用后继续执行。所读的 ReLU 融合分支把若干检查值用于 TIMING 日志，avgpool 分支留有补完整性检查 TODO，最终 linear/softmax 分支直接解盲到外部。这里只评价所读分支，没有宣称审查了全部 fused AES 汇编或所有验证入口。

EDL 对模型、输入、输出、辅助数据和多个参数使用 user_check，要求可信端自己做范围、长度、快照与并发约束；存在少量 outside-enclave 断言不等于完成全部校验。配置 DisableDebug=0，原型没有提供本轮可确认的生产证明链。公开 tree 中的演示私钥文件未下载、未使用。

全局 model、producer/consumer PRG、act_idx 和 FIFO IV/MAC 队列依赖预期单次序列。队列顺序可以提供诚实顺序运行时的对应关系，但并发、取消、重入、reset、状态回退和空队列异常仍需专门协议；本轮没有执行测试，也没有据此认定任意内存破坏或跨 Client 实际攻击成功。

静态范围：完整读取 README、EDL、enclave 配置、randpool、实际 Crypto encrypt/decrypt 段及 eval_slalom 脚本；定向读取 sgxdnn_main 初始化/盲化/预计算交接/解盲/ReLU 入口、Python 模型预计算和材料准备、conv2d/dense/model/bridge 相关片段。17 文件均取得并核验来源，但剩余内容、AES/汇编、所有算子和完整验证链没有逐行审完。未安装依赖、运行下载代码、编译、执行攻击或硬件测试。

## 9. 对项目两大部分的具体启发

项目第一部分仍是 ARM GPU 直通、共享及性能实现，第二部分仍是多 Client 任务的内存与中断通信隔离。Slalom 增加的研究视角是区分“设备访问经过授权”“任务实际到达终态”“返回数据满足正确性规范”三个命题；它不能替换前两个部分。

保持既定假设：RMM 认证原始 Client；可信 ProxyRealm 统一控制 SMMU，建图校验对象、实际 HPA 授权、权限和生命周期，软件 IPA→HPA 合成受保护 GPU Stage-1；其他设备继续硬件 Stage-2，平台保护页表、根配置、MMIO 和可信固件。本文不以 TITAN/SGX 与 RK3588 的差异否定该架构。

已有 GPUVM、认证队列、私有快照、native fence、cookie/epoch 与 persistent IRQ127 应继续承担实际隔离和完成归属。可信通知证明的是它所关联的状态转换，不能从 IRQ 或 fence 单独推出数学结果正确；也不因 Slalom 使用加密就给当前所有共享队列再叠一套同义 token。

若论文目标信任 GPU 执行语义和可信固件，结果验证可以作为可选扩展，优先用 GEMM/卷积等有明确数值规范的算子评估，而不强行纳入基础通用 GPU 接口。若将恶意设备计算、故障或不可信结果纳入范围，则需要在 Client 或可信服务中增加真正独立、秘密挑战的验证端。

完成路径可明确为：可信任务身份绑定的真实 native fence 终态，随后完成所需缓存/内存可见性和可选结果校验，最后发布对应成功或失败通知。需要重叠计算时可先产生私有临时状态，但未验证结果不得触发不可撤回外部输出或其他 Client 的授权变化；验证失败应进入可回收的错误终态，不能只记日志后发布成功。

已有私有快照可支持验证与使用相同内容；若验证后仍允许 GPU/Host 改写同一外部页，先前通过的验证不能授权后来内容。cookie/epoch 用于任务与代次关联，一次性盲化材料的消费、防回滚以及 GPU 旧访问静止则是不同性质，需要分别论证。

可验证后续包括：错误/重放结果不能形成成功通知；验证失败后旧 IRQ 不改变其他任务；取消/reset 不复用一次性材料；模型或量化版本变更使旧预计算失效；通过验证的数据与发布数据一致。它们是研究与验证建议，本轮未新增测试或宣称项目已经具有上述结果验证能力。
